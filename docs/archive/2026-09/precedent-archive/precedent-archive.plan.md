# precedent-archive Plan

## Executive Summary

| 항목 | 내용 |
|------|------|
| Feature | 시스템에 입력된 **모든 판례**(Pinecone 코퍼스 · 계산기/앱 코드 인용 · NLRC 번들)를 유실-복구 가능한 문서 아카이브와 **단일 인벤토리 장부**로 정리 |
| 시작일 | 2026-08-30 |
| 예상 기간 | 1~2일 (이번 사이클 = 아카이브 + 인벤토리. 공백 판례의 실제 수집은 후속) |
| 선행 | `precedent-corpus-expansion`·`-followup`(수집 파이프라인·원장), `textbook-corpus-cycles`(인용 판례 CSV), `pinecone-pipeline-audit`(원장·NS 계약) |
| 발단 | 판례 원문 약 2,415파일이 **전부 `.gitignore` 로컬 전용**이라는 사실 + 계산기·앱 코드가 인용하는 판례 17건 중 **최소 8건이 코퍼스 어디에도 없다**는 실측 (2026-08-30) |
| 측정 기준 | 2026-08-30 실측: laborlaw-v2 25,897벡터 전수 열거(판례 `precedent_*` 5,893 + `ctx_precedent_*` 1,310), 원장 1,568사건, 로컬 md 보강 1,579 · 크롤 837 |

### Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 판례가 5곳에 흩어져 있고 어떤 판례가 어디에 있는지 답하는 **장부가 없다.** 원문 파일(보강 1,579 + 크롤 837)은 전부 gitignore 로컬 전용 — 디스크 하나가 단일 장애점이고, 재수집에 필요한 사건번호 목록·원장(`_uploaded_ids.json`, Pinecone 롤백의 유일 수단)마저 같은 디스크에 있다. Pinecone은 백업이 아니다(`--reset` 사고 실증, Serverless 복구 수단 없음, ctx 청크는 Contextual 프리픽스가 섞인 `chunk_text`뿐이라 원문 복원 불가). 장부 부재의 실증: **계산기의 법적 근거 판례(대법원 2023다302838 통상임금 전원합의체, 코드 인용 22회 최다)가 판례 코퍼스에 문서로 있는지 아무도 답할 수 없었고**, 실측해 보니 코드 인용 17건 중 8건은 어디에도 없었다. |
| **Solution** | ① 사건번호를 기본 키로 하는 **인벤토리 CSV**(문서 보유처 · 검색 수록처 · 인용처 통합) — 평문 커밋으로 diff 가능한 단일 장부. ② 법제처 수집분(비보호 저작물)과 부속 기록(원장·미발견·겹침 CSV)을 **jsonl.gz 번들로 저장소에 커밋** — bm25_corpus.jsonl.gz(19MB)와 같은 관례, 실측 5.2MB. ③ 크롤분(nodong.kr 게시물)은 **저작권 게이트 통과 전 공개 커밋 금지** — 저장소가 PUBLIC이므로 제3자 편집·해설 혼입 여부를 판정한 뒤 계층을 정한다. ④ `--extract 사건번호`로 아카이브에서 사람이 읽는 md를 복원하는 추출기. ⑤ 오프라인 회귀로 정합 고정. |
| **Function & UX Effect** | 사용자 기능 변화는 없다(순수 자산 내구성 작업). 간접 효과: 인용-코퍼스 공백 목록이 후속 수집 대상이 되어, 계산기 답변의 근거 판례가 RAG 검색에도 실리는 길이 열린다. |
| **Core Value** | **"무엇이 있는지 모른다"는 상태 자체를 걷어낸다.** 겹침 재수집·중복 판정 사이클이 반복된 원인이고, 코드 인용 공백 8건이 무감지로 남은 원인이다. 디스크·Pinecone 어느 쪽을 잃어도 인벤토리+아카이브에서 복구 경로가 성립한다. |

### 1.2 실측 — 코드 인용 판례의 코퍼스 공백

계산기·판정기·앱 코드의 `.py`에서 사건번호 17건을 추출해 대조했다.

| 판정 | 건수 | 사건번호 |
|------|-----:|----------|
| 보강 코퍼스에 문서로 수록 | 4 | 2008다6052, 2016다243078, 96다24699, 2019다29778 |
| 크롤 코퍼스에 **언급만** 확인(문서 존재 미확정) | 5 | 2023다302838(9파일), 2014도8873(9), 2020다300299(9), 2008다57852(12), 2022다291153(1) |
| **어디에도 없음**(내용 언급조차 0) | 8 | 2023다302579, 2013다4174, 2021다201143, 2017헌바127, 2006다49372, 2018다238518, 2006다49653, 2021헌마1234¹ |

¹ `2021헌마1234`는 번호 패턴상 프롬프트 예시(placeholder) 의심 — Do에서 실인용/예시를 판별해 인벤토리에 구분 기록한다.

⚠️ "언급"은 **참조판례 인용 함정**(기존 실측: 본문 정규식 매칭 2,450 vs 실제 대표 819)이 있으므로 문서 존재의 증거가 아니다. 대표 사건번호(파일당 1개) 판정은 Do 단계 과제.

### 1.3 왜 지금인가 — 유실 단일점과 공개 경계

- **디스크 유실 시나리오**: 보강분은 법제처 재수집이 가능하지만 그 전제인 사건번호 목록 CSV도 로컬 전용이다. 크롤분은 nodong.kr 게시물 잔존 여부에 의존한다. 원장 유실 시 `laborlaw-v2` 판례 벡터의 부분 정리(고아 정리·롤백)가 불가능해진다.
- **Pinecone 유실 시나리오**: 과거 `--reset`이 실제로 인덱스 전체를 지운 사고가 있었다. 현재 구조에서 재적재는 로컬 원본이 있어야만 가능하다 — 즉 두 저장소가 서로의 백업이 아니라 **같은 디스크에 공동 의존**한다.
- **공개 경계**: 저장소가 **PUBLIC**이다. 판결문 자체는 저작권법 제7조(비보호 저작물)라 커밋이 안전하지만, 크롤 게시물의 편집·해설과 교재 유래 쟁점 태그는 경계 확인 없이 커밋하면 공개 배포가 된다. "코퍼스는 비공개 백엔드"라는 전제가 공개 채널에서 깨지는 것은 textbook-G6에서 이미 겪은 실패 클래스다.

### 4.2 아카이브 레코드 스키마 (초안 — Design에서 확정)

```json
{
  "case_no": "2000다15869",          // NFC 정규화
  "case_key": "2000da15869",         // 원장 키 규약 — pinecone_upload_legal의 변환 함수 import (사본 금지)
  "court": "대법원", "decided": "2000.06.09", "doctype": "prec",  // prec/detc
  "title": "부당이득금",
  "source": "letec",                 // letec | crawl | code-only | nlrc
  "origin_url": "https://www.law.go.kr/...", "local_path": "output_판례_보강/2000다15869_부당이득금.md",
  "issues": ["임금채권 우선변제"],    // 교재 유래 태그 — 경계 확인 후 포함 여부 확정
  "body_md": "..."                   // 원문 전문 (로컬 파일이 유일한 원문 출처 — Pinecone chunk_text 복원 금지)
}
```

### 4.3 인벤토리 컬럼 (초안)

`사건번호, case_key, 법원, 선고일, 제목, 문서보유(letec/crawl/양쪽/없음), 검색수록(laborlaw-v2:precedent_ 청크수 / laborlaw-v2:ctx_precedent_ / 사장NS만 / 미수록), 인용처(code/textbook/nlrc — 복수), 비고(예시번호·미발견 등)`

### 4.4 대안 검토

| 결정 | 채택 | 기각 대안과 이유 |
|------|------|------------------|
| D1. 저장 형식 | **jsonl.gz 번들 + 평문 인벤토리 CSV** | ⓐ 사건별 md 약 2,400개 평문 커밋(32MB): 저장소 파일 수·크기 오염, GitHub 검색 이득은 인벤토리 CSV로 대부분 대체됨. ⓑ 저장소 밖(클라우드): 인프라 추가·접근 단절, 공공저작물이라 비공개화 이유도 없음. gz 커밋은 `bm25_corpus.jsonl.gz`(19MB)로 확립된 관례고, gz의 diff 불가 단점은 평문 인벤토리가 보완. 사람이 읽는 문서는 `--extract`로 상시 복원 |
| D2. 범위 | **법원 판례 + 헌재 결정만** | 행정해석·훈령은 후속(§3 비목표). NLRC는 이미 커밋된 번들이라 중복 보관하지 않고 인벤토리 참조만 |
| D3. 중복 정본 규칙 | **법제처 수집분 우선** | 같은 사건이 보강·크롤 양쪽에 있으면 법제처 원문이 정본(공식 출처·정형 스키마·비보호 확실). 크롤분은 '대체 출처'로 인벤토리에 기록. 크롤분만 있는 사건이 크롤 계층의 존재 이유 |
| D4. 크롤분 공개 여부 | **기본 비공개, 게이트 통과 시 승격** | 오폐기(비공개 보관)는 내구성만 약간 손해지만 오공개(해설 혼입 커밋)는 회수 불가 — 방향 비대칭이 해설서 위생 처리 원칙("폐기만 범용, 복원은 명시")과 동일 |

### 4.5 기존 자산 재사용 (필수 — 사본 금지)

- 사건번호 추출·NFC 정규화·부호 로마자 매핑: `pinecone_upload_legal.py`의 단일 출처 함수 **import** (T14 NFD 사고 + M1 사본 드리프트 교훈 — 회귀 T14-g~j와 같은 구조 보장)
- 사건부호 화이트리스트: `extract_textbook_cases.py::CASE_RE` (조문 표기 오인 방지, T20)
- 대표 사건번호는 **파일당 1개** — 본문 전량 정규식 스캔 금지 (참조판례 함정)
- 원장 `_uploaded_ids.json`은 **읽기 전용** — 이 사이클은 Pinecone에 쓰지 않으므로 원장을 수정할 일이 없다
