> **Feature**: 크롤 판례 318건(verbatim)을 프로덕션 검색 네임스페이스에 적재
> **Period**: 2026-09-14 (Plan)
> **Status**: Plan

## Executive Summary

### 사이클 개요

| 항목 | 내용 |
|------|------|
| **Feature** | `output_법원 노동판례/`의 판례 문서 중 **문서는 보유하나 프로덕션 검색이 안 되는 318건**을 `laborlaw-v2`에 적재 |
| **대상 확정 근거** | 아카이브 인벤토리 전수 대조(2026-09-14) — 사장 NS에만 존재 340건 중 게이트 `verbatim` 318건 |

| **선행 확인 완료** | 저작권 게이트 통과 · letec 중복 0 · 문서 로컬 보유(재수집 불요) |

### Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 노동 판례 원문 **340건이 사장 네임스페이스(`precedent`/`laborlaw`)에만 존재**한다. 봉인 전 `pinecone_upload_legal.py`가 `rag.py::NS_GROUPS`(`laborlaw-v2`/`counsel`/`qa`)가 읽지 않는 곳에 올렸고, **임베딩 비용은 이미 지불됐으나 답변에 쓰인 적이 없다.** CLAUDE.md가 경고한 '조용한 실패'의 최대 잔재다 — 성공 메시지도 벡터 수도 정상이었다. |
| **Solution** | 게이트 `verbatim` 318건을 `laborlaw-v2`에 재적재한다. 문서가 판결문 **전문** 형식(`【주 문】`·`【이 유】`)이라 기존 `EMBED_SECTIONS`(판시사항·판결요지·참조조문)가 한 건도 매칭되지 않으므로, **`【이 유】` 블록만 임베딩**하고 당사자 표시 등 절차 보일러플레이트를 구조적으로 제외한다. |
| **Function & UX Effect** | 사용자 인터페이스 변화 없음. 코퍼스 측 변화는 `precedent` 소스가 7,750 → 약 9,700문서(+25%). 출처 라벨·저작권 상한은 기존 `precedent` 규약을 그대로 따르므로 신규 가드가 필요 없다. **검색 품질 개선폭은 착수 시점에 알 수 없다** — `eval_retrieval` 기준선 재측정이 완료 조건에 포함된다. |
| **Core Value** | **이미 가진 자산을 쓸 수 있게 만드는 일이다.** 이번 세션의 다른 잔여 항목들과 대비된다 — 미수집 1,186건은 회수 경로가 없었고, 접미 절단은 오탐 75%였고, `<sup>` 헤딩 구출은 10건에 4권 재업로드였다. 318건은 문서가 이미 로컬에 있고 저작권 경계도 이미 통과했으며 중복도 0이다. **막힌 곳이 없는 유일한 잔여 항목이다.** |

## 1. 현황 — 실측 (2026-09-14)

### 1.1 문서 보유 대비 검색 가능 상태

아카이브 인벤토리(`data/precedent_archive/inventory.csv`) 전수 대조:

| 보유처 | 문서 | 검색됨 | 검색 불가 |
|---|---:|---:|---:|
| letec (`output_판례_보강/`) | 1,744 | 1,732 (99.3%) | 12 (0.7%) |
| **crawl (`output_법원 노동판례/`)** | **815** | 475 (58.3%) | **340 (41.7%)** |

검색 불가 352건의 내역:

```
340건  crawl  — 사장 NS(precedent/laborlaw)에만 존재
 12건  letec  — 벡터 없음(전문만 있어 EMBED_SECTIONS 제외, 설계 의도)
```

### 1.2 저작권 게이트 대조

`data/precedent_archive/documents.csv`의 `gate` 열 기준, 340건 **전량 매핑**:

| 버킷 | 건수 | 비율 | 처리 |
|---|---:|---:|---|
| **verbatim** | **318** | 93.5% | **대상** — 판결문 원문, 저작권법 제7조 제3호 비보호 |
| editorial | 22 | 6.5% | **제외** — nodong.kr 편집 발췌(제목 자체가 편집자 요약) |

게이트는 2026-09-01에 승인됐다(`crawl_gate.json`: `approved=true`, 표본 육안 포함). 이 사이클은 그 승인을 **소비할 뿐 재분류하지 않는다.**

### 1.3 대상 문서의 구조 — 기존 업로더가 쓰이지 않는 이유

318건 **전량이 판결문 전문 형식**이다. `판시사항`·`판결요지` 섹션 보유 **0건**.

```
# {nodong.kr 게시물 제목}
| 항목 | 내용 |          ← 메타 표(분류/작성일/사건번호)
---
대법 2020.1.16. 선고 2014다41520
【원 고, 상고인】 …          ← 당사자 표시(보일러플레이트)
【피 고, 피상고인】 …
【원심 판결】 …
【주 문】 …
【이 유】 …                 ← 법리 판단(실질)
```

`【】` 블록 실측 빈도: 주문 320 · 이유 320 · 원심판결 319 · 당사자 표시 4종 428.

| 지표 | 값 |
|---|---:|
| 본문 총량 | 1,296,608자 |
| **【이 유】 분량** | **1,213,038자 (93.6%)** |
| 【이 유】 보유 문서 | **318 / 318** |
| 예상 청크(700자·overlap 80) | **약 1,956개** |
| 문서 길이 | 중앙값 3,770자 · 평균 4,194자 · 최대 18,000자 |

## 2. 문제 정의

| ID | 문제 |
|---|---|
| **P1** | 노동 판례 원문 318건이 **프로덕션 검색에 도달하지 않는다.** 사장 NS 적재는 어떤 게이트에도 걸리지 않는 조용한 실패이고, 이 저장소에서 가장 큰 잔재다. |
| **P2** | 크롤 판례를 **프로덕션 NS에 올리는 경로가 없다.** `pinecone_upload_legal.py`는 봉인(사장 NS 적재), `pinecone_upload_court_precedents.py`는 letec 포맷(`판시사항`/`판결요지`) 전용이라 318건에 0건 매칭. `pinecone_upload_contextual.py`는 원장이 없다(CLAUDE.md 알려진 갭). |
| **P3** | 전문을 그대로 올리면 **절차 보일러플레이트가 검색 노이즈**가 된다. `EMBED_SECTIONS`가 전문을 제외한 근거 중 하나다. |

### 2.1 `EMBED_SECTIONS` 전문 제외 규약과의 관계

기존 규약의 근거는 둘이다(`pinecone_upload_court_precedents.py:58-59`):

> 최대 52,867자로 단일 판례가 75청크가 되고, 【원고, 상고인】 같은 절차 보일러플레이트가 검색 노이즈가 된다.

이 사이클은 규약을 **바꾸지 않는다.** 적용 대상이 다르다:

| 근거 | letec(규약 대상) | crawl 318 |
|---|---|---|
| 크기 | 최대 52,867자 → 75청크 | **중앙값 3,770자**, 최대 18,000자 |
| 보일러플레이트 | 제거 수단 없음 | **`【】` 블록으로 구조적 제거 가능** |
| 대안 | 판시사항·판결요지가 있음 | **없음 — 전문 아니면 0** |

letec은 "전문 대신 요지를 쓴다"는 선택이지만, crawl 318은 **전문이 아니면 적재 자체가 불가능**하다. 두 근거 모두 이 대상에는 성립하지 않거나 해소 가능하다.

## 4. 접근 방식

### 4.1 산출물

| # | 산출물 | 비고 |
|---|---|---|
| 1 | `pinecone_upload_crawl_precedents.py` | 신규. 크롤 포맷 파서 + `【이 유】` 추출 |
| 2 | `output_법원 노동판례/_uploaded_ids.json` | 원장(`vector_ledger.py` 재사용, 코퍼스별 분리 규약) |
| 3 | 회귀 T30 | 포맷 파싱·보일러플레이트 제외·게이트 준수·원장 그룹 키 |
| 4 | BM25 코퍼스 재빌드 | 커밋 대상 |
| 5 | `eval_retrieval` 전후 측정 | analysis에 기록 |

### 4.2 chunk_id 규약 (초안 — Design에서 확정)

```
crawlprec_{case_key}_{chunk_idx}
```

- `case_key`는 `pinecone_upload_court_precedents.case_no_to_ascii`를 **import**한다(사본 금지 — 원장을 만든 바로 그 함수)
- 기존 `precedent_{case}_chunk_N`(letec)과 **접두사를 분리**해 두 코퍼스의 원장·prune 범위가 섞이지 않게 한다
- 원장 그룹 키는 **사건번호** — letec과 같은 이유(부분 실행이 나머지를 고아로 오판하는 것 방지)

### 4.3 대안 검토

| 대안 | 판단 |
|---|---|
| `pinecone_upload_court_precedents.py` 확장 | **기각.** letec 포맷 전용 파서에 분기를 넣으면 두 코퍼스의 청킹 규약이 한 파일에서 얽힌다. `EMBED_SECTIONS` 변경 압력도 생긴다 |
| `pinecone_upload_contextual.py` 재사용 | **기각.** 사장 NS 적재 + 원장 없음. CLAUDE.md가 명시한 갭을 답습한다 |
| 사장 NS 벡터를 `laborlaw-v2`로 복사 | **기각.** 구벡터는 NFD 충돌로 ID가 손상된 이력이 있다(`precedent` NS, 474벡터 유실). 원문에서 다시 만드는 것이 안전하다 |
| 전문 전체 임베딩 | **기각.** 보일러플레이트 6.4%가 검색 노이즈. `【】` 구조로 제거 가능한데 굳이 지지 않는다 |

### 4.4 기존 자산 재사용 (필수 — 사본 금지)

| 자산 | 용도 |
|---|---|
| `vector_ledger.py` | 원장·prune (textbook·court가 이미 공유) |
| `pinecone_upload_court_precedents.case_no_to_ascii` | `case_key` 생성 |
| `app/config.py::open_offline_index` | 대량 조회 시 타임아웃 |
| `data/precedent_archive/documents.csv` | 대상 선정(`gate == verbatim`) — 게이트 재구현 금지 |
