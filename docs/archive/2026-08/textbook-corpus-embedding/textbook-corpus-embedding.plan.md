## Executive Summary

| 항목 | 내용 |
|------|------|
| Feature | 노동법 해설서 2권 본문을 인용 가드와 함께 Pinecone에 임베딩 + 해설서 인용 판례 166건 공공 API 수집 |

### Value Delivered

| 관점 | 내용 |
|------|------|
| Problem | RAG 코퍼스는 판례·행정해석·상담 Q&A로만 구성돼, "왜 그런 결론이 나오는가"를 설명하는 **법리 해설 계층이 없다**. 특히 최저임금 산입범위·통상임금·임금 지급 4원칙처럼 조문과 판례 사이를 잇는 해석론이 필요한 질문에서 답변이 조문 나열에 머문다. 해설서 2권은 확보돼 있으나 저작권 우려로 2026-08-09부터 dry-run 상태로 보류돼 있다(`textbook` 벡터 실측 0건). |
| Solution | 본문 1,877청크를 `laborlaw-v2`에 `source_type=textbook`으로 임베딩하되, **축자 인용 금지·출처 표기 강제·동일 서적 청크 상한**의 3중 인용 가드를 함께 구현한다. 동시에 해설서가 인용하는 판례 중 코퍼스에 없는 166건을 법제처 공개 API로 수집해(저작권 무관) 판례 계층도 함께 보강한다. |
| Function UX Effect | "최저임금에 상여금이 산입되나요", "임금 직접지급 원칙의 예외는" 같은 해석론 질문에서 해설서의 법리 설명이 근거로 제시되고, 그 해설이 인용하던 판례 원문도 함께 검색된다. 답변은 요약·재진술 형태로만 나가고 출처(서명)가 표기된다. |
| Core Value | 법리 해설이라는 **새로운 검색 계층**을 추가하면서, 원문 축자 재생산을 구조적으로 차단해 저작권 노출 표면을 최소화한다. |

### 1.3 핵심 문제 (선행 수정 없이는 업로드 불가)

| ID | 문제 | 영향 |
|----|------|------|
| **D1** | `chunk_id`가 `textbook_{heading_idx:04d}_chunk_{n}` — **서적 식별자가 없다** | 2권을 같은 스크립트로 올리면 heading_idx 0~157 구간이 완전히 겹쳐 **주해 Ⅲ 463청크가 Win 노동법 청크를 덮어쓴다**. CLAUDE.md에 기록된 NFD post_id 충돌(판례 836개 → 고유 362개, 474개 유실)과 동일 계열의 조용한 데이터 손실 |
| **D2** | `source_type="textbook"` 라벨이 두 곳 모두에 없음 — `app/core/rag.py::format_pinecone_hits`의 라벨 맵, `public/index.html::renderSources`의 `labels` 객체 | LLM 컨텍스트 헤더와 사용자 화면 출처 칩에 원문 `textbook`이 그대로 노출. 출처 표기 요건(§3)도 미충족 |
| **D3** | 업로드 후 BM25 코퍼스 미갱신 시 신규 벡터가 키워드 검색에서 누락 | `build_bm25_corpus.py` 재실행 + `data/bm25_corpus.json.gz` 커밋 필수. 미커밋 시 프로덕션이 Dense-only로 조용히 폴백 |
| **D4** | 인용 가드 미구현 — 현 프롬프트에 해설서 축자 인용을 제한하는 규칙이 없다 | 저작물 본문이 답변에 그대로 재생산될 수 있다. §3 결정의 전제 조건 |
| **D5** | 주해 Ⅲ 헤딩 10건이 OCR 손상(`$I.99$`, `$/대 모 키$`, `!!!!!!…`, `Ⅱ. 최저임금 결정절차 [○ 1901 19121212 …`) | 손상 헤딩이 `section` 메타데이터와 `embed_text` 접두사에 그대로 들어가 검색 품질·출처 표시를 훼손 |

> D2·D4는 이미 안전한 부분도 있다. `_build_sources_payload()`는 `{title, section, source_type, score, origin}`만 담고 `chunk_text`를 프론트로 보내지 않으므로, **원문 조각은 SSE `sources` 이벤트와 공개 게시판에 노출되지 않는다.** 가드는 LLM 컨텍스트 단계에 집중하면 된다.

## 2. 구현 계획

### Phase 0 — 원본 반입·전처리 검증

- 주해 Ⅲ `.md`를 `output_노동법교재/근로기준법주해3_임금.md`로 복사(디렉토리는 `output_*/`라 gitignore 대상)
- 본문 시작 마커 확정: `<!-- page: 6 -->` (`# 제 3장 임 금` 직전). 앞 5페이지는 표지·목차 OCR 스프
- D5 대응 — 손상 헤딩 10건을 `KNOWN_OCR_FIXES` 방식의 **명시 치환**으로 처리. 범용 보정 로직은 만들지 않는다(선행 사이클의 확립된 관례)
- 검증: `--dry-run`으로 섹션 158 / 청크 463 재현, 샘플 청크 8건 육안 확인

### Phase 1 — 업로드 스크립트 다중 서적화 (**D1 수정**)

`pinecone_upload_textbook.py`를 서적 레지스트리 구조로 확장한다.

```python
BOOKS = {
    "win":   {"title": "Win 노동법(2025, …)", "path": …, "body_start": "<!-- page: 18 -->", "ocr_fixes": {…}},
    "juhae3":{"title": "근로기준법 주해 Ⅲ — 임금(제2판 수정증보판)", "path": …,
              "body_start": "<!-- page: 6 -->", "ocr_fixes": {…}},
}
```

- `chunk_id` → `textbook_{book_id}_{section_idx:04d}_{chunk_idx}` — 서적 간 충돌 원천 차단
- 메타데이터에 `book_id` 추가(향후 서적별 필터·부분 삭제 대비)
- CLI: `--book <id>` / `--all` / `--dry-run`. `--reset`은 계속 금지(공유 네임스페이스)
- 재업로드는 결정적 `chunk_id` upsert 덮어쓰기로 처리(기존 관례 유지)

### Phase 2 — 인용 가드 + 출처 라벨 (**D4·D2 수정**)

| 가드 | 구현 위치 | 내용 |
|------|-----------|------|
| G1 축자 인용 금지 | `app/templates/prompts.py` (`CONSULTATION_SYSTEM_PROMPT`, `COMPOSER_SYSTEM`) | 해설서 출처는 **요약·재진술만 허용**, 원문 문장 그대로 옮기지 않는다 |
| G2 단독 근거 금지 | 동일 | 해설서만으로 결론 내지 않는다 — 반드시 법조문 또는 판례로 뒷받침 |
| G3 출처 표기 강제 | 동일 + `rag.py::format_pinecone_hits` | 해설서 근거 사용 시 서명 표기(저작권법 제37조 출처 명시) |
| G4 동일 서적 청크 상한 | `app/core/rag.py` (rerank 이후) | 한 답변의 컨텍스트에 들어가는 동일 `book_id` 청크를 **최대 3개**로 제한 — 연속 구간 대량 재생산 차단 |
| G5 라벨 매핑 | `rag.py` 라벨 맵 + `public/index.html::renderSources` | `textbook` → `"노동법 해설서"` |

### Phase 3 — 본문 임베딩 업로드 (Track A)

- `python3 pinecone_upload_textbook.py --book juhae3 --dry-run` → 육안 검증 → 실행
- `--book win` 동일 절차 (보류 해제)
- 목표 벡터: 주해 Ⅲ 463 + Win 1,414 = **1,877**

### Phase 4 — 인용 판례 수집 (Track B)

1. `extract_textbook_cases.py` (신규) — 서적 본문 → 사건번호 추출 → 기존 코퍼스 대조 → `_미발견.csv` 차감 → 수집 대상 CSV
   - 사건부호 **화이트리스트** 필수. 기존 `CASE_NO_RE`(`\d{2,4}[가-힣]{1,4}\d+`)는 `43조의2`·`109조2` 같은 **조문 표기를 사건번호로 오인**한다(실측: 필터 없으면 308건 중 113건이 노이즈)
   - 번호 내부 공백 표기(`95다 53188`) 흡수
2. `fetch_court_precedents.py`에 `--input <csv>` 옵션 추가 — 기존 `--cases`는 L2 중복검사를 **생략**하므로 신규 수집에 부적합
3. 수집 → `output_판례_보강/` → `pinecone_upload_court_precedents.py --dry-run` → 업로드
4. (선택) `enrich_court_precedents.py`를 주해 Ⅲ 목차에도 적용해 '관련 쟁점' 태깅 — **인용 위치라는 사실 정보만** 사용, 해설 문장은 요약·의역 형태로도 가져오지 않음(선행 사이클 경계 유지)

### Phase 5 — BM25 재빌드 + 검증 (**D3**)

- `python3 build_bm25_corpus.py` → `data/bm25_corpus.json.gz` **커밋**
- `textbook` 카운트가 1,877, `precedent` 증가분이 수집 성공 건수와 일치하는지 대조
- 회귀 테스트: `test_precedent_ingest.py`에 chunk_id 충돌 방지 케이스 추가(2권 동시 처리 시 ID 유일성)

## 3. 저작권 검토 — 기존 결정의 변경

### 3.1 변경 내용

| 구분 | 기존 결정 (2026-08-09) | 본 사이클 |
|------|------------------------|-----------|
| 해설서 본문 | Pinecone 미업로드 | **업로드하되 인용 가드 5종(G1~G5) 적용** |
| 해설서 인용 사건번호 | 사실 정보로 추출·사용 | 동일 (유지) |
| 판례 원문 | 법제처 API 수집 (저작권법 제7조 제3호 — 판결은 보호 대상 아님) | 동일 (유지) |
| 원본 파일 커밋 | 금지(`output_*/` gitignore) | 동일 (유지) |

### 3.2 근거

- 코퍼스는 **비공개 검색 백엔드**다. 벡터·원문 조각이 외부에 배포되지 않으며, `_build_sources_payload()`가 `chunk_text`를 프론트로 보내지 않으므로 SSE `sources`·공개 게시판 어디에도 원문 조각이 노출되지 않는다.
- 출력물은 G1(축자 인용 금지)에 따라 **요약·재진술 형태**로만 생성되고, G3에 따라 출처가 표기된다.
- G4(동일 서적 3청크 상한)가 연속 구간의 대량 재생산을 구조적으로 차단한다.

### 3.3 남는 리스크 (수용)

LLM이 프롬프트 규칙을 100% 준수한다는 보장은 없다 — G1은 **소프트 가드**다. G4만이 구조적 상한이다. 확정적 통제가 필요하다면 Track A를 중단하고 Track B만 유지하는 선택지가 남아 있으며, `book_id` 메타데이터가 있으므로 서적별 롤백 경로도 확보된다.

> Pinecone Serverless는 메타데이터 필터 삭제를 지원하지 않는다. 롤백은 `chunk_id` 목록을 보존해 명시 삭제하는 방식이어야 한다 — Phase 3에서 업로드한 ID 목록을 파일로 남긴다.
