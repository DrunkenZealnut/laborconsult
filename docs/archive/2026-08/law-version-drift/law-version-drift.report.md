## 2. 프로세스에서 얻은 것

1. **이중 리뷰 관례 4번째 적중, 이번엔 양쪽 다** — gap-detector가 "한 파일 grep에 그친 영향 범위 조사"의 사각(`build_graph.py` 복제 사전매핑)을, 경로 리뷰가 P1 4건(2건은 이 변경이 새로 연 구멍)을 각각 적발했다. P1-1은 "조회 실패"보다 나쁜 "**틀린 조문이 맞는 법령명으로 인용**" 유형.
2. **검증 도구는 프로덕션 실입력을 봐야 한다** — 정식명 17종 고정 목록 검증은 U+00B7 결함을 영원히 통과시켰다. 목록을 `TOPIC_SEARCH_CONFIG`에서 생성하도록 바꾼 것이 재발 방지의 핵심.
3. **판본 대조 기준의 함정** — 시행일자 대조는 부칙 단계시행 법령(세법)에서 같은 공포본을 드리프트로 오판한다. 이 오탐 때문에 맞는 설계(LM)를 동적 MST로 되돌릴 뻔했다 — 판본 식별자는 공포일자+공포번호.
4. **리뷰 봇과의 근거 기반 공방** — defusedxml 제안을 위협 모델 근거로 기각하자 CodeRabbit이 자체 웹 검색 후 **자기 지적을 철회**했고, 캐시 현행성 Major는 절충안(TTL 유계화 + 정책 명문화)을 5개 항목 조목 확인 후 승인했다.
