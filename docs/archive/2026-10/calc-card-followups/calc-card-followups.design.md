# calc-card-followups — Design

> Plan: `calc-card-followups.plan.md`(같은 폴더) · 작성 2026-10-15 · 기준 코드 main `e76ab02`
> 범위: Plan P0-1~P0-5·P1-1~P1-2. 여기에 Design 중 찾은 2건을 더한다. 하나는 F6(평균임금·보수월액에서 연장수당 누락)이고, 다른 하나는 F7(해고예고 면제를 개정 전 규정으로 판정)이다(§0 D10·D11). P2는 범위 밖이다(§12).
> **이 문서의 법률 사실은 작성 시점에 공식 원문·행정해석으로 확인했다(§1).** 재현 값은 `_run_calculator(params, query)`로 뽑았다(LLM 호출 없음).

## 0. 설계 결정 요약

Plan의 열린 질문 D1~D8에 대한 답과, Design에서 새로 정한 D9~D12다.

| # | 결정 | 이유 |
|---|---|---|
| D1 | **주 40시간 초과분은 근무일 순서대로 쌓아 판정한다.** 하루 소정(최대 8h)을 쌓다가 주 40h에 닿으면 그 뒤 시간은 연장근로다. 소정근로일은 소정 시간이 하루라도 있는 날 수다. 예: 주 6일 × 8h → 소정 8h × 5일 + 연장 8h(6일째), 주휴 8h. 주 6일 × 7h → 소정 40h를 6일에 걸쳐(1일 평균 6.67h) + 연장 2h | 대법원 2022다291153 [4]의 '1일 평균 소정근로시간(1주 소정 ÷ 1주 소정근로일)'에 넣을 소정근로일을 정하는 규칙이다. 노동부 해석(근기 01254-5392, 1987: 근로시간이 법정근로시간을 넘으면 주휴는 법정근로시간분)과 상담 실무(토요일은 연장, 주휴 8시간)가 같은 결론이다. 고르게 나누면(40 ÷ 6 = 6.67h) 6일째 8시간이 전부 연장인데도 하루 6.67시간 소정으로 읽힌다 |
| D2 | **소정근로시간 상한(1일 8h·1주 40h)은 상시 4명 이하에도 적용한다.** 초과분은 연장근로로 나누되 가산은 하지 않는다(1배) | 근로기준정책과-2668(2022. 8. 26., -3590 인용): 5인 미만도 제2조①8호 소정근로시간 정의가 적용되므로, 1일 10시간을 약정해도 일급 통상임금은 8시간분이다. 근로기준정책과-5106(2016. 8. 17.): 4인 이하가 1일 8h·주 40h를 넘겨 약정해도 주휴는 8시간분이다. 가산을 하지 않는 근거는 시행령 별표 1(제56조 없음)이고, 기존 `MultiplierContext`가 이미 그렇게 처리한다 |
| D3 | **예외 신호는 질문 본문 정규식으로 읽는다.** 대상은 탄력적·선택적·간주·재량 근로, 감시·단속·경비, 농림·축산·수산, 연소자, 잠수 등 유해작업이다. 신호가 있고 초과 시간도 있으면 분리하지 않고 PR #114의 '소정근로시간 미확인' 경로로 보내 제도 확인을 안내한다. 근로시간 특례 업종(제59조)은 신호가 아니다 | 의도분석 스키마에 근로시간 제도 필드가 없고, 프롬프트를 바꾸면 분류 전체가 흔들린다. 신호를 잘못 잡아도 금액 대신 조건이 나오는 쪽이라 손해가 작다. 평가 질문 148개를 재생하니 신호어가 든 질문은 3개였다. 셋 다 그 제도를 묻는 질문이고 초과 시간이 없었다(오탐 0, §3.6). 제59조는 연장 한도(주 12h)와 휴게만 바꾸므로 소정/연장 구분과 가산에 영향이 없다 |
| D4 | **기간급(일급·월급·연봉)에 초과 시간이 있으면 두 구성을 함께 계산한다.** 기본(A)은 '그 금액이 소정근로 + 주휴의 대가이고 연장은 별도'다. 연장분이 포함됐다고 보는 역산(B)도 계산해, 최저임금 판정이 갈리면 보류한다. 구성 진술(a50-36 경로)이나 포괄임금제 라벨이 있으면 기존 경로가 먼저다. 질문에 적힌 연장시간에도 같은 규칙을 쓴다 | 근로시간을 산정할 수 있는 고정 일정에서는 연장수당을 따로 주는 것이 원칙이다(포괄 약정이 없으면 A). 하지만 연장분을 월급에 넣는 약정이 흔하고, 그 경우 판정이 뒤집힌다(R6: 12,945원 충족 vs 9,863원 미달). 최저임금 산입에서 연장근로 임금은 제외된다(최저임금법 제6조④1호) |
| D5 | **수습 요건은 질문에서 확인된 것만 충족으로 본다.** ① 계약기간: '정규직·무기계약·기간의 정함이 없는'이면 1년 이상, 의도분석 `contract_months`가 있으면 그 값, 없으면 미상 ② 수습 경과: 질문의 '수습 N개월'(N ≤ 3이면 충족)이나 'M개월째'(M ≤ 3이면 충족), 없으면 미상 ③ 직종: `occupation_code`, 없으면 미상. 미상이 있고 90%·100% 판정이 갈리면 보류한다. `probation_months` 기본값을 3에서 None으로 바꾼다 | 의도분석 지시가 "기간 정함 없는 정규직이면 contract_months를 설정하지 마세요"라서 None이 정규직과 미기재를 함께 뜻한다(prompts.py). 기본값 3 때문에 수습 6개월 중 5개월째(R11)에도 90%가 적용됐다. 스키마 대신 본문을 읽는 이유는 D3과 같다 |
| D6 | **최저임금 상태는 표시용 필드로 가른다.** `WageResult.minimum_wage_ok`(bool·None)는 그대로 두고, `minimum_wage_state`를 추가한다. 값은 `""`(미실행)·`compliant`·`violation`·`held`·`not_applicable`이다. 미실행이면 헤더 줄을 내지 않는다. 특고는 `not_applicable`이고 헤더는 '➖ 해당 없음 — 노무제공자(근로자성이 인정되면 적용)'다 | None을 판정 값으로 쓰는 곳(법률 힌트 `mw_ok`, JSON, 단언 30여 곳)을 건드리지 않고 표시만 갈라낸다 |
| D7 | **격일제 추출은 Do 첫 단계에서 실측한다**(3가지 표현). 분리는 1일 단위라 근무일수 표현과 무관하다. 1일 시간이 12h를 넘으면 [기준시간]에 '휴게·수면시간은 근로시간에서 뺀다(제54조)'를 덧붙인다 | 24시간 격일제는 휴게를 빼기 전 값이 의도분석에 그대로 들어올 수 있다 |
| D8 | **질문에 연장시간이 따로 적혀 있으면,** 그 값(stated)과 1일 초과분 합계(derived)가 같을 때는 그 값을 쓴다. 다르면 큰 값을 쓰고 "둘이 별개라면 합계 N시간"이라고 안내한다 | 같은 2시간을 두 필드에 함께 적는 추출이 흔해, 합산하면 이중 계산이 된다. 다른 날 추가 근무를 따로 적은 경우에는 합계가 맞으므로 안내로 남긴다 |
| D9 | **분리는 순수 함수 `shared.split_hours()`와 적용 함수 `apply_hour_split(inp)`로 한다.** 파이프라인은 미확인 모드 판정 직후·구성 판정 전에 적용한다. facade `_calculate`도 첫머리에서 적용하되, 이미 적용됐으면(`inp.hour_split`) 넘어간다. 계산기 함수 안에는 넣지 않는다 | 모든 계산기가 정규화된 같은 일정을 읽는다(단일 출처). 파이프라인의 구성 판정(`_has_premium_hours`)이 파생 연장시간을 봐야 포괄임금 역산이 맞게 돈다. 계산기를 직접 부르는 기존 테스트(T10 교차 일관성 루프)는 원래 뜻 그대로 남는다 |
| D10 | **평균임금·보수는 `shared.monthly_pay_estimate(inp, ow, base)`로 구한다.** 월 임금총액이 주어지지 않았고 포괄임금 총액도 아니면, base에 연장·야간·휴일수당 월액을 더한다. 평균임금·보수 계열 9곳이 이 함수를 쓴다 | 카드의 '월 총 예상 수령액'(3,285,000원)과 평균임금·보수월액(2,502,857원 기준)이 갈려 있었다(R15). F1이 연장시간을 새로 만들면 R8이 과대(7,200,000원)에서 과소(5,760,000원)로 뒤집힌다 |
| D11 | **해고예고 면제는 현행 제26조 단서 3개 호만 본다.** 1호(계속근로 3개월 미만)는 입사일부터 해고일(없으면 기준일)까지로 계산하고, 입사일이 없으면 조건부로 안내한다. 수습·일용 1개월·계절적 사업 면제와 '단서 4호' 표기는 지운다 | 2019. 1. 15. 개정으로 단서가 바뀌었다(`lsa_act_26` 원문). 지금 카드는 수습 5개월째 해고에 '면제·0원'을, 정규직 2개월째 해고에 2,876,712원을 낸다(R16·R17 — 둘 다 법과 반대) |
| D12 | **PR은 둘로 나눈다.** A = 시간 축(F1·F2·F5·F6, D1~D4·D7~D10), B = 적용 요건·표시(F3·F4·F4b·F7, D5·D6·D11). A를 먼저 낸다 | 리뷰 단위를 줄인다. 최저임금 시나리오 구조(D4·D5 공용)는 A에서 만든다 |

## 3. 시간 축 — 소정·연장 분리 (F1)

### 3.1 `split_hours`

```python
@dataclass(frozen=True)
class HourSplit:
    raw_daily: float; raw_days: float          # 질문(입력) 값
    daily: float; days: float                  # 정규화: 1일 평균 소정근로시간, 1주 소정근로일
    weekly_scheduled: float                    # = daily × days (≤ 40)
    excess: float                              # 1주 연장 = raw_daily × raw_days − weekly_scheduled
    mode: str                                  # "none"(초과 없음) | "applied" | "held"(D3 신호) | "skipped"(교대제 표·월 소정 직접 입력·탄력 계산 입력·특고)
    note: str = ""                             # [기준시간]에 붙일 설명

def split_hours(raw_daily, raw_days, *, daily_cap=8.0, weekly_cap=40.0) -> HourSplit:
    capped = min(raw_daily, daily_cap)
    if capped * raw_days <= weekly_cap:                     # 1일 한도만 걸림(또는 초과 없음)
        daily, days = capped, raw_days
    else:                                                   # 주 한도 — 근무일 순서대로 쌓는다(D1)
        full = floor(weekly_cap / capped)                   # 소정 시간을 꽉 채운 날
        rest = weekly_cap - full * capped
        days = full + (1 if rest > 1e-9 else 0)             # 소정근로일
        daily = weekly_cap / days
    weekly = daily * days
    return HourSplit(raw_daily, raw_days, daily, days, weekly, raw_daily * raw_days - weekly, ...)
```

| 입력(1일 × 일수) | 소정(1일 × 일수 = 주) | 연장/주 | 주휴(`weekly_holiday_hours`) |
|---|---|---|---|
| 8 × 5 | 8 × 5 = 40 | 0 | 8 (불변) |
| 10 × 5 | 8 × 5 = 40 | 10 | 8 |
| 10 × 4 | 8 × 4 = 32 | 8 | 32 ÷ 5 = **6.4** (현재 8) |
| 16 × 3.5 (격일제) | 8 × 3.5 = 28 | 28 | 28 ÷ 5 = **5.6** (현재 8) |
| 8 × 6 | 8 × 5 = 40 | 8 | 8 |
| 7 × 6 | 6.67 × 6 = 40 | 2 | 6.67 (현재 7) |
| 6 × 7 | 5.71 × 7 = 40 | 2 | 5.71 (현재 6) |
| 12 × 2 (주말) | 8 × 2 = 16 | 8 | 16 ÷ 5 = **3.2** (현재 4.8) |
| 16 × 1 | 8 × 1 = 8 | 8 | 주 15h 미만 → **주휴 없음**(현재 3.2) |

- 주휴 함수(`weekly_holiday_hours`)는 바꾸지 않는다. 계약은 '입력은 소정근로시간'이고, 소정을 보장하는 책임은 호출부(D9)에 있다. T10의 `(4, 10): 8` 같은 단언은 '1일 소정 10h'라는 불가능한 입력에 대한 값이라, 분리 경로 테스트로 옮긴다(§8 T1).
- 주 15시간 판정(주휴 발생·연차 비례)도 정규화된 소정으로 한다. 마지막 행처럼 판정이 바뀔 수 있는데, 2022다291153 [2]①에 따른 결과다.
- 연소자(제69조: 7h·35h)·유해작업(산안법 제139조: 6h·34h)은 한도 인자만 다르다. 이번에는 D3 신호로 보류만 하고, 한도를 바꿔 계산하는 기능은 넣지 않는다(§12).

### 3.2 적용 위치와 건너뛰는 경우

`apply_hour_split(inp) -> HourSplit`는 `inp.hour_split`이 있으면 그 값을 돌려준다. 없으면 아래를 판정하고, `applied`일 때만 `inp.schedule`을 바꾼다.

| 건너뜀(`skipped`) | 이유 |
|---|---|
| `schedule.monthly_scheduled_hours` 또는 `shift_monthly_hours`가 있음, `work_type`이 교대제 표 4종 | 기준시간을 직접 정한 입력이다. 교대제 표(182.5h 등)의 성격은 별도 점검 대상이다(§12). 파이프라인은 이 값들을 배선하지 않는다 |
| `flexible_work_unit`이 있음 | 탄력적 근로시간제 계산 입력이다 |
| `is_platform_worker` | 근로시간 규정이 적용되지 않는다 |
| `daily_work_hours <= 0`(미확인 모드) | PR #114가 0으로 둔 값이다 |

정규화는 `daily_work_hours ← daily`, `weekly_work_days ← days`, `weekly_overtime_hours ← D8 조정값`이다. 야간·휴일 시간은 그대로 둔다. 원래 값은 `hour_split.raw_*`에 남는다.

| 소비처 | 변화 | 코드 변경 |
|---|---|---|
| 월 기준시간 `_get_base_hours` | (소정 + 주휴) × 주 수 | `applied`면 상세 문자열만 바꾼다: `주 근로 10h×5일 = 50h → 소정근로 8h×5일 = 40h + 연장 10h(1일 8시간·주 40시간 초과분 — 근로기준법 제50조, 대법원 2022다291153), 주휴시간: …, 월 환산: …`. D1 경우(주 6일 × 8h)는 '6일째 8h는 주 40시간을 넘는 연장근로라 소정근로일 5일로 계산'을 붙인다 |
| 주휴수당 | 정규화된 값으로 계산한다 | 없음 |
| 1일 통상임금(`ordinary_wage`) | 시간급 × 1일 소정 | `daily_hours_used` 필드를 추가한다(퇴직금 표기용) |
| 소정근로시간(`working_hours`) | 1일·주 소정 표기 | 연장이 있으면 '1주 연장 N시간(소정근로 아님)' 한 줄 |
| 연장수당(`overtime`) | `weekly_overtime_hours`에 파생분이 들어간다 | 산식을 `shared.premium_weekly()`로 빼고 표기에 '(1일 8시간 초과 2h × 5일)'을 단다. 52시간 합계는 소정 + 연장이라 값이 같다 |

| 포괄임금 역산 | 기본시간 = 소정 + 주휴, 연장 계수 = 연장 × (1 + 가산) | 없음 — 파생 연장시간이 계수에 들어간다 |
| 연차(단시간 비례) | 비율 = 주 소정 ÷ 40 | 없음(4일 × 10h: 비율 1.0 → 0.8) |
| 최저임금 비교시간 | 소정 기준시간 | 시나리오 B(D4, §3.5) |

### 3.4 연장 가산과 사업장 규모

- 가산율은 기존 `MultiplierContext`를 그대로 쓴다(4명 이하 0, 그 밖 0.5). D2에 따라 4명 이하도 분리하고 연장은 1배로 계산한다.
- 파이프라인은 질문에 규모가 없을 때(`params["business_size"]` 비어 있음) 기본값 5인 이상으로 계산해 왔다. 연장(파생·명시)이 계산된 카드에는 경고 한 줄을 붙인다: "상시 5명 이상 기준으로 연장 가산(50%)을 계산했습니다 — 상시 4명 이하면 가산 없이 1배입니다(근로기준법 제56조, 시행령 별표 1)."
- 파생 연장이 있고 임금이 있으면 `overtime`을 계산 대상에 넣는다. 그래야 카드의 '월 총 예상 수령액'에 연장분이 빠지지 않는다.

### 3.5 기간급의 두 구성 (D4)

조건은 넷 모두다: `wage_type ∈ {DAILY, MONTHLY, ANNUAL}`, 연장·야간·휴일 시간이 있음(파생·명시), `comprehensive_breakdown` 없음, 파이프라인이 구성을 확정하지 않음(`wage_composition_known=False` — a50-36 정확·보류 경로와 포괄임금제 라벨은 True로 둔다).

- **A(기본):** 지금처럼 금액 ÷ 소정 기준시간(일급은 ÷ 1일 소정). 연장수당은 A의 통상시급으로 계산한다.
- **B(연장분 포함 역산):** 월급·연봉은 월액 ÷ (기준시간 + Σ 연장·휴일 × (1 + 가산) × 주 수 + 야간 × 가산 × 주 수)이다. 포괄임금 계수(`_calc_coefficient_hours`)와 같은 산식이다. 일급은 일급 ÷ (1일 소정 + 1일 연장 × (1 + 가산))이다.
- 최저임금 판정은 A와 B가 같으면 그 판정을 내고 안내를 덧붙인다. 다르면 보류하고 두 값을 함께 낸다(§5.1 시나리오 `ot_included`).
- 이 모드에서는 카드의 '월 총 예상 수령액'을 숨긴다(`monthly_total = 0`). A의 총액(월급 + 연장)을 받을 금액으로 단정하지 않기 위해서다. 연장수당 줄은 남긴다.
- 안내 문구(경고 첫 줄): "월급 270만 원이 하루 8시간·주 40시간(소정근로)의 대가라면, 하루 2시간씩 주 10시간은 연장근로라 연장수당(월 X원)이 따로 발생합니다. 월급에 연장수당을 포함한다는 약정(포괄임금·고정연장수당)이 있으면 역산 시급은 9,863원이고, 그 기준으로는 최저임금에 미달합니다 — 판정은 보류했습니다. 근로계약서의 임금 구성을 확인하세요."

|---|---|---|

| derived = 0 | stated | — |
| \|stated − derived\| ≤ 0.5 | stated | — |

### 3.8 격일제와 휴게 (D7)

- 분리는 1일 단위라 '주 평균 3.5일'·'월 15일' 어느 쪽으로 들어와도 결과가 같다. 월 단위 근무일은 파이프라인이 이미 주 단위로 바꾼다.
- `raw_daily > 12`이면 [기준시간]에 덧붙인다: "휴게·수면시간은 근로시간에서 뺍니다(근로기준법 제54조) — 질문의 N시간에 휴게가 들어 있으면 소정·연장 시간이 달라집니다."
- 경비 격일제는 D3(감시·단속) 신호로 미확인 모드가 된다.

### 3.9 시급 없는 주휴 블록

`_wageless_weekly_holiday(days, daily)`도 `split_hours`로 나눈다. 연장이 있으면 블록 둘째 줄이 바뀐다: `1주 근로시간: 4일 × 10h = 40h → 소정근로 8h × 4일 = 32h + 연장 8h`. 주휴는 정규화된 값으로 계산한다(4 × 10 → 6.4h).

### 4.3 평균임금·보수 (F6)

def premium_weekly(inp, hourly) -> PremiumWeekly        # calc_overtime의 연장·야간·휴일 산식을 그대로 옮김(단일 출처)

def monthly_pay_estimate(inp, ow, base):
    """월 임금총액 추정 — 주어진 총액이 있으면 그 값, 없으면 base + 연장·야간·휴일수당 월액."""
    if inp.monthly_total_pay:
        return inp.monthly_total_pay
    if base is None:
        return None
    if inp.wage_type == WageType.COMPREHENSIVE:          # 포괄임금 총액에는 이미 들어 있다
        return base
    return base + premium_weekly(inp, ow.hourly_ordinary_wage).total * WEEKS_PER_MONTH
