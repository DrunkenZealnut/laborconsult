# adjudication-corpus — 재결례 코퍼스(고용보험심사위원회 `eiac` 118 · 산재재심사위원회 `iaciac` 934) Plan

> 입력: 법제처 OPEN API `target=eiac`·`iaciac` 전량 목록과 상세 표본 50건 실측(2026-11-08), BM25 코퍼스 스냅샷(95,762문서, 11-08), 실사용 질문 170건(2026-07-01 이후, 합성·중복 제외), 직전 사이클(unemployment-separation-grounds) 측정의 잔존 유보 분류.
> 범위: 두 위원회의 재결례 1,052건을 공식 원문 코퍼스(`laborlaw-v2`)에 새 출처 유형으로 적재하고, 검색·쿼터·승격·라벨·인용 검증의 배선을 한 번에 한다. 노동위원회 판정문(`nlrc` 44,430건)은 범위 밖(§3).
> 선행: unemployment-separation-grounds(PR #153·#154 머지). 그 Plan §6 D2가 이 사이클을 정했다.
> 작성 2026-11-08 · 단계: Plan → Design(2026-11-08, D1~D7 확정)

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 실업급여는 실사용 질문의 26%(170건 중 45건)인데 심사 쟁점(피보험자격·부정수급·수급자격)의 공공 근거는 상담글의 12%뿐이고(공공 673 대 상담 5,581), 직전 사이클 뒤에도 실업급여 답변의 잔존 유보는 전부 "인용할 판례·행정해석이 없다"는 고지였다. 실제 심사 사례를 담은 재결례는 코퍼스에 0건이다. |
| **Solution** | 고용보험심사위원회 재결례 118건과 산재재심사위원회 재결례 934건을 법제처 API로 전량 받아(검색이 사건명 fuzzy라 전량 수집 후 분류) 새 출처 유형 `ruling`으로 `laborlaw-v2`에 적재한다. 공공 쿼터·법률근거 승격·라벨·출처 우선순위·인용 검증(재결 번호 화이트리스트)·BM25를 함께 배선한다. |
| **Function UX Effect** | "회사 대표 배우자인데 피보험자격이 되나", "해외에서 구직활동했는데 부정수급이냐", "자진퇴사인데 수급자격 불인정됐다", "요양 불승인·장해등급에 불복하려면"에 위원회가 실제로 어떤 사실관계를 어떻게 판단했는지 인용 가능한 사례로 답한다. 판단 주체(위원회·공단)는 그대로 둔다. |
| **Core Value** | 저작권 비보호 공공 원문(저작권법 제7조 제3호)으로 상담글 의존을 줄인다. 직전 사이클이 '규칙'을 공급했다면 이번은 '적용 사례'를 공급한다. 새 출처 유형의 배선을 한 번에 끝내 다음 공공 출처(법령해석례 등) 추가 비용을 낮춘다. |

**목표 지표**(측정은 저장소 밖 하네스 `run_eval … --law-mode cache --primary openai`, 변경 전 base vs 변경 후 브랜치, 같은 모델):

| 지표 | 목표 |
|---|---|
| 재결례 공급 | 합성 양성(심사 쟁점) 문항의 80% 이상에서 `ruling` 출처가 최종 컨텍스트에 실린다. 무관 문항(임금·연차·해고예고)에서는 0건 |
| 인용 정확 | 답변의 재결 번호는 전부 컨텍스트에 있는 것이다(화이트리스트 밖 0). 환각 번호는 검증기가 제거한다 |
| 근거 부재 유보 | 심사 쟁점 양성 문항에서 **그 쟁점 문장에 한정한** "판례·행정해석·사례 없음" 고지가 변경 전 평균의 절반 이하(직전 사이클 교훈 — 쟁점 한정 정의) |
| 비회귀 | `eval_retrieval` 해설서 도달률 불변, `eval_corpus_mix` 공공 비율 상승, 지식iN 12문항 금지 문구 비증가, 오프라인 스위트·`test_bm25_memory` 통과 |
| 자원 | BM25 로드 피크 RSS ≤ 550MB(CI Linux 기준 — 현재 459MB), `laborlaw-v2` 적재 1,052건 전량·원장 기록·고아 0 |

## 1. 실측 (2026-11-08)

### 1.1 수요

실사용 질문 170건(2026-07-01 이후, 합성·중복 제외):

| 주제 | 건수 | 비고 |
|---|---|---|
| 실업급여 전체 | 45 (26%) | 수급자격·이직사유 14, 부정수급·반환 1, 피보험자격 0(정규식 기준 — 상담글에서는 '가입 이력·확인청구' 표현이 흔해 실제는 더 많다) |
| 산재 전체 | 9 (5%) | 요양 2, 장해등급 2, 휴업급여·평균임금 1, 출퇴근 1 |
| 재결·심사청구 언급 | 0 | 불복 절차 자체를 묻는 질문은 없다 — 재결례의 쓸모는 '절차'가 아니라 '판단 사례'다 |

### 1.2 공급 (BM25 스냅샷 95,762문서)

| 쟁점 | 공공(판례·행정해석·훈령고시) | 상담(qa·counsel) | 해설서 | 공공/상담 |
|---|---|---|---|---|
| 실업급여 심사(실업급여·구직급여·피보험자격·부정수급) | 673 (판례 23 · 행정해석 14 · 훈령고시 635) | 5,581 | 33 | **0.12** |
| 산재(요양·장해·유족·휴업급여·업무상 재해) | 2,315 (판례 1,060 · 행정해석 130 · 훈령고시 1,123) | 1,329 | 1,449 | 1.74 |
| 재결·심사청구 언급 | 347 | 69 | 46 | — |

- 실업급여 심사 쟁점의 공공 근거는 훈령·고시가 대부분이고 **판례는 23건**이다. 피보험자격·부정수급은 법원까지 가는 일이 드물어 판례가 없고, 그 층위의 판단은 심사위원회 재결에 있다.
- 산재는 판례·훈령 공급이 이미 두텁다. 그래도 요양 불승인·장해등급은 사실관계가 결과를 가르는 쟁점이라 재결례의 **사실관계 서술**(사고 경위·업무 내용·의학적 판단)이 판례 요지보다 상담 질문과 밀도가 맞는다.

### 1.3 직전 사이클이 남긴 것

unemployment-separation-grounds 측정(2026-11-07)에서 변경 후 잔존 유보 8·4건(43건 중)은 **전부 이직사유 밖**이었고, 그 다수가 "제공된 자료에서 인용할 판례·행정해석은 확인되지 않습니다"였다. 재결례는 바로 그 빈칸(심사 사례)을 채우는 출처다.

## 2. 범위

### P0-1 수집 (`fetch_rulings.py`, 신규)

- `target=eiac`·`iaciac` 목록 전량(display 100 페이지 순회) → 상세(`lawService.do?ID=결정문일련번호`) → `output_재결례/{agency}/{일련번호}_{사건번호}.md`(gitignore `output_*/`).
- `fetch_court_precedents.py`의 패턴을 따른다: `_raise_if_error_root`(인증 오류를 '미발견'으로 저장하지 않는다), 진행 기록(`_progress.json`)으로 재개, 요청 간격, 저장 본문은 원문 그대로(공백 정리만 — `clean_api_text`와 같은 수준).
- 청구인 필드는 저장하되 **임베딩 본문에서 제외**한다(성별·나이·직종은 판단에 불필요하고 프로파일링 텍스트가 된다). 저장 전 개인정보 패턴(주민번호·전화)을 스캔해 발견 건을 기록한다(DoD).
- 메타: agency(`eiac`|`iaciac`), serial(일련번호), case_no, title(사건명/사건), decided_at(의결일자), category(사건의분류 / 대·중·소분류), disposition(주문 요지), official_url(결정문상세링크를 law.go.kr 공개 URL로 정규화 — OC 제거).

### P0-2 적재 (`pinecone_upload_rulings.py`, 신규)

- 네임스페이스 `laborlaw-v2`, `source_type="ruling"`(D1), 벡터 ID `ruling_{agency}_{serial}_{idx:03d}`. **그룹 키는 일련번호**(iaciac 사건번호 중복 2건) — `VectorLedger` 원장 `output_재결례/_uploaded_ids.json`, 고아 정리·대량 삭제 가드는 court 업로더와 같다.
- 청킹: 머리글(기관 · 사건번호 · 의결일자 · 분류 · 사건명) + 개요/쟁점 + 주문을 첫 청크에, 이유를 700자·겹침 80으로. 각 청크 `text`에 머리글을 붙여 BM25·답변 헤더가 출처를 잃지 않게 한다(판례 `[사건명 사건번호]` 헤더 관례).
- `official` 표식은 **달지 않는다** — 승인 게이트의 공식 원문 2차 조회(`official: True`)는 금액 고시용이고, 이미 qpack 7,111건으로 희석돼 있다.
- 커밋 대상 원장: `data/vector_ledgers/rulings_2026MM.json`(저장소 밖 스크립트가 아니라도 ID 목록을 남긴다 — 비보호 저작물이라 원문 번들 커밋도 가능하나 D6).

## 3. 범위 밖

- **노동위원회 판정문(`nlrc` 44,430건) 적재.** 1건 1청크라도 +46% 문서라 BM25 상한을 바로 넘는다(nlrc Plan §3.1). 현재 라이브 조회 경로는 프로덕션에서 `LAW_API_LIVE=off`라 죽어 있다 — 별도 과제(고정 IP 또는 부분 적재 설계).
- 행정심판 재결례(`decc` 4건)·법령해석례(`expc` 3건) — 노동 관련 건수가 적어 보류.

- 심사청구 **절차** 안내(기한·서식) — 질문 수요 0, 기존 조문(고용보험법 제87조 등)으로 충분.
