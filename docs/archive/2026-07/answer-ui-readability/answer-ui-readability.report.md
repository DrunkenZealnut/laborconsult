## Executive Summary

### Overview
- **문제**: `public/index.html`의 마크다운 렌더러와 CSS에서 표 폭, 목록 구성, 타이포 위계의 12건 결함으로 인해 답변이 읽기 어려움
- **해결 방식**: 3웨이브(표 래퍼·목록 중첩·타이포 정리)로 설계 16항목 전부 구현, 하네스 29건과 브라우저 검증 6건으로 확인
- **결과**: Match Rate 100%, 설계-구현 완전 일치, 반복 불필요
- **수치**: 발견·수정 결함 16건(사전 감사 12건 + 설계 검증 1건 + 구현 검증 4건), 변경 파일 1개(`public/index.html` CSS 11행 + 렌더러 ~80행)

### 1.3 Value Delivered

| Perspective | Content |
|-------------|---------|
| **Problem** | 사용자 불만: "표가 답변 폭을 채우지 못하고 중간에 끝나버린다." 근본 원인은 `display: block; width: auto` 표가 내용 폭만큼만 그려지기 때문. 추가로 목록이 중첩을 지원하지 않아 하위 항목이 평탄해지고(LST-1), 번호 항목 사이에 불릿이 끼면 번호가 깨지며(LST-2), 헤딩 위계가 1px 크기 차로 식별 불가능하고(TYP-1), 모바일에서 셀이 글자 단위로 세로 분해되는 문제(D3). 설계 검증 단계에서 신규 P1(중첩 placeholder 미복원으로 인한 내용 소실, LST-5)도 발견. 총 16건 결함 확정 |
| **Solution** | ① 표를 `.table-wrap` 스크롤 래퍼로 감싸 항상 답변 폭 100%를 채우고 overflow 시에만 래퍼 내부 스크롤(TBL-1~3) ② 목록 파서를 "번호 우선 + 들여쓰기 스택" 구조로 재설계해 중첩 `<ul>` 지원, 번호 연속성 유지, placeholder 고정점 복원으로 내용 소실 해소(LST-1~5) ③ 타이포 스케일(h2 18px/h3 16px/본문 15px) + 간격 리듬 정리, 표 셀 `inlineTransform` 적용, 말풍선 폭 일관화, 셀 `word-break: keep-all` 추가(TYP-1~2, D1~D4) |
| **Function/UX Effect** | 표가 답변 폭 전체를 채우고 "끊긴 표" 체감 소멸. 긴 텍스트 셀은 줄바꿈되고 금액/숫자는 한 줄 유지로 스캔 용이. 들여쓴 하위 항목이 실제 중첩 구조로 표시되고 번호 연속성(1→2→3) 유지. 모바일(375px)에서 표가 래퍼 스크롤로 수용되고 셀 글자 분해 없음. h2/h3 위계로 섹션 경계 한눈에 파악. 대표 샘플(표, 중첩 목록, 계산 결과, 콜아웃) 전부 시각 정상. 기존 리치 컴포넌트(콜아웃, summary-badge, step-list) 회귀 없음 |
| **Core Value** | **표(계산 내역)와 목록(절차·요건)이 구조 그대로 전달**되어 법률 상담 답변의 신뢰감과 이해도 향상. 렌더링만으로 콘텐츠 품질 개선 없이 가독성 개선. 모바일/데스크톱 일관된 경험 제공 |

## Lessons Learned

### What Went Well

1. **설계 검증 하네스의 조기 버그 발견**: Plan의 "검증 필요"였던 LST-2를 Design 단계에서 렌더러 추출 하네스로 재현 확정하고, 그 과정에서 신규 P1(LST-5)을 추가 발견. 이 발견이 설계 깊이(고정점 복원)를 크게 높였다.

2. **구현 중 브라우저 검증의 즉시 피드백**: Do 단계에서 로컬 서버로 실제 렌더링을 확인하면서 셀 볼드 미변환(D1), 말풍선 폭 비일관(D2), 모바일 셀 분해(D3) 같은 "설계에서 예상 못 한 상호작용"을 발견하고, 설계를 역으로 보강(§8 구현 확정)할 수 있었다 — PDCA 순환 없이도 설계-구현 정렬.

3. **단일 파일 완결의 롤백 용이성**: 변경이 `public/index.html` 하나에 집중되어 git 단위 롤백이 자명하고, 파이프라인 연쇄 영향 없음. 작은 단위의 계획이 유연한 실행을 가능하게 함.

4. **고정점 루프의 robust한 내용 소실 해결**: placeholder 재귀 복원을 단순 do-while로 구현해 중첩 블록 내 placeholder도 확실히 복원. 종료 보장(DAG 성질)과 알려진 한계(li 내부 `</p>…<p>` 래핑)를 미리 설계에 명시해 위험 제거.

### Areas for Improvement

1. **Plan 단계의 "검증 필요" 항목을 Design 이전에 자동 하네스로 확정**: LST-2는 정규식 상호작용이라 정독만으로는 재현 어렵다. Plan §3.1 P1 5건 발견 후 즉시 하네스 원형을 만들었으면 1~2시간 단축 가능했을 것.

2. **모바일 셀 분해 문제(D3)의 사전 예방**: Pretendard의 `word-break: break-word` 상속이 CJK 테스트 없이는 숨어있었다. Design 검증 사항에 "다국어 텍스트 셀(`keep-all` 테스트)"을 명시했으면 Do 단계 진입 시 즉시 대응 가능.
