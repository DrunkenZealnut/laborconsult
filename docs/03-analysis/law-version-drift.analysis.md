## 2. 머지 차단 결함 (경로 리뷰, 전부 실측 재현)

### P1-1. LM 응답에 법령명·현행성 검증 게이트가 없다 【신규】
`root.tag == "법령"`만 보고 채택하는데, 법제처 LM 조회는 **별칭·폐지판까지 해석**한다 — 실측: `LM=근로자직업훈련촉진법` → **국민 평생 직업능력 개발법**(94조문) 반환, `LM=노동조합법` → 1996년 **타법폐지**판 반환. 더 나쁜 것은 `fetch_relevant_articles`가 헤더에 **요청명**을 쓰므로 다른 법의 조문이 요청한 법령명을 달고 LLM 컨텍스트에 들어간다. Design docstring의 "드리프트가 원리적으로 불가능"은 반증 — MST 고정 드리프트가 **이름 오해석 드리프트로 벡터만 바뀐 것**. CLAUDE.md가 판례 수집에 기록해 둔 "정확일치 게이트 없이 채택하면 엉뚱한 것이 섞인다" 실패 클래스와 동일 구조다.
**조치**: `기본정보/법령명_한글`을 요청명과 대조(공백·가운뎃점 정규화 허용) + `제개정구분`에 "폐지" 포함 시 거부.

### P1-2. `제N항` 조회가 런타임에서 100% 실패한다 【기존, 본 세션 재검증】
`항번호`가 ASCII가 아니라 **원문자**(`①` U+2460)라 `re.search(r"(\d+)", "①")`이 절대 매치되지 않는다 — paragraph 지정 조회는 전량 None(실측 4법령 전부, 로그도 없음). `prompts.py:276`이 명시 지시하는 "최저임금법 제6조 제5항"(택시 특례)은 **한 번도 조회된 적이 없다**.
**조치**: 원문자→숫자 변환(U+2460~U+2473 연속, `ord(c)-0x245F`) + 항 미발견 시 조문 전체 폴백(인용이 통째로 사라지는 것 방지).

### P1-3. 폴백 경로에서 서킷브레이커가 무력화된다 【신규】
`_resolve_official_name`의 `_circuit_record_failure()`를 호출자(`fetch_article`:318)의 `_circuit_record_success()`가 곧바로 상쇄 — 검색 엔드포인트만 죽은 상황 실측에서 요청 5회 후 fail_count 0, 서킷 영구 미개방(매 요청 8+3초 온전히 지불). 부수 발견: **API 키 부재/만료 시 법제처가 HTTP 200 + `<Response>` 루트를 반환**하는데 이것이 "법령명 미매칭"으로 오진되고 성공으로 기록된다 — 자격증명 장애가 영원히 법령명 문제로 보인다.
**조치**: 성공 기록은 1차 LM이 실제 `법령` 루트를 받았을 때만. 미매칭+폴백실패는 중립. `<Response>` 루트는 미매칭과 구분해 별도 경고.

### P1-4. 직장내괴롭힘 기본 법령 1/3이 항상 누락된다 【기존, 본 세션 재검증】
`legal_consultation.py:77`의 남녀고용평등법이 가운뎃점 **U+00B7**(`·`)인데 법제처 정식명·별칭 사전은 **U+318D**(`ㆍ`) — 코드포인트가 달라 LM 미매칭 + 양방향 부분일치도 양쪽 False → 최종 None. 하드코딩 인용 39건 전수 조회에서 실패는 정확히 이 2건(P1-2 항 포함). **`check_law_freshness.py`는 `ㆍ` 판본을 검사해 ✅를 내는데 프로덕션은 `·`로 조용히 실패한다** — 검증 스크립트와 프로덕션 입력의 대상 불일치.
**조치**: 77행 즉시 수정 + 구조적으로 `_resolve_law_name`에 가운뎃점 정규화(`·`/`ㆍ`/`‧` 흡수) — LLM이 어느 쪽을 내든 견디는 방법은 후자뿐.

**check 스크립트 결함**: 프로덕션 경로 미호출(폴백·`_extract_article`·이름 오해석 전부 검증 밖 — P1-2·P1-4가 여기서 새어나감), 반환 법령명 미대조, 검증 목록이 프로덕션 실입력(default_laws 39건)이 아닌 정식명 17종 고정. **개선 방향: 검증 목록을 `default_laws`+자동매핑에서 생성** — 분석자가 그 방식으로 실패 2건을 찾았다.

## 5. 점검했고 문제없음 (재검증 불요)

L2 upsert(콜론 키·동시 5스레드·RLS/GRANT — 프로덕션 실측), 구/신 키 공존 무해, 예외 전파(클로저→바깥 try), `probing` 플래그 누수 없음, 캐시 dict GIL 안전(RMW 없음), 17종 현행성 17/17, 오프라인 스위트 전체 통과.

## 6. 특기 사항

- **프로덕션 Supabase에 리뷰 프로브 행 2건 기록됨** — `v2:__probe_colon_test__:법_1`, `v2:__probe_race__:법_1`. `expires_at` 과거로 무해화 완료(조회 None 확인). anon 키로 DELETE 불가라 행 자체는 잔존 — SQL Editor 사용 시 삭제 권장.
- 이 Check가 잡은 P1-2·P1-4는 **이 사이클이 만들지 않은 기존 결함**이지만, 주제(법령 조회 정확성)가 정확히 겹치고 각각 1~5줄 규모라 iterate 범위에 포함하는 것이 합리적이다.

## 7. 다음 단계

2. P2-2(probe 배치)·P2-4(중복 제거)·check 스크립트 재설계(default_laws 기반 생성)는 규모 판단 후 포함/분리

### 8.2 Act 중 추가 발견·수정 (회귀 테스트가 적발)

- **폴백 부분일치가 공백 변형을 못 잡음** — 원형 그대로의 양방향 부분일치는 "근로자퇴직급여보장법" vs "근로자퇴직급여 보장법"이 어느 방향으로도 부분문자열이 아니라 실패. compact 정규화 후 비교로 수정(mock B1이 적발 — 라이브에서는 법제처 LM의 관대함이 가려 온 결함).

### 8.3 의도적 이월 (Report에 잔여로 기록)

- **P2-2 probe 배치·전역 서킷 분리** — 서킷 구조 재설계(조문/판례 분리, probe 부여 단위 변경)는 이 사이클의 목표(판본 정확성)와 축이 달라 별도 사이클로. 단 중복 서킷 검사 제거로 probe 고착은 해소됨.
- P3 4건(L2 반영 행 수·Session 쿠키·캐시 상한·카운터 원자성) — 진단성/이론적 수준, 관측 후 판단.
