## 1. 요약

**색 계층은 완결됐고, 치수 계층은 미완이다.**

토큰 단일 출처화·팔레트 교체·서체 단일화·이모지 제거·서비스워커 대응은 8개 페이지 전부에서 100% 이행됐다. 반면 **스페이싱 스케일·타이포 스케일·12칼럼 그리드·모션 규칙**은 손으로 다시 쓴 소형 4페이지(`offline` `install` `privacy` `terms`)에만 적용됐고, **대형 4페이지(`index` `board` `calculators` `admin`) 내부에는 거의 적용되지 않았다.**

원인은 구현 방식에 있다. 대형 페이지는 시간·위험을 이유로 **토큰명 기계 치환**으로 처리했다. 치환은 `var(--navy)` → `var(--color-text)` 같은 1:1 대응은 해결하지만, `font-size: 14px` → `var(--text-sm)`이나 `padding: 12px 16px` → `var(--space-2)`처럼 **대응이 1:1이 아닌 변환은 건드리지 못한다.** 색은 이름이 있었고 치수는 리터럴이었다는 차이다.

추가로 **다크모드를 실제로 깨뜨리는 결함 2건**과 **접근성 기준 미달 1건**이 `board.html`에서 발견됐다.

## 3. Gap 목록

### G-1 · 12칼럼 그리드 미적용 (FR-06) — 심각도 중

`tokens.css`에 `.grid-12`와 `--grid-columns`·`--grid-gap`이 정의돼 있으나 **어느 페이지도 사용하지 않는다.**

```
tokens.css 정의  : 3건
페이지 사용      : 0개 파일
```

설계 §3.4의 핵심 요구인 "격자는 구조다"가 코드에 반영되지 않았다. 정의만 있고 쓰이지 않으므로 현재는 죽은 코드다.

**대상**: `index.html`(랜딩·FAQ), `calculators.html`(메뉴), `admin.html`(통계 카드)

---

### G-2 · 이중 컨테이너 중 구조 영역 미이행 (D-3) — 심각도 중

`--reading-max`(800px)는 5개 파일에서 쓰이나 **`--container-max`(1280px)는 0개 파일에서 쓰인다.**

```
--reading-max   : board, index, install, privacy, terms (5)
--container-max : 0
```

설계 D-3은 "읽기 800px / 구조 1280px" 이중 구조를 결정했으나, 실제로는 전 페이지가 800px 단일 폭이다. 랜딩·계산기 메뉴의 1280px 승격이 누락됐다.

---

### G-3 · 모션 규칙 위반 26건 (FR-07 / M-1) — 심각도 중

`transform`·`opacity` 외 속성을 전이하는 선언이 남아 있다.

| 파일 | 위반 건수 |
|------|----------:|
| `index.html` | 14 |
| `board.html` | 10 |
| `calculators.html` | 1 |
| `admin.html` | 1 |
| **합계** | **26** |

주요 패턴:

```
transition: all 0.2s                                    16건
transition: border-color 0.2s                            3건
transition: right 0.3s cubic-bezier(...)                 1건   ← 슬라이드 메뉴. 레이아웃 리플로우 유발
transition: color 0.2s                                   1건
transition: background 0.15s, border-color 0.15s         1건
```

`transition: right`은 특히 문제다. `right` 애니메이션은 매 프레임 레이아웃을 다시 계산해 저사양 기기에서 프레임을 떨어뜨린다. `transform: translateX()`로 바꿔야 한다.

### G-4 · 스페이싱 스케일 부분 적용 (FR-05) — 심각도 중

대형 4페이지의 인라인 스타일에 임의 px 값이 그대로 남았다.

| 파일 | 고유 px 값 |
|------|----------:|
| `index.html` | 27종 |
| `board.html` | 17종 |
| `admin.html` | 14종 |
| `calculators.html` | 8종 |
| `privacy`·`terms`·`install` | 각 2종 |
| `offline.html` | 0종 |

`index.html`의 8px·4px 배수가 아닌 값: `1 2 3 5 6 7 9 10 11 13 14 15 17 18 22 26 34 42`(px) — 18종.

소형 4페이지는 손으로 다시 써서 완전히 이행됐고, 대형 4페이지는 기계 치환만 거쳐 미이행 상태다.

---

### G-5 · 타이포 스케일 거의 미적용 (FR-03) — 심각도 높음

가장 큰 미이행 항목이다.

| 파일 | 토큰 사용 | 리터럴 `font-size` |
|------|----------:|-------------------:|
| `index.html` | 0 | 71 |
| `board.html` | 4 | 47 |
| `admin.html` | 0 | 26 |
| `calculators.html` | 0 | 12 |
| **합계** | **4** | **156** |

설계 §3.2.2가 정의한 7단계 스케일(`--text-display` ~ `--text-label`)이 대형 페이지에서 사실상 쓰이지 않는다. "타이포그래피가 위계를 독립적으로 전달한다"는 이 시스템의 제1원칙인데, 그 위계를 구현하는 토큰이 미적용이다.

### G-6 · 다크모드 실효 결함 2건 (FR-09) — 심각도 높음 · 실제 버그

`board.html`에 라이트 고정 배경이 남아 다크모드에서 깨진다.

| 행 | 선언 | 영향 |
|---:|------|------|
| 188 | `.msg-bubble.bot { background: #f8f7f5 }` | 다크에서 밝은 회색 말풍선 + 밝은 본문 텍스트 → **글자가 읽히지 않음** |
| 211 | `.answer-outline { background: #f8f7f5 }` | 다크에서 목차 바가 밝은 채로 남음 |

188행이 특히 심각하다. 다크모드에서 `--color-text`는 `#F5F5F5`(거의 흰색)인데 배경이 `#f8f7f5`(거의 흰색)로 고정돼 **대비 약 1.02:1** — 사실상 안 보인다.

### G-7 · 액센트 hover 규칙 위반 1건 (A-7) — 심각도 높음 · 접근성

```
board.html:307  .write-btn:hover { background: #a86a3a; border-color: #a86a3a; }
```

Do 단계에서 `.submit-btn`은 고쳤으나 **`.write-btn`이라는 별개 버튼을 놓쳤다.** `#a86a3a`는 설계 §8.5에서 AA 미달(4.31:1)로 **명시적으로 기각한 값**이다. 어두워지는 hover라 A-7도 위반한다.

## 6. 회고 — 왜 벌어졌나

Do 단계에서 **대형 페이지에 기계 치환을 쓴 것**이 원인이다. 치환은 빠르고 안전했지만(회귀 0건) 이름이 있는 것만 바꿀 수 있었다.

| 대상 | 기존 형태 | 치환 가능? | 결과 |
|------|-----------|:----------:|------|
| 색 | `var(--navy)` | 가능 (1:1) | 100% 이행 |
| 서체 | `var(--font-display)` | 가능 (1:1) | 100% 이행 |
| 타이포 크기 | `font-size: 14px` | **불가** (문맥 판단 필요) | 30% |
| 스페이싱 | `padding: 12px 16px` | **불가** (반올림 판단 필요) | 40% |
| 그리드 | 구조 자체가 없음 | **불가** (마크업 변경 필요) | 20% |

교훈은 다음 사이클(흐름도 25종)에 그대로 적용된다. 흐름도는 하드코딩 hex 2,888회로 **색조차 이름이 없다.** 기계 치환이 통하지 않으므로 설계 §8.1의 매핑표를 먼저 완성하고 파일별로 검수해야 한다.

또 하나 — G-7(`.write-btn`)은 같은 규칙을 어긴 형제 선언을 놓친 사례다. 한 곳을 고칠 때 **같은 패턴을 파일 전체에서 찾는 습관**이 있었다면 Do 단계에서 잡혔다.

| 1 | `.notice-link` 서피스 위 코퍼 텍스트 | 2.99:1 | A-1 위반. 설계 §3.1.3이 예측한 정확한 수치 |

| 3 | `.msg.user` 동일 패턴 | 다크 1.09:1 | 〃 |

2~4번은 **`background: var(--color-text)`에 `color: white`를 고정한 패턴**이다. 라이트에서는 `--color-text`가 어두워 성립하지만 다크에서는 밝아져 흰 글씨가 사라진다. 정적 분석으로는 "토큰을 쓰고 있다"로 보여 통과한다 — 모드를 실제로 뒤집어야만 드러난다.

**추가 조치**: 푸터 구분자 `|` 2곳에 `aria-hidden="true"` 부여(장식 요소이므로 저대비가 의도된 것임을 명시).

### 7.4 미해소로 남긴 것

**FR-05 스페이싱 34%** — 의도적으로 남겼다.

8px 정확 배수 148건은 토큰으로 바꿨다(별칭이므로 시각 변화 0). 나머지 286건은 `10px` `12px` `14px` 같은 비배수 값이고, 이를 8px 격자에 맞추려면 **반올림해야 하며 레이아웃이 실제로 움직인다.** `padding: 12px`는 8px로 줄이든 16px로 늘리든 어느 쪽도 "무해한 치환"이 아니다.

브라우저 검수로 현재 상태의 무결성은 확인했지만, 286건을 일괄 반올림한 뒤의 결과는 **화면마다 다시 확인해야 안전하다.** 수치를 채우려고 검증 없이 밀어붙이면 지금 0건인 레이아웃 결함을 새로 만든다. 별도 사이클로 분리하는 편이 낫다.

**FR-06 그리드 75%** — 설계 D-3은 세 영역(랜딩·계산기 메뉴·관리자)을 1280px 구조 영역으로 지정했으나 실제로는 하나만 적용했다.

| 영역 | 판단 |
|------|------|
| 관리자 대시보드 | **적용.** 통계 카드 span 3, 차트 8/4 비대칭 |
| 랜딩(`index`) | **미적용.** 중앙 로고 + 채팅 입력 구조라 1280px로 넓히면 입력창이 과도하게 길어져 가독성이 나빠진다 |
| 계산기 메뉴 | **미적용.** `100dvh` 사이드바+뷰어 앱 셸이라 최대 폭 개념이 성립하지 않는다 |

설계의 일괄 규칙이 실제 UI와 맞지 않는 사례다. 설계 문서에 이 판단을 반영해야 한다(설계 D-3 수정 필요).
