# 노동OK Q&A 갱신 실행 설계

기준일: 2026-10-24. 상위 명세는 `docs/01-plan/features/nodong-qa-refresh-and-quality.plan.md`다.

## 선택한 구현

기존 Python·Pinecone·BM25 구조를 유지한다. 게시글 ID와 내용 해시를 갖는 manifest 및 문서별 갱신 장부를 추가한다. 기존 업로더 전체 재실행은 완료 파일명만 비교하므로 변경 답변을 놓치고, namespace 초기화는 다른 상담 자료를 삭제하므로 사용하지 않는다.

1. Q0/Q1: 원본 두 폴더를 읽어 ID별로 통합한다. 중복 내용 충돌은 자동으로 최신이라고 단정하지 않고 재조회 대상으로 표시한다. 작성일은 본문 밖 메타데이터에서만 읽는다. 답변 없는 댓글 영역의 로그인 안내를 답변으로 저장하지 않는다.
2. 수집: 실행 시작 시 KST 종료 시각을 고정한다. 페이지 범위를 명시하여 끝까지 방문하고, 2026-03-01부터의 겹침 구간과 기존 미답변·충돌 문서를 재조회한다. 목록 공지·관련글을 제외한다. 접근 차단·비정상 HTML·빈 목록은 실패로 기록한다. 완료 목록과 실패 목록으로 재개한다.
3. Q2: 운영 qa의 벡터 값·메타데이터를 먼저 보관한다. 평가 namespace에 운영 스냅샷을 복사하고 변경 문서만 기존 ID 규격으로 대체한다. 새 청크 확인 후 해당 문서의 남은 청크를 정리한다. BM25는 임시 산출물에서 전 namespace와 문서별 버전을 검증한다.
4. Q3/Q4: provenance를 Dense·BM25·최종 컨텍스트까지 보존한다. 공개 sources는 기존 필드만 내보내고 내부 추적은 별도 저장한다. 현재/과거 기준은 질문의 사건 시점으로 구분하며 상담글 자체를 법적 정답으로 삼지 않는다.
5. Q5: A(노동OK 제외)/B(이전)/C(갱신)의 다른 근거·계산기·모델을 고정한다. 기존 P0 고정 버전 62667da 기록은 보존한다. 실험 실행 코드와 모델 설정을 보고서에 별도로 명시한다. 자동 검사와 사람 평가는 구분한다.
6. Q6: 선택식 만족도 투표를 세션에 귀속시키며 내부 식별자·질문 원문을 중복 저장하지 않는다. 관측 4주 결과는 실제 자료가 쌓인 후 평가한다.
7. Q7: 재개·복구·주간 실행 명령과 점검표를 제공한다. 예약 실행 생성은 별도의 명시적 요청을 받아 적용한다.

## 검증·공개 경계

- 원문·벡터 백업·운영 평가 결과는 저장소 밖 권한 0700 작업 디렉터리에 보관한다.
- 테스트 fixture는 합성 질문으로 만든다. 수집한 이용자 원문을 테스트·보고서에 복사하지 않는다.
- 업데이트 후보는 Q5 통과 전 운영 qa에 적용하지 않는다. 검토용 PR에는 실행 범위·실패·비용·복구 방법을 포함한다.
- 기존 로컬 BM25 변경본은 별도 보관하며 덮어쓰지 않는다.
- 오류·중단은 정상 완료와 구분한다. 전체 사이트의 변경 전수 확인을 주장하지 않고 방문 페이지·ID를 명시한다.
