# law-version-drift Design

> Plan: `docs/01-plan/features/law-version-drift.plan.md` (실측: 17개 중 11개 낡음, 고용보험법 §70 실질 변경)
> 목표: 조문 조회를 MST 고정판본에서 법령명(`LM`) 현행판 조회로 전환 — 드리프트 재발 경로 제거

## 1. 변경 개요

| 대상 | 변경 | 근거 |
|------|------|------|
| `app/core/legal_api.py::fetch_article` | `_lookup_mst` 호출 제거, `lawService` 파라미터 `MST` → `LM` | MST 사용처는 이 함수 1곳뿐(295행). 판례 경로(`target=prec`)는 무관 |
| `_PRELOADED_MST` / `_MST_CACHE` / `_lookup_mst` | **삭제** | 남기면 부활 경로가 된다(Plan G2). `_lookup_mst` 호출처 1곳뿐이라 안전 |
| 캐시 키 | `v2:` 접두사 | L2에 낡은 조문이 최대 24h 잔존하는 것 차단(Plan G4) |
| `_resolve_law_name` / `_LAW_NAME_ALIASES` | **유지** | `LM`도 이름 정규화가 필요(약칭 10종). 실측상 법제처가 띄어쓰기 변형은 허용하지만 약칭("고보법")은 모른다 |
| 모듈 docstring·주석 | "법령 검색 → MST 획득" 서술 제거, *"전부개정 시에만 변경"* 오류 전제 제거 | 잘못된 전제가 남으면 재발 동기가 된다 |

## 2. `fetch_article` 신규 흐름

```
cache_key = f"v2:{law_name}_{article_no}[의{sub}][_{paragraph}]"   # ← 접두사만 변경
L1 → L2 → (circuit check) →
  ① lawService(target=law, LM=_resolve_law_name(law_name))
  ② 응답 판정: root.tag == "법령" → _extract_article(무변경 — 같은 스키마)
  ③ 미매칭(root.tag == "Law", 조문 0)이면 **1회 폴백**:
       lawSearch(query=canonical)로 정식 법령명 획득 → LM 재시도
  ④ 그래도 실패 → warning 로그 + None (기존 fail-open 유지)
```

### 2.1 응답 판정 (실측 기반 — Act에서 게이트 3종 추가)

| 입력 | 응답 | 판정 |
|------|------|------|
| 정식명 (17/17 검증) | `<법령>` 루트, **항상 현행판** | 반환 법령명·폐지 게이트 통과 후 성공 |
| 띄어쓰기 변형 ("근로자퇴직급여보장법") | `<법령>` — 법제처가 자동 정규화 | 성공 |
| 미등록 약칭·오타 | **HTTP 200 + 빈 `<Law>` 루트** | 미매칭 — 루트 태그 판정 필수 |
| **별칭·개명법** ('근로자직업훈련촉진법') | `<법령>` 루트인데 **다른 법**('국민 평생 직업능력 개발법') | **오해석 — 반환 `법령명_한글` 대조로 거부**(Check P1-1). 거부 없으면 다른 법의 조문이 요청명 헤더로 인용된다 |
| **폐지판** ('노동조합법') | `<법령>` 루트, `제개정구분=타법폐지` | **거부** |
| **자격증명·파라미터 오류** | **HTTP 200 + `<Response>` 루트** + 오류 문구 | **예외로 승격 → 서킷 failure**(Check P1-3). 미매칭 취급하면 키 장애가 "법령명 문제"로 영구 오진 |

법령명 비교는 전부 `_norm_law_name`/`_norm_compact`(가운뎃점 ㆍ·‧ 통일 + 공백 정리/제거) 경유 — U+00B7 하나로 조회가 조용히 실패한 실사례(P1-4)가 근거다.

### 2.2 폴백 ③의 성격 (Act에서 채택 조건 강화)

- 발동 조건: LM 미매칭. 발동 대상은 LLM이 `relevant_laws`에 넣은 비정형 이름.
- 기존 `_lookup_mst`를 **이름 해석기 `_resolve_official_name`으로 개명**해 재사용 — 부분일치는 **compact 정규화 후 양방향**(원형 그대로면 공백 변형이 어느 방향으로도 부분문자열이 아니라 폴백 목적 자체가 불성립 — Act 회귀 B1이 적발). 결과는 인메모리 캐시.
- **채택은 compact 동일(표기 변형)일 때만** — 실질 다른 이름(개명·다른 법)으로의 해석을 허용하면 조문과 헤더(요청명)가 어긋나는 오인용이 되살아난다(P1-1과 같은 결말). 그런 경우는 None(fail-open) + **L1 negative 캐시**(`_MISS_SENTINEL` — 없으면 실패 이름이 매 요청 LM 왕복을 반복, Check P2-3. L2에는 저장 금지 — 오타 7일 영속 방지).
- 내부 서킷 검사는 하지 않는다 — 호출자가 이미 통과했고, 중복 검사는 probe 요청이 자기 `probing` 플래그에 막혀 폴백을 못 타게 한다(Check P2-2).
- 서킷 기록 3치: 조문 확보 = success / 예외 = failure / **미매칭 확정 = 중립**(`_circuit_record_neutral` — probe만 반납). 미매칭에 success를 기록하면 폴백 검색의 failure가 상쇄돼 검색 장애에도 회로가 영영 안 열린다(Check P1-3).
- 호출량: 성공 경로 **1회**, 미스 경로 최대 3회 — 단 negative 캐시로 **동일 이름 재요청은 0회**.

## 3. 캐시 버전 전환

- **L1**: 프로세스 전역 dict — 배포 재시작으로 자연 해소. 키 접두사는 일관성용.
- **L2** (`laborconsult.law_article_cache`, `cache_key TEXT PRIMARY KEY`): 접두사 `v2:` 신규 키로 저장 → 기존 행은 조회되지 않는다. **별도 마이그레이션·수동 삭제 불요** — 지우는 게 아니라 안 읽는 방식이라 롤백도 안전(구버전 코드는 구 키를 계속 읽음).
  - ⚠️ **정정(Check G-2)**: 원안의 "TTL 24h 경과 후 `purge_expired_data()`가 수거"는 사실과 달랐다 — L2 만료는 **7일**(`_l2_cache_set`)이고, `purge_expired_data()`의 대상 6종에 `law_article_cache`는 **없다**. 구 행은 만료 후에도 삭제되지 않고 잔존한다(읽히지만 않으므로 정확도 영향 없음). 수거가 필요해지면 purge 함수에 1블록 추가가 별도 선택지다.
- 캐시 키의 `law_name`은 기존대로 **raw 이름**을 쓴다(canonical 정규화는 비목표 — 같은 조문이 약칭·정식명 두 키로 캐시되는 기존 동작 유지. 정규화하면 이 사이클의 diff가 커지고 기존 키 체계와 또 갈린다).

## 5. 롤백

- 코드 리버트만으로 완전 복귀 — 구버전은 구 캐시 키를 읽으므로 L2 정리 불요.
- 단계적 완화 수단은 두지 않는다(킬스위치 불요) — 실패 시 기존과 동일한 fail-open(None → RAG 흐름 유지)이라 장애 반경이 변하지 않는다.
