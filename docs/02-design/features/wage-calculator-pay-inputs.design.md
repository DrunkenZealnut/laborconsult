# C4b 지급 주기·평균임금·기존 휴가 입력 설계

확정일: 2026-10-24. 기준: C2 `b3507ea`, 실행 브랜치 `codex/wage-update-pay-inputs`.

## 1. 입력 계약

### 고정수당

- `amount`는 지급 회차 금액이다. `annual=true`이면 연간 총액이며 `/12`로 월 환산한다.
- `payment_cycle`: 매월·분기·반기·연. 각각 1·3·6·12로 나눈다. 명시적으로 불명인 주기는 금액 계산을 보류한다. 기존 직접 호출의 생략된 주기는 매월 계약을 유지하되 분석기는 주기를 확인하지 못하면 `미확인`을 기록한다.
- `source_id`는 질문의 동일 급여 항목을 연결하는 식별자다. 금액이 같다는 이유로 항목을 합치지 않는다.
- 통상임금, 최저임금, 고정연장수당의 월 환산을 일치시킨다. 월 환산은 매월 실제 지급할 채권을 뜻하지 않는다(C5에서 지급기일 별도).

### 평균임금

| 필드 | 의미 |
|---|---|
| `monthly_total_pay` | 명시된 월 총액·월 환산 총액. 기본급은 별도로 유지 |
| `last_3m_wages` | 산정기간의 실제 임금 내역. 숫자 배열 또는 `{base, allowance}` 배열. 생략한 경우에만 기준 월액×3 추정 |
| `last_3m_days` | 제외 전 산정기간의 달력일수. 제외 후 일수를 재차 빼지 않는다 |
| `annual_bonus_total` | 직전 12개월의 평균임금 산입 대상 연 상여 총액. 계약상 장래 상여를 실제 지급액으로 만들지 않는다 |
| `annual_bonus_allowance_ids` | 연 상여와 같은 항목인 고정수당의 `source_id` 목록. 명시적 빈 목록은 별개 항목. 미확인 시 중복 가능 항목이 있으면 보류 |
| `last_3m_bonus_included` | 실제 3개월 임금총액에 이미 들어 있는 위 연 상여의 금액. 0은 포함되지 않았다는 명시 확인 |
| `monthly_total_bonus_included` | 총액 또는 연봉에서 추정한 월액에 이미 포함된 위 연 상여의 월 환산액. 포함 여부가 불명확하면 보류 |
| `excluded_periods` | `{start, end, reason, paid}`. 시작·끝 포함. 법정 제외 사유와 그 기간의 임금(실지급 자료 사용 시 필수)을 확인 |

실제 자료가 있으면 월액 추정치로 대체하지 않는다. 잘못된 배열·날짜·음수·무한값은 0으로 보정하지 않는다. 제외 기간 중복·산정 창을 일부만 걸치는 금액·산정기간 전부 제외는 추가 확인 대상으로 보류한다. 완전히 같은 제외 기록은 한 번만 반영한다. 사유 발생일 없이 날짜 구간을 빼지 않는다.

상여 중복 제거는 `(3개월 임금 - 이미 포함된 동일 상여) + 연 상여×3/12`로 한다. 추정 경로에서는 동일 `source_id` 수당을 제거한 월액과 원래 월액의 차액을 사용한다. 총액을 직접 제공한 경로는 포함 금액을 별도 확인한다. 이름·금액의 유사성으로 자동 차감하지 않는다.

상여·연차 가산과 제외 기간이 함께 있으면 연간 산입 기준 및 제외기간 귀속액을 추가 확인하도록 보류한다. 1년 미만 근속의 연 상여도 실제 지급 대상 개월 수가 필요하므로 12개월로 확정하지 않는다. 일반 3개월 산식이 적용되지 않는 사례를 부풀린 금액으로 내보내지 않는다.

보류는 평균임금을 사용하는 퇴직금·휴업수당·산재보상·실업급여·DB 퇴직연금에도 전파한다. 별도 보험 계산은 유지한다.

### 기존 휴가 하위 유형

- `maternity_leave_type`: `maternity`, `spouse_birth`, `infertility`, `spouse_miscarriage`. 질문에서 요청한 유형만 표시한다. 본인 유산·사산은 기존 모듈에 구현되지 않았으므로 출산 90일로 대체하지 않는다.
- `family_leave_days`, `family_leave_used_days`: 이번 사용 일수와 같은 법정 한도에서 이미 사용한 일수. 날짜와 일수 미확인 시 실제 수령액을 확정하지 않는다.
- `family_leave_start_date`·`family_leave_end_date`는 실제 사용 구간, `family_leave_eligible`는 법정 요건 충족의 명시 확인이다. 입사·퇴사일에서 대신 만들지 않는다.
- `family_leave_insured_days`, `is_priority_support_company`: 고용보험 수급 조건. 보험 조건이 불명확하면 사업주 유급액과 조건부 지원 상한을 구분한다.
- 난임치료는 2026-11-27 전 6일 중 2일 유급, 이후 4일 유급. 배우자 유산·사산은 2026-09-18 이후 5일 중 3일 유급. 기존 근거 표와 일 상한을 재사용한다. 경계를 걸친 휴가·사용 이력은 구간별 사실 확인 대상으로 처리한다.
- 명시한 본인 출산휴가는 기업·피보험 자격과 전체 최초 사용 구간(90/100/120일)을 검증한다. 부분·분할·연도 경계는 전체 급여로 대체하지 않고 보류한다. 보험 상한으로 사업주 유급 의무를 줄이지 않으며 최초 60일(다태아 75일)의 통상임금과 정부지원 차액을 구분한다.
- 기존 직접 호출에서 유형 생략 시 비교 결과 호환성을 유지한다. 채팅 분석기는 유형을 명시한다.

## 2. 검증

1. 연 120만원·분기 30만원·반기 60만원은 월 10만원으로 동일. 명시 불명 주기는 계산 보류.
2. 실제 3개월 자료·제외 전 일수·법정 제외기간 전달, 임금 및 일수 동시 차감.
3. 같은 상여의 이중 입력, 별개 상여, 총액 포함 상여, 실지급액에 포함된 연 상여를 각각 확인.
4. 미확인 포함 여부·잘못된 날짜/금액·중복 제외·전부 제외·소비 모듈 보류 및 독립 보험 유지.
5. 난임·배우자 출산·배우자 유산·사산 단독 카드, 시행일·유급 한도·기사용·보험 조건, 무관한 출산 90일 카드 없음.
6. [미매핑 106행 감사](wage-calculator-input-label-audit.md), 기존 전체 회귀, CLI 116건 대조, 자연어 실답변 반복 평가 및 전체 원격 CI.

## 3. 독립 리뷰 후 결정

- 알 수 없는 수당 주기로 대안 월액 계산이 실패해도 독립 체불 이자는 유지한다.
- DB 퇴직연금 단독 호출도 퇴직금 산정 결과를 사용하며 평균임금 보류를 0원 미발생으로 바꾸지 않는다.
- 파이프라인의 월급 구성 보정 후에도 휴가 급여만 요청한 카드에 기초 월급 총액을 다시 붙이지 않는다.
- 본인 출산휴가의 새 명시 입력을 무시하던 경로를 별도 검증했다. 전체 사용·확인된 자격으로만 산정한다.
- 자연어 평가에서 같은 상여의 월 환산액을 새 수당으로 오해한 사례가 있어 항목명·원금액·주기를 계산식에 표시한다. 미래 시행 난임 유급 4일은 사용 구간·시행일·공식 출처를 같이 제공한다.
- 자동 유형 감지의 새 필드 지원은 이번 범위에 포함하지 않는다. 채팅과 명시 targets 호출은 지원하며 직접 자동 호출은 기존 계약이다.
