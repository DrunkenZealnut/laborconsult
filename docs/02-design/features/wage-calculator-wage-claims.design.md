# C5 월별·항목별 체불 원금 정산 설계

> 2026-10-24 · P1-B · C6 `080583b` 이후 · 확정 계획 C5 구현 계약

## 범위와 근거

월별 지급 의무액과 해당 항목에 충당된 기지급 원금을 대조한다. 이 결과로 C2에 원래 의무액·지급기일·실제 변제일을 전달한다. 남은 원금만 새 채권처럼 전달해 과거 이자를 없애지 않는다. 퇴직급여·연차수당은 목록에 명시한 경우에만 포함한다.

변제충당의 지정·법정 순서와 비용·이자·원본 구분은 [민법 제476~479조, 시행 2026-03-17](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032404465)을 따른다. 사실이 없는 상태에서 오래된 월부터 임의 충당하지 않는다. 최저임금 미달 계약의 효력은 [법제처 생활법령의 최저임금법 제6조 안내](https://easylaw.go.kr/CSP/CnpClsMainPreview.laf?ccfNo=1&cciNo=2&cnpClsNo=3&csmSeq=1694&popMenu=ov)를 참조한다. 법률상 지급 의무와 충당에 다툼이 없는 입력을 전제로 하며, 이율·제외·퇴직 기한은 C2를 재사용한다.

## 입력 계약

| 필드 | 의미 |
|---|---|
| `wage_claim_items` | 1~100개 월별 항목. `id, month, name, due_date, components` 및 금액/산출 출처 |
| `wage_claim_scope_complete` | 요청한 정산 범위의 항목과 지급 내역이 모두 명시되었다는 확인. 근로관계의 모든 채권을 포함한다는 뜻은 아님 |
| `wage_claim_amount_basis` | `gross`일 때만 합산. 세전 의무액과 통장 세후 입금액을 직접 차감하지 않음 |
| `wage_claim_calc_date` | 잔액 기준일. 명시하지 않으면 기존 조회 기준일 규칙 사용 |
| `wage_claim_payments` | 지급 ID·날짜·총액·항목별 원금/이자/비용 충당액과 확인 여부 |
| `wage_claim_adjustments` | 확인된 의무액 정정: ID·항목 ID·증감액·사유·확인. 임의 상계·징계 공제를 대신하지 않음 |
| `wage_claim_include_interest` | 이자도 요청한 경우 true. 단독 원금 정산은 이자를 0원으로 단정하지 않음 |

항목에는 세전 `amount` 또는 `source`를 넣는다. 실제 지급액은 항목의 `paid_amount`와 선택적 `paid_date`, 또는 전체 지급 목록으로 받는다. 같은 지급을 두 경로로 더하지 않는다. 양쪽이 있으면 항목별 합계가 일치해야 한다. 지급 금액이 없다는 명시도 0으로 보존하며 생략을 0원으로 해석하지 않는다.

지급 목록: `{id,date,amount,allocation_confirmed,allocations:[{item_id,principal_amount,interest_amount,cost_amount}]}`. 항목별 합계가 지급 총액과 같아야 한다. 귀속이 불명인 일괄 지급은 정산을 보류한다. 이자 충당액 미확인은 C2와 동일하게 이자·총 청구액만 보류한다. 지급액만 있고 날짜가 없으면 원금은 계산하되 이자 연계는 보류한다.

`components`는 실제 임금 요소의 안정된 식별자 목록이다. 예: `regular`, `weekly_holiday`, `overtime`, `night`, `holiday`, `bonus:<항목>`, `annual_leave`, `retirement`, `other:<항목>`. 월급에 고정연장수당이 포함되면 해당 요소도 월급의 목록에 넣는다. 같은 월에서 요소가 겹치는 두 행은 중복 청구 가능성 때문에 보류한다. ID만 다르게 붙인 중복 산출 출처도 거부한다. 별도 산정된 최저임금 차액과 임금 미지급액을 독립 채권처럼 무조건 더하지 않는다.

## 기존 계산기의 재사용

명시된 `amount`는 해당 월 지급 의무액으로 그대로 사용한다. 연·분기 상여도 실제 지급 대상월·금액·기일을 확인받으며 월 환산액을 자동 생성하지 않는다.

파생 출처는 `basis_confirmed=true`와 해당 정산월을 요구하며, 현재 입력의 임금·근로조건을 사용한다. 다른 월의 다른 조건은 확정된 월별 금액으로 입력하거나 별도 산정해야 한다.

| source | 입력/사용 결과 | 중복 방지 |
|---|---|---|
| `ordinary_hours` | 확정 실제 시간 `hours` × 기존 통상시급 | regular 요소 |
| `overtime`, `night`, `holiday` | 해당 월의 확정 시간으로 기존 가산수당 모듈의 1회 시간 구간 산식 사용. 월 평균 주수로 다시 곱하지 않음 | 해당 가산 요소; 휴일 8시간 초과분 별도 입력 |
| `weekly_holiday` | 확인된 동일 조건의 완전한 주 `weeks` × 기존 주휴수당. 개근 정보 필수 | weekly_holiday 요소 |
| `minimum_wage` | 기존 최저임금 검사로 계약 월액의 부족분 산출 후 계약 의무액에 한 번만 보충. 실제 지급액은 이후 한 번 차감 | regular·weekly_holiday와 겹치는 별도 행 금지 |
| `prorated` | C6 결과의 `source_item_id`와 동일한 항목 지급액 재사용 | 같은 월·출처 ID 중복 금지; C6 전체 월액은 regular·weekly_holiday 포함 |
| `monthly_estimate` | `shared.monthly_wage_total` 추정 월액 | 실제 월별 확정 채권으로 C2에 자동 전달 금지; 연·분기 수당이 있으면 실제 명세 요구 |

## 계산과 이자 연계

1. 날짜·금액·ID·범위·세전 기준·요소 중복을 검증한다.
2. 항목별 의무액과 확인된 정정을 합산한다. 음수 의무액은 보류한다.
3. 확인된 원금 지급액을 항목별로 차감한다. 미지급액은 0 이상, 초과 지급액은 별도 표시한다. 다른 항목의 체불과 자동 상계하지 않는다.
4. 기준일 이전 지급기일이 지난 미지급액과 아직 기한이 지나지 않은 금액을 구분한다. 실제 미래 지급 내역은 반영하지 않는다.
5. 이자 요청이면 원래 채권과 날짜별 원금·이자 변제를 C2에 전달한다. 확정액이 아닌 추정이나 지급 날짜가 없으면 원금 결과를 남기고 이자만 보류한다. 이미 전액 갚은 채권도 지연 지급 이자가 남을 수 있어 원래 내역을 전달한다.
6. 결과는 월별·항목별 의무액, 조정액, 기지급 원금, 미지급액, 초과 지급액, 원금 합계, 이자, 총 청구 추정액을 분리한다. 평소 월급 총액이나 요청하지 않은 연장수당을 붙이지 않는다.

## 구현·검증 순서

1. 자연어 fixture와 변경 전 각 2회 평가, 단위/배선 실패 사례 기록.
2. 순수 원금 명세·지급 배분·출처 재사용과 C2 입력 변환.
3. 모델·분석/대체 추출·라벨·카드 연결. 미지원 라벨 보호를 필요한 입력 보류로 교체.
4. 전액 지급, 복수 월, 실제 시간 수당, C6 결과, 최저임금 중복, 부분/초과 지급, 미확인 배분, 잘못된 날짜·음수·중복 ID·미래 지급 검증.
5. 확대 회귀, CLI 116사례(기존 입력 변화 없음 예상), 전체 CI·PostgreSQL, 독립 리뷰 한 번, 최종 실제 답변 각 2회, 보고서·별도 PR.

P2/P3와 운영 데이터 업데이트·main 병합·배포는 포함하지 않는다.

## 최종 리뷰에서 보강한 계약

- 퇴직 지급기한이 원래 지급일보다 먼저 오면 C2의 동일 날짜 계산을 재사용하여 체불 여부를 구분한다. 원래 지급기일과 실제 적용 기한을 함께 표시한다.
- 파생 채권은 실제 기초 임금이 있어야 한다. 시급에 월 정액 수당을 더하면 그 환산에 필요한 소정근로시간도 확인한다. 명시 금액·확정 일할 명세는 독립 계산을 유지한다.
- 주휴 대상 주의 출근 일수와 소정근로일수가 일치해야 한다. 개근·미개근이 섞인 주를 동일 조건으로 확정하지 않는다.
- 월 전체 금액에 포함된 고정연장·야간·휴일·연차 및 이름/원본 ID가 같은 고정수당·상여 요소를 자동 중복 검사한다. 임금 구성에 따라 겹칠 가능성이 있으면 분리 확인 전 보류한다.
- 최저임금 위반 여부가 같아도 수습 감액·대체 시간 기준에 따라 부족 금액이 달라지면 확정 채권으로 만들지 않는다.
- 원본 금액은 음수 검증에 보존하며, 파생 계산은 확정된 사업장 규모와 정규화된 근로시간을 사용한다.
- 공통 이자 제외 기간은 귀속을 추측하지 않는다. 각 채권의 `exclusions`로 명시하기 전 이자만 보류한다.
- `wage_claim_include_interest=false`와 별도 기존 채권 입력이 함께 있으면 독립 C2 요청으로 실행하고 합계의 범위를 밝힌다. 관계가 미확인이면 중복 가능성을 보류한다.
- 분석기·대체 추출기는 같은 주휴·임금·이자 의존 필드를 제공한다. 정산 관련 추출에는 8,192~32,768의 제한된 출력 예산을 주며, 공급자의 토큰 한도 종료는 실패로 처리하여 다음 공급자로 넘긴다. 모두 실패하면 일부 명세를 완전한 정산으로 채택하지 않는다. 아주 큰 명세는 나누어 입력해야 할 수 있다.
