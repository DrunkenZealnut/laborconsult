| D3 | `separation_grounds`는 **`unemployment`의 동반 블록**이다. `RuleFact.companion_of="unemployment"`(신설 필드)를 두고, `unemployment`가 이미 실렸으면 `MAX_BLOCKS` 칸을 쓰지 않는다. `unemployment`가 없으면 일반 블록처럼 한 칸을 쓴다. 순서는 `unemployment` 바로 다음이다 | 2번째 칸을 차지하게 두면 복합 질문에서 이미 고친 오류 클래스(해고예고 예외·괴롭힘 벌칙 조문)가 빠진다(실측 2건, 검증 H3). 맨 뒤로 보내면 이번에는 이직사유 질문의 핵심 블록이 빠진다. 동반 블록은 같은 주제의 확장이라 MAX_BLOCKS의 근거('무관 블록 잡음')에 해당하지 않는다 |
| D4 | 문장 속 **수량은 모두 앵커 구절에 있어야 하고**, 정해 둔 **결속어와 함께 나와야 한다**(U2 — 예: 3시간↔왕복, 30일↔간호). 요건이 붙은 앵커는 그 요건 문구까지 문장에 있어야 한다(U2b — 12호 "계속 다닐 수 없게 된") | 이 블록이 막으려는 것은 학습 지식에 의존한 수치다. 앵커는 원문에 그 구절이 있음만 보장하고, 문장이 그 구절과 같은 말을 하는지는 보지 않는다. 그래서 1차 문안에서 12호 조건이 잘려도 통과했다(검증 H1) |

| D6 | 2-1 "이직사유·수급자격 제한" → 고용보험법 제58조(주 조문). 시행규칙 제101조는 싣지 않는다. 예열에는 고용보험법 시행규칙을 넣는다(실측 489행). 자리는 새 묶음 `SUPPORT_WARM_LAWS`다(규칙 블록·이직확인서 조문의 법령) | 제101조 본문은 "별표 2를 말한다"뿐이다. `BASE_LAWS`는 "기본 17종"의 역사적 목록이라 의미가 흐려진다(검증 L4) |
| D7 | 별표 원문 스냅샷 `data/annex_fixtures/ei_rule_annex2_20260918.txt`·`ei_rule_annex1_2_20260918.txt`를 커밋한다. 블록의 별표 앵커를 **CI에서** 이 스냅샷으로 대조한다(U3). 로컬에서는 스냅샷과 저장본이 같은지 본다(U3b) | 법령은 비보호 저작물이다. K6만 있으면 CI가 skip해 앵커 오탈자가 로컬 관문까지 숨는다. 재수집 뒤 스냅샷이 낡는 문제는 U3b가 잡는다(검증 L3) |
| D8 | `check_law_freshness --anchors`가 **앵커를 현행판에서도 대조**한다. 별표뿐 아니라 조문도 한다. 감시 대상 법령은 `check_law`가 이미 받은 root를 재사용하고, 그 밖의 법령은 1회 조회한다. <br>• 현행판 거짓·조회 실패·별표 0개 또는 2개 이상 → **실패** <br>• 다음 판본 거짓 → 경고 <br>• 저장본과 현행 본문이 다르면 → 경고("재수집") | 개정이 시행된 뒤에는 다음 판본 대조로 보이지 않는다. 저장본만 낡은 채 K6가 통과한다. 이 근거는 조문에도 똑같이 성립한다(검증 M3). 추가 API 호출은 감시 밖 법령의 앵커만큼이다 |

## 3. 규칙 블록 `separation_grounds`

### 3.1 문안 (`lines`, 6줄 — §1.2에서 앵커와 함께 원문 확인)

1. **수급자격 제한(고용보험법 제58조)**
   - 직업안정기관의 장이 다음에 해당한다고 인정하면 수급자격이 없다.
   - 제1호(중대한 귀책사유로 해고된 경우):
     - 가목: 형법이나 직무 관련 법률을 위반해 금고 이상의 형을 선고받은 경우
     - 나목: 사업에 막대한 지장을 초래하거나 재산상 손해를 끼친 경우로서 시행규칙 별표 1의2의 기준에 해당하는 경우(예: 금품을 받고 불량품을 납품받아 생산에 차질을 가져온 경우, 기밀 유출, 공금 착복·횡령·배임)
     - 다목: 정당한 사유 없이 장기간 무단 결근한 경우
   - 제2호(자기 사정으로 이직한 경우):
     - 가목: 전직 또는 자영업을 하기 위한 이직
     - 나목: 제1호의 귀책사유가 있는 사람이 해고되지 않고 사업주의 권고로 이직한 경우
     - 다목: 시행규칙 별표 2의 정당한 사유에 해당하지 않는 이직

```python
    ("ei_rule_annex2",   "고용보험법 시행규칙", "근로자의 수급자격이 제한되지 아니하는 정당한 이직 사유", "별표2"),
    ("ei_rule_annex1_2", "고용보험법 시행규칙", "사업에 막대한 지장을 초래하거나 재산상 손해를 끼친 경우", "별표1의2"),
]
def annex_url(law, label): return "https://www.law.go.kr/" + quote(f"법령별표서식/({law},{label})")
def fetch_annex(api_key, law, title_part):           # 조회 = fetch_law_root(eflaw 현행판) 단일 출처
    root = fetch_law_root(law, api_key, timeout=TIMEOUT)
    unit = annex_unit(root, title_part)              # ValueError는 호출부가 실패로 집계한다
    if unit is None or not (unit.findtext("별표내용") or "").strip():
        return None
    return {"body": unit.findtext("별표내용"), "date": root.findtext(".//시행일자"),
            "annex_date": unit.findtext("별표시행일자")}
```

- `legal_api`는 `main()`의 `load_dotenv` **뒤에** 함수 안에서 import한다. 기존 `fetch_article_xml`과 같다(검증 L1 — 모듈 수준 import는 `LAW_API_*`가 .env를 놓친다).
- 헤더는 `{"doc_id", "source_type": "law", "title": "고용보험법 시행규칙 별표 2", "official_url": annex_url(...), "issuer": "법제처 국가법령정보센터", "date": 시행일자, "keys": []}`다. 업로더가 건너뛴다.
- `main`: 조문 → 고시 → **별표** 순서다. `--doc`은 세 목록을 모두 본다. 저장본 대조 표시는 조문과 같다.
