# monthly-base-unification — Design

> Plan: `docs/01-plan/features/monthly-base-unification.plan.md`(v0.1) · 작성 2026-10-23 · 기준 코드 main `700f857`
> 범위: Plan P0(기준 월액·평균임금 단일 출처)·P1(시급제 근로장려금·문서·fixture·테스트).
> 검증 방법: 저장소 밖 작업 트리에 시제품을 만들어 확인했다. 대상은 다음과 같다.
> - 재현 f1~f6
> - CLI 116사례(main 출력과 사례별 diff)
> - 고정수당 축 격자 300건(새로 만듦)
> - 총액 경로 12건

>
> 시제품과 스크립트는 저장소에 넣지 않는다. 숫자는 모두 그 실행에서 나왔다.
> 법률 사실은 법제처 현행판 원문으로 대조했다(§1). 행정해석은 로컬 코퍼스에서 찾지 못했다. 그래서 휴업수당 하한은 법 문언만으로 확정한다(§1 끝).

## 0. 설계 결정 요약

| # | 결정 | 이유 |
|---|---|---|
| D1 | **기준 월액의 단일 출처는 `shared.monthly_wage_total(inp, ow, *, premium=True)`다.** 기본은 통상임금 월액 + 통상임금에서 뺀 고정수당이고, 입력에 따라 다음 하나를 더한다. ① 주어진 총액(`monthly_total_pay`)이 있으면 그 값만 쓴다. ② 연장 등이 이미 든 총액이면 포괄임금 명세의 기본급 밖 몫을 더한다. ③ 그 밖에는 계산한 연장 등 중 고정연장수당을 넘는 금액을 더한다(§3) | 지금은 facade 월 총액과 `monthly_pay_estimate`(F6)가 서로 다른 정의를 쓴다. F6 소비처는 base를 저마다 고른다(Plan §3) |
| D2 | **고정연장수당은 기본(통상임금에서 뺀 고정수당)에 이미 들어 있다. 연장 등은 그것을 넘는 몫만 더한다.** 결과는 '나머지 고정수당 + max(계산한 연장 등, 고정연장수당)'과 같다 | 계산한 연장 등이 0이어도 고정연장수당은 매월 받는 임금이다(f1). 고정연장수당은 통상임금에서 뺀 고정수당의 부분집합이다. 두 판정이 같은 이름 규칙을 쓰기 때문이며, 격자 I9가 고정한다 |
| D3 | **포괄임금·구성 진술 총액은 '총액 + 총액 밖 고정수당'이다.** 연장 등은 더하지 않는다. 명세(`comprehensive_breakdown`)가 있으면 통상임금 자리에 기본급만 있으므로, 총액에서 기본급을 뺀 몫을 되돌린다 | 지금 facade는 명세가 있는 포괄임금의 월 총액을 기본급으로 낸다(CLI #3·#67: 300만 원 → 200만 원). 시제품의 첫 판은 총액만 써서 총액 밖 식대가 빠졌다. 그래서 총액 경로 12건 중 10건에서 갈렸고, 고친 뒤 0건이다(§2.3) |
| D4 | **평균임금 일액의 단일 출처는 기존 `average_wage.calc_average_wage`다.** Plan이 이름 붙인 새 함수 `average_daily_wage`는 만들지 않는다. 퇴직금은 이미 이 함수를 쓰고, 실업급여·휴업수당·산재가 새로 쓴다(§4) | 산정기간 일수(이직일 기준 역산)·시행령 제2조 제외기간·상여·연차수당 3/12·제2조 제2항 하한을 이미 모두 갖춘 구현이다. 새 함수를 두면 같은 산식이 두 벌이 된다 |
| D5 | **제2조 제2항 하한은 `calc_average_wage` 안에 그대로 둔다.** 통상임금이 총액에서 나온 경로(`ordinary_wage_from_total`)에 하한 예외를 더하지 않는다 | 시제품에서 그 예외를 더해 봤다. 그러자 포괄임금 명세 없음·연장시간 없음 입력의 퇴직금·평균임금이 바뀌었다(115,068 → 97,826원/일). 이 입력은 고정수당·상여·연장·휴업 어느 축에도 없어 Plan 범위 밖이다. 예외 없이도 실패 테스트는 늘지 않았다. 실업급여만 그 예외를 갖는 현재 비대칭은 후속으로 둔다(§12-1) |
| D6 | **facade 월 총액 = `monthly_wage_total(premium=연장수당 섹션을 계산했는가)` + 탄력적 근로시간제 연장 임금이다. 공휴일 수당 ÷ 12는 더하지 않는다** | 매번 premium을 넣으면 보상휴가 사례(CLI #24)의 월 총액이 3,000,000 → 4,812,500원으로 바뀐다. 연장 대가를 돈으로 받지 않는 질문인데도 그렇다. #106·#107도 연장수당을 묻지 않았는데 오른다. 파이프라인은 F6가 연장분을 더하는 입력이면 연장수당 섹션을 함께 계산한다(calc-card-consistency G2). 그래서 파이프라인 경로에서는 월 총액 = 세전이 성립한다. 공휴일 ÷ 12는 둘 다 월 임금이 아니다. 월급제는 공휴일 임금이 월급에 이미 들어 있고, 시급제는 질문의 공휴일 일수를 12로 나눈 값일 뿐이다(#10). 대안 비교는 §5.2 |
| D7 | **옛 경로를 지운다.** 지울 것은 `monthly_pay_estimate`·`premium_monthly_with_fixed`·`premium_monthly_note`, `shutdown_allowance._calc_avg_daily_wage`, 산재의 '월 금액 ÷ 30'이다. `adds_premium_pay`는 남긴다. 파이프라인 G2가 쓰고, 이제 `monthly_wage_total`도 그것을 부른다 | 남겨 두면 다음 소비처가 다시 직접 계산한다. `monthly_wage_total`이 `adds_premium_pay`를 부르면 calc-card-consistency Check G-6의 '같은 함수' 문제가 구조로 해소된다. G-6은 F6가 같은 판정을 따로 하던 문제다 |
| D8 | **R3: '통상임금에서 뺀 고정수당'의 범위는 그대로다.** `not_ordinary_fixed_total`은 연장·야간·휴일·연차수당 이름 판정분만이다. 성과조건 수당과 최소보장 성과급의 보장분 밖은 기준 월액에 넣지 않는다 | 평균임금에는 실제로 지급된 임금이 모두 들어간다. 그러나 변동 금액은 추정할 수 없다. 그런 임금이 있으면 사용자가 `monthly_total_pay`·`last_3m_wages`로 준다(기존 경로). 이 범위를 넓히면 성과가 없던 달까지 더하게 된다 |
| D9 | **표기는 더한 항목만 적는다.** 더한 것이 없으면 지금처럼 '통상임금', 보류 경로는 지금처럼 '월급 총액', 포괄임금은 '포괄임금 총액'이다(`monthly_wage_note`) → **Do에서 바꿈(§14 C2):** 총액 경로도 계산기는 '통상임금'이라 적고 '월급 총액' 이름은 파이프라인이 총액일 때만 붙인다 | 시제품 첫 판은 보험 계산식을 '통상임금 월 X원'으로 바꿔 CLI 20여 사례의 글자가 바뀌었다. 지금 표기를 지키면 그런 변화는 0건이다. 고정연장수당을 넘는 몫은 '중 고정연장수당을 넘는 금액 월 N원(계산한 금액 − 고정연장수당)'으로 적는다. 첫 판은 고정수당 20만 원과 연장 391,071원을 나란히 적었다. 그러면 합이 실제보다 20만 원 크게 읽힌다 |
| D10 | **실업급여 평균임금의 분모를 92일 고정에서 3개월 총일수로 바꾼다.** `calc_average_wage`의 산정기간을 쓴다. 우선순위는 `last_3m_days` → 이직일 기준 역산 → 92일이다. 기초일액 하한(고용보험법 제45조 제2항, 일용근로자 예외)과 다중 사업장 분기(같은 조 제1항 단서)는 실업급여에 그대로 둔다 | 제45조 제1항의 기초일액은 근로기준법 제2조 제1항 제6호의 평균임금이고, 그 정의는 '그 기간의 총일수'로 나눈다. 지금은 같은 카드의 퇴직금과 실업급여가 서로 다른 분모를 쓴다. 이직일 2026-03-01이면 81,615원과 83,429원으로 갈린다(격자 I4 144건). CLI는 이직일이 없는 사례뿐이라 숫자가 바뀌지 않는다 |
| D11 | **Plan 완료 조건 2를 고친다. 의도된 변경 축에 '포괄임금 명세 총액'·'공휴일 수당 월 환산'을 더한다** | Plan은 바뀌는 입력을 고정수당·상여·연장·휴업으로만 봤다. CLI diff에서 #3·#67·#69(포괄임금 명세)와 #10(공휴일)이 더 나왔다. 둘 다 facade 월 총액이 틀렸던 것이다(§6.1) |
| D12 | **PR 1개, 커밋 2개.** A = 계산기 코드와 기존 테스트 기대값 갱신. B = 새 테스트 파일·fixture·CI 등록·CLAUDE.md | 지난 사이클과 같은 단위다. A만으로 CI가 통과해야 한다 |

## 1. 근거 (법제처 현행판 대조, 2026-10-23)

| 사실 | 원문 | 쓰는 곳 |
|---|---|---|
| 평균임금 = 산정 사유 발생일 이전 3개월 동안 지급된 임금 총액 ÷ **그 기간의 총일수** | 근로기준법 제2조 제1항 제6호 | D4·D10. 산재의 ÷ 30과 실업급여의 92일 고정을 없앤다 |
| 그렇게 산출한 금액이 통상임금보다 적으면 **그 통상임금액을 평균임금으로 한다** | 근로기준법 제2조 제2항 | D4·D5. 평균임금을 쓰는 모든 곳에 적용된다. 휴업수당도 그 하나다(f5) |
| 사용자 귀책 휴업이면 **평균임금의 100분의 70 이상**을 지급한다. 단, 그 금액이 통상임금을 넘으면 통상임금을 지급할 수 있다 | 근로기준법 제46조 제1항 | 휴업수당 계산기가 평균임금 위에 그대로 얹는다(변경 없음) |
| 평균임금 산정기간 중 제외 기간(휴업 기간 등)과 그 임금은 뺀다 | 근로기준법 시행령 제2조 제1항 | `calc_average_wage` 기존 구현. 휴업수당·산재·실업급여가 새로 받는다 |
| 재해보상의 평균임금 산정 사유 발생일 = **사고가 발생한 날** 또는 질병 발생이 확정된 날 | 근로기준법 시행령 제52조 | 산재는 `accident_date`가 있으면 그날을 산정 기준일로 한다(§4) |
| 산재보험의 '평균임금'은 근로기준법에 따른 평균임금이다 | 산업재해보상보험법 제5조 제2호 | 산재가 `calc_average_wage`를 쓰는 근거. 특례 평균임금은 범위 밖(Plan §5) |
| 기초일액 = 이직 당시 근로기준법 제2조 제1항 제6호의 평균임금. 그 금액이 통상임금보다 적으면 통상임금(일용근로자 제외) | 고용보험법 제45조 제1항·제2항 | D10. 6호 금액(하한 전)을 받아 제45조 제2항을 실업급여가 적용한다 |

- 휴업수당의 산정 기준일은 휴업 시작일(`shutdown_start_date`)로 둔다. 이것은 모델 필드의 기존 규약('휴업 시작일 (평균임금 산정 기준)')이다. 이 사이클에서 새로 정한 법률 사실이 아니다.
- 행정해석: 로컬 BM25 코퍼스에서 '휴업수당 + 제2조 제2항(통상임금보다 적으면)'이 함께 나오는 행정해석·판례·훈령을 찾았다. 0건이었다(일시 상승 임금의 평균임금 산정 1건만 인접). 제2조 제2항은 '평균임금'의 정의 조항이다. 그래서 평균임금을 기초로 하는 제46조에도 그대로 적용된다고 보고, 문언만으로 확정한다.

### 2.3 총액 경로 (12건)

입력 공간은 '포괄임금 명세 없음 / 명세 있음 / 구성 진술 월급' × '수당 없음 / 식대 20만' × '연장 0·10시간'이다. 기대값은 총액 + 총액 밖 수당이다(300만 또는 320만). 이 값과 월 총액·세전·평균임금 3개월 ÷ 3·근로장려금 ÷ 12를 대조했다.

|---|---|---|---|
| 기대값과 다른 행 | 10/12 | 4/12(식대 누락) | **0/12** |

main은 이런 값을 냈다.
- 명세 있는 포괄임금의 월 총액·세전이 기본급(220만)이다.
- 포괄임금 명세 없음 + 연장 10시간을 facade에 직접 넣으면 월 총액에 연장분이 더해진다(3,937,500). 파이프라인은 이 경로에서 연장수당을 금액 보류하므로 화면에는 나오지 않던 값이다.

## 4. 평균임금 일액 — `calc_average_wage` 하나

| 소비처 | 호출 | 위에 얹는 것 |
|---|---|---|
| 퇴직금 | `calc_average_wage(inp, ow)`(기존) | 1년 평균 비교(기존) |
| 실업급여 | `calc_average_wage(inp, ow).avg_daily_3m`(**하한 전** 6호 금액) | 제45조 제2항 하한(일용근로자 예외, `ordinary_wage_from_total`이면 비교 안 함 — 기존) → 상·하한액(제46조). 다중 사업장 분기(제45조 제1항 단서)는 지금대로 따로 계산한다 |
| 휴업수당 | `calc_average_wage(replace(inp, end_date=inp.shutdown_start_date or inp.end_date), ow).avg_daily_wage` | 70%, 단서(통상임금 상한), 부분 휴업 비율(기존) |
| 산재 | `calc_average_wage(replace(inp, end_date=inp.accident_date or inp.end_date), ow).avg_daily_wage` | 급여 종류별 계산(기존). 최저보상기준(기존) |

- **실업급여는 하한 전 값을 받는다.** `avg_daily_wage`(제2조 제2항 하한 후)를 받으면 제45조 제2항 문구가 사라진다. 일용근로자 예외(제45조 제2항 단서)도 무력해진다.
- **계산식 표기는 지금 모양을 지킨다.** 바뀌는 것은 숫자의 출처뿐이다.
  - 실업급여: `평균임금 일액(추정): (월 X원 × 3[ + 상여금 B원 + 연차수당 L원]) ÷ N일 = Y원`. N은 `period_days`, X는 `monthly_wage_total`이다. 제외 기간이 있으면 'X원 × 3' 자리에 '3개월 임금총액 W원(제외 임금 차감 후)'을 쓴다. 그래야 줄 안의 산식이 맞는다. 실지급(`last_3m_wages`) 경로는 지금 모양 그대로다.
  - 휴업수당: `1일 평균임금: Y원`. 하한이 걸리면 `(3개월 평균임금 A원 < 1일 통상임금 B원 → 통상임금, 근로기준법 제2조 제2항)`을 붙이고, 법적 근거에 제2조 제2항을 더한다.
  - 산재: `평균임금: Y원/일 (3개월 기준)`. 하한이 걸리면 휴업수당과 같은 꼴이다. `accident_date`를 썼으면 법적 근거에 시행령 제52조를 더한다.
- **경고.** 추정 경고('평균임금은 이직 전 3개월 실지급 임금으로 산정합니다…', '통상임금 월액으로 추정했습니다…')는 지금 조건 그대로 유지한다. 시제품 실험판은 이 경고를 빠뜨렸다. CLI diff로 보면 이것만 사라져 있었다.

### 14.5 후속(이번에 반영하지 않음)

0. **의도분석의 연 단위 수당 추출(Live calc-18 r1).** `fixed_allowances` 항목에 지급 주기(연·분기)가 없어 연 상여가 월 수당으로 들어간다(4회 중 2회). 기준 월액 단일화로 그 오류가 평균임금 계열까지 번진다. 스키마에 주기 필드(→ `annual`)를 두거나, 질문의 '연·연간·매년 + 금액' 표지로 고정수당을 연 단위로 바로잡는 결정적 보정이 필요하다. 아래 1·2와 같은 사이클에서 다루는 것이 맞다 — 연 상여를 연 단위 고정수당으로 받으면 기준 월액(1/12)으로 보험·DC·근로장려금에도 들어간다.
1. **채팅 경로가 연 상여·미사용 연차수당을 넘기지 않는다.** 의도분석 항목에 없어 `annual_bonus_total`·`unused_annual_leave_pay`가 늘 0이다. 상여 3/12 가산(f6)은 계산기를 직접 부를 때만 닿는다. `last_3m_*`·`excluded_periods`도 같다.
2. **DC형 연간임금·근로장려금 소득에 연 상여가 없다**(이 사이클 전부터). 근로자퇴직급여보장법 제20조의 '연간 임금총액'·총급여에는 상여가 들어간다 — 원문 대조 후 고친다(리뷰 L7).
3. **일할계산(`prorated`)은 아직 `monthly_total_pay or monthly_wage`를 직접 읽는다.** 월급 일할이라 기준 월액과 뜻이 달라 이번에 두지 않았다. CLAUDE.md에 예외로 적었다.
4. 노무제공자 평균임금 표기 '(통상임금 × 3 추정)'(리뷰 L9), `docs/calculator-audit/09-shutdown-allowance.audit.md`의 `_calc_avg_daily_wage` 언급.
