# calculator-statute-audit — 계산기 모듈 × 신규 적재 법령·재결례 대조 감사 Plan

> 입력: Pinecone `laborlaw-v2`에 2026-10-09 이후 적재된 공공 원문 — 공식 자료팩 54문서(법령 전문 33종·판례 8·행정규칙 13, `qpack_20261009_`), 공식 고시·조문 14문서(`official_`), 재결례 1,052건(`ruling_`, 11-08). 대조 대상은 `wage_calculator/`의 조문 인용 134건·수치 상수·근거 문구.
> 작성: 2026-11-12 · 단계: Plan · 기준: main `74400ff`(wage-update-followups PR #137~#140 머지 직후)
> 대조 방법: 자료팩 원본(`laborconsult_eval/source-integration-20261009/cleaned/`, 저장소 밖)을 법령명·조문 키로 색인해 계산기 코드의 인용과 대조했고, 자료팩에 없는 조문은 법제처 현행판(`target=eflaw`)으로 다시 확인했다(등록 IP). 고시 금액은 법제처 행정규칙 상세로 받았다. 재결례는 쟁점 분포(분류·본문 키워드)만 봤다 — 개별 사건 판단이라 산식 근거로 쓰지 않는다.

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 계산기가 인용하는 조문 134건은 현행 법령에 전부 존재하지만, 산식·문구 세 곳이 법령과 다르다. 조기재취업수당을 '절반×50% = 최대'로 적는다(법령: 미지급일수의 1/2, 절반 남긴 경우가 하한). 실업급여 기준기간에 법에 없는 '일용직 1년'을 적는다(18개월). 산재 휴업급여는 3일 이내 불지급 단서가 없다. 그리고 재결례 934건에서 반복해 다투어진 산재 규칙 다섯이 계산기에 없다 — 최고·최저 보상기준(제36조⑦), 61세 이후 휴업급여 감액(제55조), 일용근로자 통상근로계수(시행령 제24조), 직업병 평균임금 특례(제36조⑥), 일용근로자 수급요건(고용보험법 제40조①5호). 2026년 고시 세 건(최고·최저 보상기준 268,299/82,560원, 장례비 19,279,760/13,943,000원, 통상근로계수 73/100)과 11-01 신설 고시(조기재취업 지급제외 임금 월 300만원)는 코드에 반영되지 않았거나 수치만 있고 출처 등록이 없다. |
| **Solution** | 법 영역별 PR 2개. PR-1 실업급여(조기재취업수당 산식·요건·고시, 기준기간 문구, 일용근로자 요건 안내, 공개 흐름도 공식 교정) + 이 문서. PR-2 산재(3일 단서, 최고·최저 보상기준 표와 적용, 61세 감액표, 통상근로계수, 직업병 특례 안내, 공개 흐름도). 새 근거 문구는 전부 `legal_anchors.py` 앵커와 `fetch_official_rules` 등록을 함께 넣어 원문 대조 테스트와 `check_law_freshness --anchors`가 순회한다. |
| **Function UX Effect** | 조기재취업수당 카드가 '최대'가 아니라 '절반 남긴 시점 기준 하한'을 보이고 요건·제외 사유를 함께 안내한다. 61세 이상·일용근로자·고소득자의 산재 급여가 법정 한도·계수로 계산된다. 3일 이내 요양은 산재 휴업급여 0원과 사업주 보상(근로기준법 제78·79조)을 안내한다. |
| **Core Value** | 새로 적재한 공공 원문을 검색 코퍼스로만 쓰지 않고 계산기의 산식·수치·문구를 대조하는 데 썼다. 자료팩 자체의 공백(산식 이미지로 보류된 조문 7건·스냅숏 이후 신설 조문 19건)도 이 대조에서 드러나 후속 과제로 남긴다. |

**목표 지표**
- §2의 발견 사례가 기대 동작으로 바뀌고, 각 사례가 main `74400ff`에서 실패하고 수정 후 통과하는 오프라인 테스트로 고정된다.
- 새 근거 문구마다 `CALC_BASIS_ANCHORS` 앵커가 있고, 로컬 원문(`output_공식법령/`)·현행판(`check_law_freshness --anchors`) 대조를 통과한다.
- 대상이 아닌 입력의 수치는 바뀌지 않는다(골든·배선·CLI 116사례 중 바뀐 것은 전부 이번 발견의 입력이어야 하고 목록을 Design에 남긴다).

## 2. 현재 동작 (재현 2026-11-12, main `74400ff`)

### 2.1 조문 인용 — 134건 전부 현행 법령에 존재

`wage_calculator/**/*.py`의 조문 인용 134건(법령 17종)을 자료팩 조문 키로 대조했다. 130건은 자료팩에 있고 제목이 인용 맥락과 맞는다. 자료팩에 없던 4건은 법제처 현행판으로 다시 확인했다 — 전부 **존재한다**.

| 인용 | 자료팩 | 법제처 현행판 | 판정 |
|---|---|---|---|
| 고용보험법 시행령 제104조의2 (`reduced_work_benefit.py`) | 없음 | 있음 — 육아기 근로시간 단축 급여(② 산식, 상한 250만/160만·하한 50만) | 인용 정당. 자료팩이 산식 이미지 때문에 보류한 조문 |
| 고용보험법 시행령 제104조의15 (`unemployment.py`) | 없음 | 있음 — 노무제공자 구직급여 수급요건(① 소득 100분의 30 이상 감소) | 인용 정당. 같은 사유로 보류 |
| 국민연금법 시행령 제5조 (주석 2곳) | 자료팩에 법령 없음 | `output_공식법령/np_enf_5.md`로 이미 수집됨 | 정당 |
| 최저임금법 시행규칙 제2조 (주석) | 자료팩에 법령 없음 | 미수집 — 주석 전용이라 이번 범위 밖 | 정당(원문 미대조) |

## 3. 원인

- 계산기의 산식·근거 문구가 처음 만들어질 때 법령 **조문 전문**이 코퍼스에 없었다(판례·행정해석·상담글 위주). 조기재취업수당은 상담글 어휘("절반 남기면 50%")를 그대로 산식으로 옮겼고, 일용직 '1년'은 출처가 없다.
- 산재 계산기는 법 제52·54·57·62·66·71조만 보고 만들어져 제36조(산정 기준 총칙)와 제55조·시행령 제23~25조를 거치지 않았다. 재결례는 바로 그 조문들을 다룬다.
- 고시 금액은 값만 상수에 적고 출처(`fetch_official_rules.ADMRULS`)·앵커를 두지 않아 현행성 점검이 돌지 않았다.

## 4. 해결 방향

### 4.1 PR-1 — 실업급여(U1~U3) + 문서
- U1: 산식 문구를 "구직급여일액 × 미지급일수 × 1/2"로, 카드 값은 "절반 남긴 시점 기준(하한)"으로 라벨을 바꾼다. 요건·제외·청구 시기·2년 제한을 경고로 싣고 `legal_basis`에 시행령 제84·85조를 더한다. 고시 임금 상한은 재취업일이 2026-11-01 이후일 때의 조건으로 안내한다(`reference_date`가 그 이전이면 "고시 시행 전"으로 적지 않는다 — 효력 기간을 가진 표로 둔다, 난임 상한표와 같은 구조).
- U2: 기준기간 문구를 "18개월(초단시간근로자 24개월)"로 고친다.
- U3: `is_daily_worker`면 제40조①5호·제49조① 단서를 경고로 싣는다(판정은 하지 않는다 — 근로일수 자료가 입력에 없다).
- 공개 흐름도 두 사본의 공식·예시 교정, `sw.js` VERSION 상향.
- 등록: `ARTICLES` + ei_enf_85·ei_enf_86(제40·64조·시행령 제84조는 이미 등록), `ADMRULS` + ei_early_reemp_wage(law.go.kr 전용), `CALC_BASIS_ANCHORS` 추가.

### 4.2 PR-2 — 산재(I1~I5)
- I1: 요양 1~3일은 휴업급여 0원 + 근로기준법 제78·79조 안내.
- I2: `COMPENSATION_LIMITS_DAILY = {2026: (최고 268_299, 최저 82_560)}` 단일 표(기존 `MIN_COMPENSATION_DAILY`는 이 표의 최저 열로 파생). 평균임금 결정 직후 급여별로 적용 — 장해·유족: 최고·최저, 휴업·상병보상연금: 최고만, 장례비: 미적용. 최저 < 최저임금×8이면 최저임금×8. 최고 값이 없는 연도(2024·2025)는 최고 미적용 + 경고.
- I3: `age ≥ 61`이면 별표 1 계수를 경로별(제52조 / 제54조 본문·② / 제54조 단서)로 곱한다. 나이는 입력의 만 나이로 보고 "해당 연령에 도달하는 날부터 바뀐다"를 경고로 적는다. 단서(61세 이후 취업 중 재해 등)는 입력이 없어 안내만.
- I4: `is_daily_worker and daily_wage`면 평균임금 = 일당 × 0.73(고시)로 바꾸고 산식·제외 사유(제23조①1호 단서)·적용 제외 신청(제24조②)을 안내한다. `daily_wage`가 없으면 안내만.
- I5: `injury_type`이 질병·뇌심혈관이거나 진폐 언급이면 특례 안내(계산은 일반 평균임금 유지, "공단이 특례 적용 시 달라진다").
- 공개 흐름도(두 사본)에 3일 단서·최고·최저 보상기준 한 줄.
- 등록: `ARTICLES` + iaci_act_36·iaci_act_52·iaci_act_54·iaci_act_55·iaci_enf_23·iaci_enf_24·iaci_enf_25·lsa_act_79, `ANNEXES` + iaci_annex1(고령자 휴업급여 지급기준), `ADMRULS` + 보상기준·장례비·통상근로계수 3건(law.go.kr 전용), 앵커.

## 5. 범위 밖

- **자료팩 보정**(2.4) — 보류 조문 7건을 산식 텍스트로 옮겨 적재하고 스냅숏 이후 신설 조문을 더하는 일은 `laborconsult_eval/source-integration-20261009`의 외부 파이프라인과 배치 원장(`data/vector_ledgers/qpack_20261009.json`) 갱신이 필요하다. 별도 사이클(source-pack-refresh)로 둔다.
- 채팅 의도분석에 `age`·산재 입력(`sick_leave_days`·`disability_grade`·`num_survivors`)을 추출하는 배선 — `analyzer._INFO_KEYS`에 없어 I2~I5는 CLI·API와 질문 본문에서 읽는 일용(`_states_daily_worker`) 경로에만 닿는다. 분석기 배선은 별도 판단(의도분석 스키마 변경은 분류를 흔든다).
- 조기재취업수당의 재취업일 입력(실제 미지급일수) — 새 입력 필드 추가는 분석기 배선과 같은 이유로 보류. 카드는 하한 금액 + 산식으로 답한다.
- 2024·2025 최고 보상기준 금액의 수집 — 법제처 검색이 현행 고시만 돌려주면 그 연도는 최고 미적용 경고로 둔다.
- 재결례를 산식 근거로 쓰는 일, 재결례 전용 규칙 블록, 상한 경과조치(시행령 부칙 제35934호 제4조 — 이직일이 2025년이면 종전 상한 66,000원)의 이직일 기준 전환(현재 `reference_year` 기준, 안내 한 줄만 더한다).
