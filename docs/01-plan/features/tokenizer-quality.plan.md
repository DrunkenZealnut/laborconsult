| **Core Value** | **하이브리드 검색의 절반이 조용히 반쪽으로 동작하고 있었다는 사실 자체를 걷어낸다.** 실패가 예외도 로그도 남기지 않는 종류(문서는 "Mecab 우선"이라 적혀 있고 코드는 폴백만 돈다)라, 고치는 것과 같은 비중으로 **다시 조용해지지 않게 오프라인 회귀로 고정**하는 것이 이 사이클의 목적이다. |

## 1. 현황 분석

### 1.1 발단 — 프로덕션 토크나이저는 Mecab이 아니다

`app/core/bm25_search.py`의 문서화와 `CLAUDE.md`는 일관되게 "Mecab 우선, 미설치 시 정규식 폴백"이라고 서술한다.

- `bm25_search.py:6` — `Mecab 형태소 분석기 설치 시 정확한 토큰화 사용`
- `bm25_search.py:127` — `한국어 토크나이저 — Mecab 우선, 미설치 시 정규식 폴백`
- `CLAUDE.md` — `BM25 uses rank_bm25 with Mecab tokenizer (fallback: regex)`

**그러나 `konlpy`는 `requirements.txt`에 없다.** Vercel `@vercel/python` 빌드는 이 파일만 설치하므로 `_get_mecab()`의 `from konlpy.tag import Mecab`은 프로덕션에서 **항상** `ImportError`로 떨어진다. 로컬에도 없다(실측: `konlpy`/`mecab`/`MeCab`/`kiwipiepy`/`soynlp` 전부 미설치).

> 설령 `konlpy`를 추가해도 소용없다 — konlpy의 `Mecab`은 시스템에 `mecab-ko` 바이너리와 `mecab-ko-dic` 사전이 설치돼 있어야 하는데, `@vercel/python`에는 그 설치 단계가 없다.

즉 **정규식 폴백이 프로덕션의 유일한 토크나이저**이고, 지금까지 한 번도 그렇지 않았던 적이 없다. `_get_mecab()`은 사실상 죽은 코드이며, 문서의 "Mecab 우선"은 **이 결함을 3중으로 은폐해 온 서술**이다. 아무도 폴백의 품질을 검증할 이유를 갖지 못했다.

### 1.2 대상 결함 6종

| ID | 결함 | 영향 | 우선순위 |
|----|------|------|:--------:|
| D1 | 말끝 조사 **과다절단** — 실단어의 끝글자를 삼킴 | 도메인 핵심어 22종 분열, 최대 51% | **High** |
| D2 | 구두점 앞 조사 **미절단** — 룩어헤드가 `(?=\s\|$)` 뿐 | 같은 단어가 3가지로 토큰화 | **High** |
| D3 | 조사 목록 **누락** — `에`·`으로`·`에게` 등 부재 | 질의 토큰 상시 오염 | **High** |
| D4 | 어미 **미정규화** — 활용형이 전부 별개 토큰 | 동사·형용사 매칭 사실상 불능 | Medium |

| D6 | 연결어가 색인에 잔류 (`것으로` 12,376회 등) | IDF 공간 낭비 | Low |

### 1.3 D1 — 말끝 조사 과다절단 (실측)

현행 구현(`bm25_search.py:146-150`):

```python
text = re.sub(r"(?:에서|부터|까지|에게)(?=\s|$)", "", text)
text = re.sub(r"[은는이가을를의로도만와과](?=\s|$)", "", text)
tokens = re.sub(r"[^\w\s]", " ", text).split()
return [t for t in tokens if len(t) >= 2]
```

두 번째 `re.sub`은 **어절 끝 한 글자가 조사 후보 12자 중 하나면 무조건 떼어낸다.** 그 글자가 단어의 일부인지 조사인지 구분하지 않는다. 노동법 어휘는 `가`(휴가)·`로`(근로)·`도`(연도)·`의`(합의)로 끝나는 복합명사가 밀집해 있어 피해가 집중된다.

24건 중 3건에서 **주제어가 잘렸다.** 질의가 `연차휴`가 되면 BM25는 `연차휴가`로 색인된 7,942회를 **한 건도 후보에 넣지 못한다.**

> **주의 — 이 결함은 "자기일관적이라 상쇄된다"가 아니다.** 코퍼스와 질의가 같은 함수를 쓰므로 `연차휴`끼리는 매칭된다. 문제는 **같은 단어가 두 토큰으로 나뉘어 어느 쪽도 전체를 보지 못한다**는 점이다. 분열률 43%는 "43%가 틀렸다"가 아니라 **"어느 쪽으로 질의해도 43% 또는 57%를 잃는다"** 는 뜻이다.

### 1.4 D2 — 구두점 앞 조사는 절단되지 않는다 (실측)

두 `re.sub`의 룩어헤드가 `(?=\s|$)` 뿐이라, 조사 뒤에 구두점이 오면 매칭이 실패한다. 구두점은 그 **다음 줄**에서야 공백으로 치환되므로 조사가 그대로 살아남는다.

```
'근로자와, 사용자'   -> ['근로자와', '사용자']     ← 조사 '와' 잔류
'퇴직금을. 지급'     -> ['퇴직금을', '지급']       ← 조사 '을' 잔류
'임금의·수당'        -> ['임금의', '수당']         ← 조사 '의' 잔류
'연차휴가(유급)'     -> ['연차휴가', '유급']       ← 우연히 올바름
```

이 결함이 D1과 결합해 **같은 단어의 3가지 토큰화**를 만든다:

| 원문 문맥 | 토큰 | 판정 |
|-----------|------|------|
| `연차휴가 사용` (뒤에 공백) | `연차휴` | ❌ 과다절단 |
| `연차휴가를 사용` (뒤에 조사) | `연차휴가` | ✅ |
| `연차휴가(유급)` (뒤에 구두점) | `연차휴가` | ✅ 우연 |

`근로자와`(271회)가 어휘에 남아 있는 것이 D2의 지문이다 — `근로자`는 53,116회이므로 `와`는 99% 정상 절단되고, 남은 271회는 전부 **구두점 앞** 사례다.

### 1.5 D3 — 조사 목록 누락 (실측)

2글자 조사는 `에서|부터|까지|에게` 4종, 1글자는 `은는이가을를의로도만와과` 12자뿐이다. **`에`가 어디에도 없다.**

```
"임금체불로 노동청에 진정을 넣으려고 합니다"
   -> ['임금체불', '노동청에', '진정', '넣으려고', '합니다']
```

`노동청에`와 `노동청`이 서로 다른 토큰이 된다. 평가셋에서도 `중간에`·`시각에`·`공휴일에`·`일주일에`가 그대로 잡혔다. `으로`도 없어 `괴롭힘으로` → `로`만 떨어져 **`괴롭힘으`** 라는 존재하지 않는 토큰이 만들어진다.

### 1.6 D4 — 어미 미정규화

동사·형용사가 활용형 그대로 색인된다. 코퍼스의 `지급하여야`·`지급한다`·`지급해야`가 전부 별개 토큰이고, 질의의 `되나요`·`있나요`·`하나요`·`계산하나요`·`무엇인가요`도 마찬가지다. Mecab 경로가 `VV`/`VA` 어간을 뽑도록 설계된 것은 정확히 이 문제 때문인데, 그 경로가 죽어 있어 대응이 전무하다.

### 1.7 D5 — 상용구 노이즈 (실측)

코퍼스 최빈 토큰 25종에 nodong.kr 상담 답변의 **정형 인사말·서명**이 대거 포함된다:

```
경우(56k), 근로자(53k), 한국노총(32k), 사용자(29k), 안녕하세요(23k),
있습니다(23k), 회사(20k), 따라(20k), 바랍니다(20k), 저희(20k), 임금(20k),
대한(19k), 위해(18k), 퇴직금(18k), 근로기준법(16k), 노동자(16k),
노동OK(16k), 경우에(16k), 해당(16k), 하루되시기(16k), 관심(16k),
노력하고(16k), 부천상담소입니다(16k), 권익향상(16k), 성원(16k)
```

`부천상담소입니다`·`하루되시기`·`권익향상`·`성원`·`노력하고`·`관심`이 나란히 16k회인 것은 이들이 **한 덩어리의 정형 문구**("…권익향상을 위해 노력하고 있습니다. 성원과 관심 부탁드리며 좋은 하루되시기 바랍니다")로 거의 모든 상담 문서 끝에 붙기 때문이다.

상용구·범용어 16종 + 연결어 15종 합계 **313,562회 = 총토큰의 5.7%**.

**이것이 왜 문제인가** — 고빈도라 IDF가 낮아 오매칭을 직접 유발하지는 않는다. 실제 피해는 **BM25 길이 정규화**다. 상담 문서만 일률적으로 토큰이 부풀어 `doc_len`이 커지고, 상용구가 없는 해설서·판례 청크 대비 상대적으로 점수가 깎인다. 이는 `legal-corpus-coverage` 사이클이 공공저작물 쿼터로 교정하려던 편향과 **같은 방향**이며, 쿼터는 그 편향을 사후에 되밀 뿐 원인을 건드리지 않는다.

### 1.8 D6 — 연결어 잔류

D1의 분열 목록에는 도메인 실단어가 아닌 것도 섞여 있고, 이들은 **보호가 아니라 제거 대상**이다.

| 토큰 | 빈도 | 처리 |
|------|---:|------|
| 것으로 / 것이므 | 12,376 / 1,485 | 불용어 |
| 경우에는 / 경우에 | 16,180 / 16,000+ | 불용어 |
| 하지만 | 5,976 | 불용어 |
| 실제로 | 4,787 | 불용어 |
| 하더라도 | 3,746 | 불용어 |
| 원칙적으로 | 3,153 | 불용어 |
| 있으므로 / 없으므로 / 하므로 / 아니므로 | 2,221 / 999 / 957 / 548 | 불용어 |

> **설계상 가장 중요한 구분**: D1이 찾아낸 45종 분열쌍은 **정반대의 처방이 필요한 두 부류**로 나뉜다. 22종은 끝글자를 **지켜야** 할 도메인 실단어(`연차휴가`)이고, 나머지는 통째로 **버려야** 할 연결어(`하더라도`)다. 45종을 일괄 "보호"하면 색인에 연결어 노이즈를 주입하게 된다. 두 목록은 **반드시 분리해서** 관리해야 한다.

### 1.9 현행 파이프라인 상의 위치

```
build_bm25_corpus.py  →  data/bm25_corpus.jsonl.gz   (raw text 저장, 토큰 없음)
                                    ↓  콜드 스타트
                    _load_streaming()  →  _tokenize_ko(doc["text"])   ← 코퍼스 측
                                    ↓
                              BM25Okapi(tokenized)
                                    ↓  요청 시
                    search_bm25(query) →  _tokenize_ko(query)          ← 질의 측
```

**토큰화는 빌드타임이 아니라 로드타임에 일어난다.** 따라서:

- ✅ **코퍼스 재빌드가 필요 없다.** `_tokenize_ko`만 고치면 다음 콜드 스타트부터 새 토큰화가 적용된다. `data/bm25_corpus.jsonl.gz` 재생성·재커밋 불요.
- ✅ 코퍼스 측과 질의 측이 **같은 함수 하나**를 쓰므로 구조적으로 어긋날 수 없다. 이 단일 출처는 반드시 유지한다.
- ⚠️ 대신 **콜드 스타트 비용이 토크나이저 복잡도에 직결**된다. 76,983문서를 매 콜드 스타트마다 토큰화한다.

## 4. 접근 방식

### 4.1 배제된 대안 — 형태소 분석기 런타임 탑재 (실측 근거)

가장 자연스러운 해법은 제대로 된 형태소 분석기다. **실측으로 배제했다.**

| 후보 | 판정 | 근거 |
|------|------|------|
| konlpy + Mecab | ❌ 불가 | `mecab-ko` 시스템 바이너리 + `mecab-ko-dic` 필요. `@vercel/python`에 설치 단계 없음 |
| kiwipiepy | ❌ 불가 | 휠은 존재(`cp39-abi3-manylinux2014_x86_64`, pip 설치 가능)하나 **크기가 한도를 넘는다** |

kiwipiepy 실측 (2026-08-27, PyPI):

| 구성요소 | 압축 | 압축 해제 |
|----------|---:|---:|
| `kiwipiepy-0.23.2` (`_kiwipiepy.abi3.so` 41.3MB 포함) | 11.5MB | **41.6MB** |
| `kiwipiepy_model-0.23.0` (`cong.mdl` 75.7MB 등) | 88.0MB | **109.0MB** |
| 합계 | 99.5MB | **150.6MB** |

Vercel `@vercel/python` 서버리스 함수의 압축 해제 상한은 **250MB**이고, 현재 배포본은 이미 `pinecone`·`anthropic`·`openai`·`cohere`·`supabase`·`google-generativeai`·`fastapi`·`lxml`·`networkx`·`numpy`(rank_bm25 의존)·`bcrypt`·`nh3`·`pypdf`에 더해 코퍼스 gz 19.8MB를 싣고 있다. 여기에 150.6MB를 추가할 여유는 없다.

**빌드타임 토큰화로 우회할 수 없다.** 코퍼스를 로컬에서 kiwi로 토큰화해 파일에 담아도, **질의**는 런타임에 토큰화해야 한다. 질의만 정규식으로 처리하면 코퍼스와 토크나이저가 어긋나 지금보다 나빠진다(FR-6 위반).

> 기록용 — 이 배제는 "형태소 분석이 불필요하다"가 아니라 **"현재 배포 형태에서 불가능하다"** 이다. 배포 형태가 바뀌면(예: 별도 토큰화 서비스, Vercel 함수 크기 상향) 재검토 대상이며, D4·복합명사 분해는 그때까지 미해결로 남는다.

### 4.2 채택 — 정규식 토크나이저 정조준 수정

`_tokenize_ko()` 내부와 소형 사전 상수만 손댄다. 처리 순서가 결과를 좌우하므로 고정한다:

```
① 정규화        전각·가운뎃점 변형 통일
② 어절 분할     구두점을 경계로 (D2 해소 — 조사 절단 '전'에 분할해야 한다)
③ 보호어 조회   도메인 사전에 있으면 ④를 건너뛴다 (D1 해소)
④ 조사 절단     확장된 조사 목록, 어절 끝 기준 (D3 해소)
⑤ 어미 정규화   활용형 → 어간 (D4 완화)
⑥ 불용어 제외   상용구·연결어 (D5·D6 해소)
⑦ 길이 필터     len >= 2
```

**②를 ④보다 먼저 두는 것이 D2 해소의 핵심**이다. 현행은 구두점 치환이 조사 절단 뒤에 오기 때문에 룩어헤드가 구두점을 볼 수 없다. 순서를 뒤집으면 모든 조사가 어절 끝에 오게 되어 룩어헤드 자체가 단순해진다.

**③이 ④보다 먼저**여야 `연차휴가`가 지켜진다. 순서가 바뀌면 보호어 사전은 아무 일도 하지 않는다.

### 4.3 두 사전의 분리 (FR-7)

| 상수 | 내용 | 초기 규모 |
|------|------|---:|
| `PROTECTED_TERMS` | 말끝 조사 절단을 금지할 도메인 실단어 | 22종 + 부서명 6종 (실측 기반) |
| `STOPWORDS` | 색인에서 제외할 상용구·연결어·질의 어미 | 30여종 (실측 기반) |

두 목록 모두 **코퍼스 실측에서 도출**하며 추측으로 채우지 않는다. 보호어를 과하게 넣으면 조사가 붙은 어절이 통째로 색인되고, 불용어를 과하게 넣으면 실단어가 사라진다 — 양쪽 다 조용한 실패이므로 §6의 회귀가 경계를 고정한다.

### 4.4 문서 정정

`bm25_search.py` docstring·`_tokenize_ko` docstring·`CLAUDE.md`의 "Mecab 우선" 서술을 정정한다. `_get_mecab()`은 **제거하지 않고** 유지하되(로컬에 Mecab이 있는 개발자에게는 실제로 동작한다), **프로덕션 경로는 정규식임을 명시**한다.

> ⚠️ Mecab 경로를 남긴다면 **두 경로가 다른 토큰을 낸다**는 사실이 새 위험이 된다. 로컬에서 Mecab으로 측정한 수치를 프로덕션 근거로 쓰면 안 된다. 이 함정을 docstring에 못 박는다.

## 6. 검증 계획

### 6.1 신설 — `eval_tokenizer.py` (오프라인, API 키 불요)

토크나이저는 **외부 API 없이 전량 측정이 가능한 몇 안 되는 영역**이다. 이 사이클의 핵심 산출물 중 하나다.

| 측정 | 지표 | 목표 |
|------|------|------|
| M1 분열쌍 자동 탐지 | 실단어/절단형 동시 존재 종수 | 22종 → **0종** |
| M2 주제어 보존율 | 평가셋 24건 중 주제어 절단 건수 | 3건 → **0건** |
| M3 상용구 제거율 | 불용어 토큰 출현 비율 | 5.7% → **1% 미만** |
| M4 BM25 recall@k | 고정 질의의 정답 문서 회수율 | 전후 비교, **회귀 없음** |
| M5 토큰화 시간 | 76,983문서 전량 | NFR-1 (+50% 이내) |
| M6 어휘 규모 | 고유 토큰 수 | 326,235 → 감소 기대 |

M1은 **하드코딩 목록 대조가 아니라 탐지 알고리즘**으로 만든다. 목록 대조는 이번에 고친 22종만 지키고 새로 생기는 분열을 놓친다(R-3).

### 6.2 회귀 — `test_offline_units.py` 추가

기존 스위트(23개 테스트, 964줄)에 토크나이저 계약을 추가한다:

| 케이스 | 고정 대상 |
|--------|-----------|
| T-a | `연차휴가`가 문맥 3종(공백/조사/구두점)에서 **동일 토큰** |
| T-b | `근로자와,` → `근로자` (D2) |
| T-c | `노동청에` → `노동청` (D3) |
| T-d | `PROTECTED_TERMS`와 `STOPWORDS`가 **분리된 상수**이고 교집합이 공집합 (FR-7) |
| T-e | 코퍼스 측·질의 측이 동일 함수 참조 (FR-6, 구조적 보장) |
| T-f | 불용어 제거가 `search_bm25` 반환 `content`를 바꾸지 않음 (FR-4) |

`.github/workflows/tests.yml`에 편입한다. CI에는 konlpy가 없으므로 **자동으로 프로덕션 경로를 측정**한다(R-7의 반사이익).

전체 파이프라인 도달률에 회귀가 없는지 확인한다(API 키 필요, 수동). **`--freeze`는 절대 실행하지 않는다** — 고정 분해 쿼리가 갈리면 기존 기준선과 비교 불가능해진다.
