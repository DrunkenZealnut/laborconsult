# claim-authority-and-assessor-facts — 피보험자격 확인청구 기관 + 괴롭힘 판정기 사실 전제 Plan

> 입력: 3차 재평가(2026-10-05, 지식iN 20문항, 코드 `c69012d`)에서 남은 확정 오류 4문항(7·9·11·15)과, 그 원인을 좁히는 실측
> 선행: effective-law-and-graph-precedents(PR #98)·아카이브 PR #99 · 작성 2026-10-05 · 단계: Plan

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 3차 재평가에서 확정 오류가 남은 4문항 중 3개(7·9·15)가 두 결함에서 나왔다. ① 피보험자격 확인청구를 **고용센터**로 안내했다(15번은 "최대 3년 소급"까지 단정). 처리기관은 근로복지공단이다. 규칙 블록은 질문 키워드로만 붙어 20문항 중 1개에만 들어갔고, 모델이 스스로 확인청구를 꺼낸 문항은 막지 못했다. ② 괴롭힘 판정기가 **질문에 없는 사실**을 채워 판정을 단정했다. 실측 5개 질문 모두에서 문제가 나왔다: 사실이 없는 개념 질문에도 판정, 기간을 지어냄, 쟁점이 다른 질문에 괴롭힘 판정, 같은 질문인데 실행마다 다른 판정. |
| **Solution** | ① 20문항 중 14개에 붙는 실업급여 블록에 역할을 가르는 문장을 넣는다. 이직사유 소명과 수급자격 판단은 고용센터, 피보험자격 확인청구는 근로복지공단이고 언제든지 할 수 있다. 공식 원문 앵커를 단다. 블록이 붙지 않는 경로는 두 답변 분기 공통 규칙으로 막는다. ② 판정기 입력을 **질문 원문 근거로 검증하는 결정적 필터**를 둔다. 구체 행위가 없으면 판정 대신 "판단 보류"와 필요한 사실을 낸다. 개념 설명·불리한 처우·성희롱 질문에는 괴롭힘 판정을 붙이지 않는다. |
| **Function UX Effect** | 실업급여·퇴직금 답변이 확인청구 창구와 시점을 맞게 안내한다. 괴롭힘 판정 결과는 사용자가 말한 사실에만 근거하고, 정보가 부족하면 단정하는 대신 무엇을 알려 주면 판단할 수 있는지 보여 준다. |
| **Core Value** | 판정 결과와 규칙 블록은 LLM이 그대로 옮겨 쓰는 **시스템이 만든 사실**이다. 이 사이클은 그 사실이 **질문**과 **공식 원문** 양쪽에 근거할 때만 컨텍스트에 들어가게 한다. effective-law 사이클의 "손으로 쓴 사실은 원문 대조가 붙을 때만" 원칙을 도구 인자까지 넓히는 것이다. |

**목표 지표**: 지식iN 20문항 Live에서 확인청구 기관 오류·누락 0(7·15·18번), 괴롭힘 5개 질문 × 3회에서 근거 없는 판정 입력 0건, 3차 대비 다른 문항 비회귀.

## 1. 실측 (2026-10-05)

### 1.1 확인청구 안내와 규칙 블록 (지식iN 20문항, 3차 답변)

| 문항 | 붙은 블록 | 답변 내용 | 판정 |
|---|---|---|---|
| 3 | unemployment · **insured_status** | 근로복지공단 · "언제든지" | 정확 |
| 7 | unemployment | 회사가 거부하면 "관할 고용센터에 … 확인·정정을 요청" | 확정 오류 잔존 |
| 15 | **없음** (퇴직금 질문) | "고용센터에 피보험자격 확인청구를 하면 최대 3년까지 소급 가입" | 확정 오류 잔존 |
| 18 | unemployment | 피보험자격 이력은 언급하지만 확인청구 안내 없음 | 불완전 |
| 11·13·17 | unemployment | 피보험자격을 언급, 확인청구는 언급하지 않음 | — |

- `insured_status`는 질문에 "피보험자격"이 있거나, 보험 문맥과 미가입·미신고·3.3% 같은 일반어가 함께 있을 때만 붙는다(`rule_facts.py:146`). 20문항 중 3번에만 붙었다. 오류는 모두 **블록 없이 모델이 스스로 꺼낸** 경우다.
- `unemployment` 블록은 20문항 중 14개에 붙는다. 7·18번이 그 안에 있고, 15번은 밖이다(블록 0개).
- 15번의 "3년"은 확인청구 기한이 아니다. 고용보험법 **제50조⑤**에 따르면, 취득신고가 안 됐던 피보험자의 피보험기간은 확인된 날부터 소급하여 3년이 되는 날이 속하는 보험연도 첫날부터 계산한다(보험료 납부가 증명되면 그 기간). 확인청구 자체는 **제17조①**에 따라 "언제든지" 할 수 있다. 확인 권한은 **시행령 제145조②**에 따라 근로복지공단에 위탁돼 있다. 수급자격 인정은 **제43조②**에 따라 직업안정기관(고용센터)이 결정한다. 이상 2026-10-05 eflaw 현행판 대조.
- 2차 리포트도 같은 구분을 요구했다: "단순 상담·문의가 가능한 것과 정식 접수기관을 틀리게 지정한 것은 구분해 평가했다."

### 1.2 괴롭힘 판정기 도구 인자 (5개 질문 × 2회, `_extract_params` → `_run_assessor`)

| 질문 | 질문에 있는 사실 | 추출·판정 | 문제 |
|---|---|---|---|
| risk-03 | 없음("세 가지 요소를 설명해 주세요") | 인자 0개인데 판정 실행 → "해당 가능성: 낮음" (2/2) | 판정할 사안이 없는데 판정을 낸다 |
| risk-04 | 상사·매일·공개 모욕·업무 배제 | 행위 유형은 맞음. **기간 "6개월"/"1개월"** 을 채움 | 질문에 없는 기간을 지어낸다(점수 가중치에 쓰임) |
| risk-05 | 신고 후 불리한 부서 전보 예고 | 전보를 괴롭힘으로 판정. 1회 "보통", 2회 "낮음" | 쟁점(불리한 처우 금지, 제76조의3⑥)이 다르고 실행마다 판정이 다르다 |
| risk-06 | 상사의 반복적 성적 발언 | 괴롭힘 "높음"(행위 유형을 폭언·모욕으로 분류) | 성희롱은 남녀고용평등법 소관이다. 판정 틀이 다르다 |
| kin-09 | "괴롭힘도 당하고 있다" + 팀장이 사직서 사유 지시 | 팀장을 가해자로, 사유 지시를 행위로 추론. 회사 대응 "미조치"를 채움 → "높음" (2/2) | 행위가 특정되지 않았는데 단정한다 |

- 판정 결과는 답변 컨텍스트에 그대로 들어가고, LLM은 그것을 **표로 옮겨** 사용자에게 보여 준다(3차 9번 답변).
- 답변 규칙에는 이미 "성립 요건 중 하나라도 사실관계가 불분명하면 '가능성이 높다'고 단정하지 말라"(`ANSWER_ACCURACY_RULES`)가 있다. 그래도 판정기가 낸 "높음"이 이겼다. **프롬프트로는 막히지 않는다. 판정기가 애초에 그 결론을 만들지 않아야 한다.**
- 원인:
  - 도구 스키마(`pipeline.py::HARASSMENT_TOOL`)의 필드 설명에 "질문에 없는 값은 비워 두라"가 없다.
  - `tool_choice="any"`가 도구 사용을 강제하므로, 키워드(`_HARASS_KEYWORDS`: 괴롭힘·모욕·성희롱·직장 내 …)만 맞으면 개념 질문도 이 경로로 들어온다.

## 2. 범위

### P0-1 — 피보험자격 확인청구 기관·시점

**P0-1a. 실업급여 블록에 역할 구분 문장**(14/20 문항 경로)
- 문장: 이직사유가 사실과 다르면 수급자격을 신청할 때 고용센터에 증거로 소명한다(수급자격 인정 — 제43조②). 피보험자격 취득·상실 신고 자체가 사실과 다르면 근로복지공단에 확인청구하고, 이는 언제든지 할 수 있다(제17조①, 시행령 제145조②).
- 앵커는 `ei_act_43`·`ei_act_17`·`ei_enf_145`다. 모두 이미 `output_공식법령/`에 있다. K6이 대조한다.
- 블록 길이 증가분을 `MAX_BLOCKS=3` 합계(최대 약 1,800자)와 함께 잰다.

**P0-1b. 블록 밖 경로 — 두 분기 공통 규칙**
- 15번처럼 블록이 하나도 붙지 않는 질문에서 모델이 확인청구를 꺼내는 경우를 막는다.
- `ANSWER_ACCURACY_RULES`에 조건부 한 줄을 넣는다: 확인청구를 언급하면 근로복지공단·언제든지로 쓰고, 소급 범위를 단정하지 않는다.
- 이 문장도 법률 사실이므로 앵커 대조 대상에 넣는다. 지금 답변 규칙에는 앵커 검사가 없으니 설계에서 정한다.
- 대안: 답변 후 점검(확인청구 + 고용센터 + 근로복지공단 부재 감지). 비용·UX를 설계에서 비교한다.

**P0-1c. 제50조⑤ 원문 수집**
- `fetch_official_rules.py`에 `ei_act_50`을 추가한다.
- 목적: "3년"을 다루는 문장을 쓸 때의 앵커, 그리고 15번 유형 평가 매처(`forbidden_claims`)의 근거.

### P0-2 — 괴롭힘 판정기 사실 전제

**P0-2a. 판정 실행 조건**
- 사용자가 **자기 사안의 구체 행위**를 서술했을 때만 판정한다.
- 개념 설명(risk-03), 불리한 처우 단독(risk-05), 성희롱(risk-06)에는 괴롭힘 판정을 붙이지 않는다.
  - 불리한 처우는 기존 `harassment_retaliation` 블록이 맡는다.
  - 성희롱은 남녀고용평등법 경로로 안내한다.
- 판정 여부를 LLM 플래그 하나에만 맡기지 않는다. 결정적 조건과 함께 쓴다(예: 행위 서술이 질문 원문에 근거가 있는지).

**P0-2b. 추출값 근거 검증(결정적 필터, LLM 무관)**
- 판정 입력에 넣기 전에 각 값의 근거를 **질문 원문**에서 확인한다.
  - 행위 유형: `BEHAVIOR_TYPE_KEYWORDS`가 질문에서 찾는 유형만 남긴다.
  - 기간·빈도·회사 대응·목격자·증거: 질문에 해당 표현이 있을 때만 남긴다.
  - 가해자 역할: 질문이 그 사람을 **행위자로** 지목할 때만 남긴다(kin-09의 "사유를 쓰라고 한 팀장"은 행위자 지목이 아니다).
- 근거 없는 값은 버리고 `metadata`에 기록한다(관측).

**P0-2c. 판정 출력**
- 핵심 요소(행위·우위)가 미확인이면 종합을 "높음/보통/낮음"이 아니라 **"판단 보류 — 행위 정보 부족"** 으로 낸다. 판단에 필요한 사실 목록을 함께 낸다.
- 지금은 ②가 "불분명"이어도 종합이 "높음"으로 나온다(3차 9번).

**P0-2d. 도구 스키마 설명 보강(소프트)**
- 필드 설명에 "질문에 명시되지 않은 값은 비워 두세요"를 넣는다.
- 소프트 가드이므로 P0-2b가 실제 방어다.

## 3. 범위 밖

- 온라인 수급자격 교육 14일(20번): 법령에는 없고 고용노동부 운영 안내에 있다. 운영 안내를 앵커로 받을지는 별도로 판단한다(규칙 블록 앵커는 지금 법령 원문만 받는다).
- 확정 가능한 사실까지 "고용센터에서 확인"으로 미루는 유보 과다(3차 관찰): `ANSWER_ACCURACY_RULES`의 유효기간·처리기한 확인 문장과 관련이 의심되지만 인과는 미확인이다. 따로 측정한다.
- 일용근로자 판단(11번), 무관 판례 2018두63235(3번, 크롤 판례 RAG 경로).
- 성희롱 전용 판정 로직 신설: 이번에는 괴롭힘 판정에서 **빼는 것**까지만 한다.

## 4. 위험

| 위험 | 대응 |
|---|---|
| 근거 검증이 정당한 추론까지 걸러 판정이 과소해짐 | risk-04처럼 사실이 명시된 사례에서 판정이 유지되는지 회귀. 키워드 사전(`BEHAVIOR_TYPE_KEYWORDS`)의 동의어 범위를 실측으로 넓힌다 |
| "판단 보류" 증가로 답변이 빈약해짐 | 보류할 때도 성립 요건 세 가지와 필요한 사실 목록을 낸다. 판정기 밖의 RAG·법령 경로는 그대로다 |
| 실업급여 블록이 길어져 컨텍스트 증가 | 블록 문자 수를 측정하고 기존 줄과 중복되는 표현을 정리한다 |
| 답변 규칙(P0-1b)은 소프트 가드라 무시될 수 있음 | Live로 확인한다. 효과가 없으면 답변 후 점검(설계 대안)으로 올린다 |
| 판정기 출력 형식 변경이 기존 테스트·소비자에 영향 | `format_assessment` 소비처(파이프라인 meta·컨텍스트)와 E18·괴롭힘 테스트를 함께 갱신한다 |
| 실행마다 추출이 달라짐(risk-05 보통/낮음) | 결정적 필터 뒤의 입력으로 판정하므로 변동 폭이 줄어드는지 3회 반복으로 잰다 |

## 5. 완료 조건

1. 지식iN 20문항 Live에서:
   - 7·15·18번의 확인청구 안내가 맞다. 언급하면 근로복지공단·언제든지, 소급 범위는 단정하지 않는다.
   - 나머지 문항의 자동 통과 수가 3차보다 줄지 않는다.
2. 괴롭힘 5개 질문(risk-03·04·05·06, kin-09) × 3회에서:
   - 질문에 없는 값(기간·회사 대응·행위 유형·가해자)이 판정 입력에 들어간 경우가 0건이다.
   - risk-03·05·06에는 괴롭힘 판정이 붙지 않는다.
   - kin-09는 "판단 보류"로 나온다.
   - risk-04는 판정을 유지한다.
3. 오프라인 테스트(CI 등록, API 키 불요):
   - 근거 검증 필터. 기록한 추출값 fixture로 검사한다.
   - 판정 실행 조건.
   - 블록 앵커(K6·E11). `ei_act_50`도 포함한다.
4. 새로 넣는 법률 문장은 모두 공식 원문 저장본으로 대조한다. 원문을 받기 전에 문구를 확정하지 않는다.
