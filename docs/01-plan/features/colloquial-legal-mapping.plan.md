## Executive Summary

| 항목 | 내용 |
|------|------|
| Feature | 구어체 상담 표현("잘렸다"·"퉁치자")의 법률 개념 매핑 — 현황 실측과 취약 경로 보강 |
| 시작일 | 2026-08-20 |
| 예상 기간 | 1~2일 |
| 선행 | textbook-retrieval-balance(2026-08-19 아카이브, 다양성 승격 패턴), llm-fallback-hardening(교차벤더 폴백) |
| 발단 | "한국어 맥락 파악이 제대로 구현되어 있는지 리뷰하고 개선" 요청 → 구어 질의 8건 실측 |

### Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 구어→법률용어 변환은 의도분석 LLM 한 곳에 **전적으로** 의존한다. 변환 자체는 실측 8/8 정확("퉁치자"→임금 상계 금지까지 잡는다)하지만, 의도분석이 실패하면(12s 타임아웃·Claude/OpenAI 동시 장애·레거시 폴백) 구어 원문이 그대로 검색돼 **판례·행정해석·해설서 도달이 0/8**이 된다. 정상 경로에서도 구어 단문은 법률참조 0·길이 짧음으로 SIMPLE(top_n=3)에 떨어져 Q&A가 상위를 독식하고 판례 연계가 4/8에 그친다. |
| **Solution** | ① 의도분석 실패 폴백에만 발동하는 **정적 구어→법률용어 사전**(고신뢰 ~30항목)으로 폴백 검색 쿼리에 법률용어를 병기하고, ② 다양성 승격(`_ensure_textbook_presence`)과 같은 **교체 패턴**으로 "rerank 결과에 판례·행정해석 0건 && pool에 존재 → 최하위 중복-출처와 교체"를 추가한다(총량 불변이라 저작권 상한 무접촉). ③ 의도분석 프롬프트의 변환 예시를 해고 편중에서 괴롭힘·산재·4대보험 계열로 넓히고 구어 질의 고정 세트로 회귀를 고정한다. |
| **Function UX Effect** | "사장이 나가라는데요"처럼 법률용어 없는 질문에도 답변 근거에 판례·행정해석이 실리고, LLM 장애 중에도 구어 질문의 검색이 법률 자료에 도달한다. |
| **Core Value** | 한국어 맥락 이해가 **LLM 가용성에 좌우되지 않는 다층 구조**가 된다 — 1차 LLM 변환(현행 유지), 2차 정적 사전(신규), 3차 승격(출처 다양성 보장). |

## 1. 현황 분석 (2026-08-20 실측)

### 1.1 구어 변환은 이미 구현돼 있고, 잘 작동한다

변환 지점은 의도분석 프롬프트 두 곳이다:

- `app/templates/prompts.py:188` — precedent_keywords 추출 지시: *"사용자의 일상어가 아닌 법률 용어를 사용하세요. 예: '사장이 갑자기 나가라고 함' → ['부당해고', '해고예고수당', '해고 제한']"*
- `app/templates/prompts.py:287-288` — *"사용자의 일상어를 법률 용어로 변환하세요: '짤리다/나가라고 함/해고당했다' → '부당해고'"*

구어 질의 8건 실측(`analyze_intent`, 2026-08-20) — **8/8 정확 변환, 스코프 게이트 오차단 0**:

| 질의 | 추출된 법률용어 |
|------|----------------|
| "저 어제 잘렸어요" | 부당해고, 해고예고수당, 해고 정당성 |
| "사장이 내일부터 나오지 말래요" | 부당해고, 해고사유 서면통지, 구두해고 |
| "월급 대신 가불이랑 퉁치자고 하는데" | **임금 전액 지급 원칙, 가불금 상계, 임금 상계 금지** |
| "회사 물건 파손했다고 월급에서 까겠대요" | 임금 전액 지급 원칙, 손해배상액 공제, 근로기준법 제43조 |
| "삼일 일하고 짤렸는데 돈을 안 줘요" | 임금체불, 부당해고, 해고예고수당 |
| "수습 끝나니까 그냥 나가라네요" | 수습 해고, 본채용 거부, 부당해고 |
| "사직서 쓰라고 계속 눈치 줘요" | 사직 강요, 권고사직, 의원면직 |
| "야근 수당을 밥값으로 때운대요" | 연장근로수당, 수당 대체지급 |

### 1.2 변환이 검색에 반영되는 경로 (단일 의존)

`pipeline.py:1588-1614`: `precedent_keywords` → `build_precedent_queries()`(rule 쿼리) + LLM 분해(MODERATE↑) → `_merge_search_queries(decomposed, rule, fallback=question_summary or query[:80])`. **원문 질의는 변환 쿼리가 하나라도 있으면 검색 쿼리에 들어가지 않는다** — 설계 자체가 "LLM이 번역한 쿼리로 검색"이다. rerank(Cohere)만 원문 기준이라 구어-문서 의미 매칭을 보조한다.

### 1.3 취약점 실측

검색 A/B (법률용어 코퍼스 = 판례·행정해석·훈령예규·해설서 도달, rerank top_n 내):

| 경로 | 법률 코퍼스 도달 | 평균 법률소스 건수 |
|------|:---:|:---:|
| **원문-only** (의도분석 실패 폴백 재현) | **0/8 = 0%** | 0.0 |
| 변환 병합 (프로덕션 정상 경로) | 4/8 = 50% | 0.8 |

- **V1 (High) — 의도분석 실패 시 RAG 자체가 스킵된다.** 의도분석은 Claude→OpenAI 교차벤더 폴백까지 있지만, 그마저 실패하면(`pipeline.py:1485`) 판례·행정해석 검색 블록이 `if analysis:`(`pipeline.py:1566`) 조건으로 **통째로 건너뛰어져 답변이 검색 근거 0으로 생성된다** — 법률 상담에서 할루시네이션 위험이 가장 높은 상태. 설령 이 블록을 폴백에서도 돌리더라도 쿼리가 구어 원문뿐이면 법률 코퍼스 도달 0/8(실측)이다: BM25는 어휘 불일치("잘렸다" 토큰은 판례의 "해고"와 매칭 불가), Dense도 법률 문서와의 유사도가 낮아 Q&A만 잡힌다. 따라서 G1은 "폴백 RAG 활성화 + 구어 사전 병기" 두 단계다.
- **V2 (Medium) — SIMPLE 분류의 구어 편향.** `classify_complexity`(query_decomposer.py:74)의 재료는 길이·법률참조 수·접속사 수다. 구어 단문은 세 값이 체계적으로 낮아 SIMPLE(top_n=3)로 떨어지고, 상위 3을 Q&A가 독식해 변환 키워드로 pool에 들어온 판례가 rerank 절단으로 사장된다. 실측: 정상 경로 미도달 4건(c1·c5·c6·c8) 전부 SIMPLE. 해설서 다양성 승격에서 실측한 것과 동일한 실패 모드(코퍼스에 있는 근거가 절단으로 사장)의 **판례 버전**이다.
- **V3 (Low) — 변환 예시의 계열 편중.** 프롬프트 예시가 해고 계열 2곳뿐이다. 임금 계열은 실측에서 잘 변환됐으나 괴롭힘("갈군다")·산재("공상 처리하재요")·4대보험("보험 안 들어줬대요") 계열은 예시도 회귀 고정도 없다 — 품질이 모델 세대에 따라 흔들려도 감지 수단이 없다.

### 1.4 문제가 아닌 것 (반증 기록)

- **Q&A 코퍼스 도달은 원문-only에서도 정상** — 4.9만 건 Q&A가 구어 원문을 담고 있어 구어-구어 매칭이 된다. 문제는 "판례·법령과의 연계"(요청의 핵심)다.
- **스코프 게이트 오차단 없음** — 8/8 `is_labor_related=True`. 구어라서 노동법 무관으로 차단되는 일은 없다.
- **후속 질문 문맥** — `analyze_intent(question, history, config, summary)`가 대화 이력을 받으므로 "그럼 퉁치면 안 되나요?" 류 후속 질문도 문맥 위에서 분석된다.

## 2. 목표 / 비목표

### 목표

1. **G1 (P0)**: 의도분석 실패 폴백에서도 구어 질의가 법률 코퍼스에 도달한다 — 정적 사전으로 폴백 쿼리에 법률용어 병기. 실측 0/8 → **≥ 4/8**.
2. **G2 (P1)**: 정상 경로에서 pool에 들어온 판례·행정해석이 rerank 절단으로 사장되지 않는다 — 법률근거 승격(교체). 실측 4/8 → **≥ 6/8**.
3. **G3 (P2)**: 변환 품질을 회귀로 고정한다 — 구어 질의 고정 세트(계열별 12~16건) + 프롬프트 예시 계열 확장.

### 비목표 (명시적 제외)

- **BM25 동의어/형태소 확장** — 인덱스 재설계 급 비용인데 Dense+LLM 변환이 이미 커버. YAGNI.
- **`classify_complexity` 구어 가중치** — 의도분석 성공 시 keywords가 커버하고 실패 시 G1이 커버한다. 분류기 수정은 전 질의에 영향을 줘 오탐 반경이 크다.
- **SIMPLE `top_k`/`rerank_top_n` 상향** — 외부 전송량(Cohere·Self-RAG)과 해설서 노출이 늘어 **저작권 재검토가 필요한 기존 잔여사항**(textbook-retrieval-balance 아카이브)이다. 이 사이클에 섞지 않는다. G2의 교체 방식은 총량 불변이라 이 제약을 우회하는 것이 아니라 **건드리지 않는 것**이다.

## 3. 개선 설계 방향

### 3.1 G1 — 폴백 RAG 활성화 + 구어 사전 (P0)

- **G1a**: RAG 블록의 `if analysis:` 가드를 풀어 의도분석 실패 시에도 검색이 돌게 한다(추가 비용 = 검색 1회, 가드 fail-open 방침과 같은 방향). **G1b**: 그때의 검색 쿼리에 정적 사전 매핑을 병기한다.
- 위치: 의도분석 실패 시의 fallback 쿼리 생성부(`pipeline.py` 레거시 경로). 정상 경로에서는 **발동하지 않는다** — LLM 변환이 더 정확하고, 이중 발동은 쿼리 슬롯만 낭비.
- 형태: `{구어 패턴 → 법률용어[]}` 정적 dict, 고신뢰 항목만(잘리/짤리/나가라(고)/퉁치/월급.*까/떼먹/밥값.*때우/공상 등 ~30항목). 오매핑은 오답의 근거가 되므로 **애매한 항목은 넣지 않는다**(해설서 헤딩 위생의 "오폐기 < 오복원" 원칙과 동일 방향 — 미변환은 Q&A 도달로 남지만 오변환은 무관한 판례를 근거로 만든다).
- 산출: 원문 + 매핑된 법률용어 쿼리를 병기(원문을 대체하지 않는다 — Dense의 구어 매칭은 유지).

### 3.2 G2 — 법률근거 승격 (P1)

- `rag.py::_ensure_textbook_presence`와 동일 패턴·동일 지점(rerank 내부): "top_n 안에 판례·행정해석이 0건 && 전체 랭킹 `2×top_n` 이내에 존재 → 최하위 **중복-출처** 1건과 교체".
- 지킬 것(해설서 승격에서 검증된 불변식 재사용): 교체이지 추가가 아니다(총량 불변) / 단일 출처는 victim이 되지 않는다 / 판정은 점수가 아니라 랭크 창 / 킬스위치 env.
- **승격 대상에 해설서(textbook)를 넣지 않는다** — 해설서 노출 증가는 저작권 재검토 대상. 판례·행정해석·훈령예규만.
- 기존 해설서 승격과의 상호작용: 둘 다 발동 시 교체 2건까지 가능 — victim 선정이 서로의 승격분을 잡아먹지 않도록 순서·제외 규칙을 Design에서 확정한다.

### 3.3 G3 — 회귀 고정 (P2)

- 실측 스크립트를 `data/eval_colloquial_queries.json` 고정 세트로 승격(계열: 해고·임금·괴롭힘·산재·4대보험·비정규직). `eval_retrieval.py`처럼 수동 실행 항목.
- 프롬프트 예시를 계열별 1건씩 추가(현행 해고 2건 → 5~6계열). 프롬프트 변경이므로 `test_abuse_guard.py` 스코프 게이트 회귀(오차단 0) 동반 확인.
