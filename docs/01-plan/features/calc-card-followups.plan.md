# calc-card-followups — 계산 카드가 소정근로시간·적용 요건을 가정하는 문제 Plan

> 입력: PR #114 본문의 '후속(이 PR 밖)' 4건. 그 PR의 독립 리뷰(code-analyzer)가 지적한 L2(1일 8시간 초과)와 '기존 문구 오류' 2건(퇴직금 '× 8h', 수습 '최저임금 9,288원'), 그리고 특고 카드를 확인하다 관찰한 1건이다. 이 Plan을 쓰며 같은 클래스를 다시 훑어 2건을 더 찾았다(F5 실업급여 하한, F4b 계산하지 않은 최저임금의 '판정 보류' 표시).
> 작성: 2026-10-15 · 단계: Plan · 기준: main `e76ab02`(PR #114 머지)
> 재현 방법: `pipeline._run_calculator(params, query)`에 의도분석 결과 형태의 params를 직접 넣어 카드를 뽑았다(LLM 호출 없음). Design에서 이 사례들을 테스트로 옮긴다.

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 계산 카드는 "이 수치를 사용하세요"로 LLM에 들어가 그대로 답변 금액이 된다. 현 main에서 14건이 재현됐다. 하루 8시간을 넘는 시간을 전부 소정근로로 세어 연장 가산이 빠지고(시급 12,000원·주 5일 × 10시간: 월 260,714원), 주휴가 부푼다(주 4일 × 10시간: 8시간, 판결 기준 6.4시간). 단시간근로자의 실업급여 하한은 8시간으로 고정돼 2배로 나온다(주 5일 × 4시간: 총 9,907,200원, 법정 4,953,600원). 수습 5개월째인데도 90% 기준으로 '충족'을 내고, 특고에게는 '최저임금 미달·노동청 신고'를 안내한다. |
| **Solution** | 원인은 두 가지다. 첫째, "1일 소정근로시간"을 다섯 곳이 각자 정한다(입력값 그대로, 8시간 고정, 상수 8). 둘째, 적용 요건(수습 감액 요건·근로자성)을 모르면 충족을 가정한다. 처방도 둘이다. 소정·연장 분리 함수 하나를 만들어 모든 소비처가 쓰게 한다(근로기준법 제2조①8호·제50조, 대법원 2022다291153 [2]①). 요건이 확인되지 않아 판정이 갈리면 PR #114의 '판정 갈림 보류'를 다시 쓴다. |
| **Function UX Effect** | 카드가 소정근로와 연장근로를 나눠 보여 주고, 상시 5명 이상이 확인되면 연장 가산을 계산한다. 탄력적 근로시간제나 감시단속 승인처럼 분리 전제가 달라지는 신호가 있으면, 금액 대신 조건을 밝힌다. 수습·특고 카드는 판정의 전제(감액 요건·근로자성)를 먼저 밝히고, 전제가 확인될 때만 판정한다. |
| **Core Value** | PR #114의 '가정한 숫자보다 보류' 원칙을 두 축으로 넓힌다. 하나는 **시간 축**이다(질문한 시간 중 법적 소정근로시간은 어디까지인가). 다른 하나는 **적용 대상 축**이다(감액 요건과 근로자성이 확인됐는가). 카드의 숫자가 법적 정의와 같아야 답변도 맞는다. |

**목표 지표**
- 재현 14건이 법정 값이나 조건부 표시로 바뀐다(**14/14**, 오프라인 테스트로 고정).
- 1일 8시간·주 40시간 이하 입력은 수치가 **불변**이다(골든·배선·CLI 116사례).
- Live 합성 질문에서 카드 오류 수치가 답변에 옮겨진 건수는 **0**이다.

## 1. 출처와 범위 판단

- 4건은 PR #114 독립 리뷰의 지적 3건(L2, 기존 문구 오류 2건)과 특고 카드 관찰 1건이다. PR #114는 a50-40(소정근로시간 미기재) 한 갈래만 고치고 나머지를 후속으로 미뤘다.
- 재현해 보니 두 건은 표기만의 문제가 아니었다. 수습은 판정까지 틀리고(R11), 1일 8시간 초과는 퇴직금 금액에도 번진다(R8).
- 같은 클래스(1일 8시간 고정 가정)를 계산기 전체에서 다시 훑었다. 두 건이 더 나왔고, 둘 다 원인과 수정 지점이 겹쳐 이 사이클에 넣는다.
  - 실업급여 하한·평균임금 추정(F5): 단시간근로자에게 2배 과대 금액을 낸다.
  - 최저임금을 계산하지 않은 카드의 '⏸ 판정 보류' 표시(F4b).
- 나머지 `× 8` 리터럴(`annual_leave` 연차수당 등)은 근거 확인 대상으로만 둔다(§4 P0-2).

## 3. 원인

1. **1일 소정근로시간의 단일 출처가 없다.** 다섯 곳이 각자 정한다. PR #114가 주휴 산식 4곳을 한 곳으로 모은 것과 같은 클래스다.
   - `ordinary_wage._get_base_hours`: 1일 시간 × 근무일수를 그대로 '주 소정근로'로 쓴다.
   - `shared.weekly_holiday_hours`: 최종값에만 8시간 한도를 건다.
   - 1일 통상임금(`ordinary_wage`): 입력 1일 시간을 그대로 곱한다.
   - `severance`: '8h' 문자열을 고정으로 출력한다.
   - `unemployment`: `통상시급 × 8`과 상수 `LOWER_LIMIT_HOURS = 8`을 쓴다.
2. **적용 요건을 모르면 충족을 가정한다.**
   - 수습 감액: `contract_months is None`을 '기간 정함 없음 = 1년 이상'으로 읽는다. '미기재'와 구분하지 않는다. `occupation_code`가 없으면 단순노무가 아닌 것으로 보고, 수습 경과 월은 보지 않는다.
   - 특고: `pipeline.py`의 `_pw_exclude`에도 facade의 `_auto_detect_targets`에도 최저임금 제외가 없다. 후자에는 "항상 최저임금 검증"이라고 적혀 있다.
3. **'계산 안 함'과 '판정 보류'가 같은 값이다.** `WageResult.minimum_wage_ok`의 `None`은 "미실행 또는 계산 보류"를 함께 뜻한다. 그런데 `format_result`는 `None`이면 늘 '⏸ 판정 보류'를 찍는다.

## 4. 개선 항목

### P0 — 이번 사이클 필수

**P0-1. 소정·연장 분리 단일 출처 (F1)**
- `shared.py`에 분리 함수 하나를 둔다(이름·시그니처는 Design에서 정한다).
  - 입력: 1일 시간, 근무일수
  - 출력: 1일 소정, 주 소정, 주 연장, 근거 문자열
  - 기본 규칙: 1일 소정 = min(1일, 8), 주 소정 = min(합계, 40), 나머지는 연장
- 소비처
  - 월 기준시간
  - 주휴: `weekly_holiday_hours`에 주 소정을 넘긴다
  - 1일 통상임금: 시간급 × 1일 소정(시행령 제6조③)
  - 최저임금 비교시간
  - 포괄임금 역산
  - 흐름도 JS 2곳: `weekly_holiday_pay_calc.html`, `comprehensive_wage_reverse_calc.html`
- 연장 가산은 상시 5명 이상이 확인될 때만 계산한다. 규모를 모르면 '5명 이상이면 연장 가산 X원'으로 조건을 단다. 4명 이하면 가산하지 않는다(별표 1).
- 월급제 + 초과 시간
  - 월급에 연장분이 포함되는지 질문에 없으면, 두 구성의 통상시급을 함께 낸다.
  - 최저임금 판정이 갈리면 보류한다(R6).
  - a50-36(총액에 산입 제외 수당이 포함되면 보류)과 같은 규약이다.
- 분리 전제가 달라지는 신호가 있으면 금액 대신 조건을 밝힌다. 판별 방법은 D3에서 정한다. 신호:
  - 탄력적·선택적 근로시간제(제51조~제52조)
  - 감시·단속 승인(제63조)
  - 근로시간 특례 업종(제59조)
  - 연소자(제69조)
  - 유해·위험작업(산업안전보건법 제139조)
  - 상시 4명 이하(D2)
- 질문이 연장시간을 따로 말하면("하루 10시간, 그중 2시간은 연장") 이중 계산을 막는다(D8).

**P0-2. 1일 소정근로시간 소비처 정리 (F2·F5)**
- 퇴직금
  - 산식 표기를 실제 계산 시간으로 바꾼다.
  - `_ineligible`의 `× 8`도 `ow.daily_ordinary_wage`로 맞춘다.
- 실업급여
  - 최저기초일액 = 이직 전 1일 소정근로시간 × 최저임금(고용보험법 제45조④).
  - 1일 소정근로시간은 시행규칙 제91조의2 산식을 따른다. 일 단위로 정했으면 그 시간이고, 주 단위로 정했으면 (주 소정 + 유급휴일 소정) ÷ 48 × 8이다(월 단위·주마다 다른 경우도 같은 조).
  - 평균임금 추정도 `통상시급 × 8` 대신 실제 월 임금으로 하고, 1일 통상임금과 비교한다(제45조②).
- 같은 클래스 전수 점검
  - 계산기의 `× 8`·`* 8`·`8.0` 리터럴을 모두 다시 본다. 남기는 곳에는 근거를 단다.
  - 예: `annual_leave`의 `× 8h`는 단시간 비례 일수에 8시간을 곱하는 시행령 별표 2 제4호 산식으로 보인다. Design에서 원문으로 확인하고, 결함이 아니면 근거 주석만 단다.

**P0-3. 수습 감액 (F3)**
- 표기: `2026년 최저임금: 9,288원/h` → `수습 감액 최저임금: 9,288원/h (2026년 최저임금 10,320원의 90%)`. 비교 줄과 힌트 문구도 같은 라벨을 쓴다.
- 요건 세 가지는 질문에서 확인된 것만 충족으로 본다.
  - 1년 이상 기간을 정한 계약
  - 수습을 시작한 날부터 3개월 이내
  - 단순노무 고시 직종이 아님
- 하나라도 미확인이고 90% 기준과 100% 기준의 판정이 갈리면, 보류하고 두 기준을 함께 낸다.
- `probation_months`와 수습 경과를 배선한다. 질문에 'N개월 중 M개월째'나 입사일이 있으면 3개월 경과를 판정한다. 없으면 '수습 시작일부터 3개월까지만 감액'을 조건으로 적는다.
- `contract_months is None`을 '기간 정함 없음'과 '미기재'로 나눌지(의도분석 스키마 보강)는 D5에서 정한다.

**P0-4. 특고·최저임금 상태 표시 (F4·F4b)**
- `is_platform_worker`면 최저임금 판정을 내지 않는다.
  - 대신 조건부로 안내한다: "최저임금법은 근로기준법상 근로자에게 적용된다(최저임금법 제2조). 노무제공자는 원칙적으로 대상이 아니고, 실질적으로 근로자에 해당하면 기준은 시간당 X원이다."
  - '노동청 신고 가능'과 벌칙 힌트는 내지 않는다.
- 최저임금 상태를 넷으로 나눈다.
  - 충족
  - 미달
  - 판정 보류: 요건 미확인, 판정 갈림
  - 적용 대상 아님: 근로자성 미확인
- 계산하지 않았으면 헤더 줄을 내지 않는다(R14).
- 표현 방식(3값 + 사유 필드, 또는 enum)과, 이 상태를 읽는 곳(LLM 머리말·`WAGE_CALC_RULES`·프런트) 전수 점검은 D6에서 정한다.
