### Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 답변 컨텍스트의 **96%가 타인 저작물**이다(실측 12주제 54건 중 상담 41·해설서 11). 공공저작물인 판례·행정해석은 **2건, 4%**뿐이다. 해설서에는 저작권 가드 6종(풀어쓰기·권당 3·총량 6·서명 표기·게시판 제외)이 있지만 **상담 Q&A 49,842건에는 아무 가드가 없다** — 원문이 그대로 LLM 컨텍스트에 들어가고, 상한도 풀어쓰기 지시도 공개 게시판 제외도 없다. 노출량으로 보면 해설서(상한 6건)보다 상담글이 훨씬 크다. 원인은 코퍼스 부족이 아니라 구성 불균형이다: 상담글이 코퍼스의 72%라 검색 결과를 전역 점수로 절단할 때 슬롯을 독식한다. 법률 문서는 존재하며(laborlaw-v2 pool이 전 주제에서 15/15로 충족), 소스를 지정해 조회하면 정확한 판례가 상위에 온다. |
| **Solution** | 소스를 **저작권 지위로 3분류**해 다르게 다룬다. ① **공공저작물**(판례·행정해석·훈령 — 저작권법 제7조 비보호): 상한 없이 우선 배분. ② **해설서**: 기존 상한 유지, 늘리지 않음. ③ **상담 Q&A**: 답변 *근거*에서 사후 *사례*로 강등하고 상한·풀어쓰기 가드를 신설. 검색은 이미 두 그룹을 병렬 조회하므로 절단 방식만 바꾸면 되고 추가 조회가 없다. |
| **Function UX Effect** | 답변이 "비슷한 상담 사례를 요약한 것"에서 "판례·법조문에 근거한 설명 + 참고 사례"로 바뀐다. 실측 투영: 공공저작물 2 → **20건(10배)**, 상담 비중 76% → **22%**, 저작물 비중 96% → **60%**. |
| **Core Value** | 인용해도 되는 자료(공공저작물)를 주 근거로, 조심해야 할 자료(타인 저작물)를 보조로 되돌린다 — 답변의 법적 신뢰도와 저작권 안전성이 같은 방향으로 개선된다. |

## 1. 실측 (2026-08-20)

### 1.1 착수 가설의 검증과 반증

이 사이클은 "4대보험·근로자성 코퍼스가 비어 있다"는 가설로 제안됐다. **Plan 작성 전에 검증했고 가설 3개가 연속 반증됐다.**

| 가설 | 검증 방법 | 결과 |
|------|-----------|------|
| ① 코퍼스 공백 | BM25 69,374문서 주제별 인구조사(대조군 병행) | **근로자성은 법률 소스 399건 존재** — 반증. 4대보험만 실제 공백(미가입·소급 3건) |
| ② 어휘 불일치 | 8주제를 LLM 키워드 vs 법률문서 용어로 검색 | 법정 용어인 부당해고(제23조)도 LLM 키워드로 **0/15** — 어휘만의 문제 아님 |
| ③ 쟁점 혼합 | `precedent_query.py:83`이 키워드 4개를 한 문자열로 합침 → 분리 후 RRF | **더 나빠짐**(임금체불 개별 14/15 → 병합 3/15) — 반증 |

**진짜 원인**: 짧고 흔한 주제어일수록 상담글이 이긴다.

| 잘 되는 쿼리 | | 안 되는 쿼리 | |
|---|:---:|---|:---:|
| "임금 전액 지급 원칙" | 14/15 | "임금체불" | **0/15** |
| "사용자 조치의무" | 14/15 | "직장 내 괴롭힘" | **0/15** |
| "해고 사유 서면통지" | 11/15 | "부당해고" | **0/15** |

코퍼스 구성이 **qa 49,842(71.8%) / 법률 18,288(26.4%) / counsel 1,244(1.8%)**이고 상담글은 구어체라 일상 표현의 쿼리와 임베딩 거리가 가깝다. `rag.py:133-135`가 두 그룹 결과를 합쳐 **점수로 전역 정렬한 뒤 절단**하므로 그 지점에서 상담이 이긴다.

### 1.2 저작권 노출 실측 — 이 사이클의 핵심 근거

12주제의 **실제 답변 컨텍스트**(rerank + 승격 + 가드 `format_pinecone_hits` 통과 후):

| 구성 | 공공저작물 | 해설서 | 상담 | 저작물 비중 | 상담 비중 |
|------|:---:|:---:|:---:|:---:|:---:|
| **현행** | **2** | 11 | **41** | **96%** | **76%** |
| 목표 구성(시뮬레이션) | **20** | 19 | 11 | 60% | 22% |

- 법률 pool은 전 주제에서 `MIN_SCORE 0.35` 통과분이 **15/15**로 충족 — 상담글을 빼도 근거가 부족해지지 않는다.
- 소스 필터를 걸면 프로덕션 쿼리 그대로도 정확한 문서가 상위에 온다(근로자성 → "보험회사 위탁계약형 지점장의 근로자성 — 종속성의 판단 요소" 0.557).
- 시뮬레이션의 해설서 11→19 증가는 **지시와 어긋나므로 그대로 채택하지 않는다**(§2 T1-b 게이트).

### 비목표

- **`top_k`·`rerank_top_n` 상향** — 전송량이 실제로 늘어 저작권 검토 대상이다. T1은 **배분 변경**이지 증량이 아니며 이 구분이 성립 전제다.
- **상담 코퍼스 삭제·축소** — 벡터는 그대로 둔다. 바꾸는 것은 *쓰는 방식*이다. 유사 사례 제시는 실사용자에게 유용한 기능이므로 없애지 않는다.
- **국민연금·건강보험 심층 수집** — 소관이 복지부·공단이라 현행 인프라(고용노동부·법제처) 밖. T4는 고용보험·산재보험 우선.
- **`_PRELOADED_MST` 갱신 — 범위 밖이나 별도 사이클 필요(아래 실측)**. `legal_api.py:91-108`의 사전 매핑이 낡아 **프로덕션이 구버전 조문으로 답하고 있다.** 라이브 대조(2026-08-20):

  | 법령 | 코드의 MST | 현행 MST | 현행 시행일 |
  |------|---:|---:|---|
  | 근로기준법 | 265959 | **283457** | 2026-08-20 |
  | 고용보험법 | 276843 | **283373** | 2026-08-20 |
  | 산업재해보상보험법 | 279733 | **283459** | 2026-07-01 |
  | 근로자퇴직급여 보장법 | 279829 | **284455** | 2026-07-01 |
  | 최저임금법 | 218303 | 218303 | 2020-05-26 (일치) |

  MST를 명시하면 **그 판본의** 조문이 오므로 개정 내용이 반영되지 않는다. 코드 주석은 *"법 전부개정 시에만 변경"* 이라고 적혀 있으나 실제로는 **일부개정마다 일련번호가 바뀐다** — 이 전제 오류가 드리프트의 원인이다. 이 사이클에서 손대지 않는 이유는 근거 구성 재편과 무관한 축이고, 갱신 방식(주기적 재조회 vs 사전매핑 폐기)이 별도 판단을 요하기 때문이다.

## 3. 처방 방향

### 3.1 T1 — 소스 3분류 배분

- 위치: `rag.py::search_pinecone`의 병합·절단(`deduped.sort → [:top_k]`).
- 현행은 두 그룹(`laborlaw-v2` / `counsel+qa`)을 같은 top_k로 병렬 조회한 뒤 **전역 정렬**해 자른다. 이 절단을 분류별 배분으로 바꾼다.
- **laborlaw-v2를 그룹째 늘리면 안 된다** — 그 안에 해설서가 섞여 있어 저작물 노출이 함께 는다(실측 14→32). 공공저작물만 별도 배분해야 지시와 정합한다.
- 배분값·복잡도별 차등·법률 부족 시 빈 슬롯 처리는 Design에서 실측으로 확정.
- **계산 경로 확인 항목**: 계산기 결과는 검색 슬롯을 쓰지 않아(별도 `parts.append`) 재배분과 독립이고 저작권 대상도 아니다(우리 산출물 — 판례·법조문과 같은 취급). 다만 `pipeline.py:1752`의 `and not calc_result` 때문에 **계산 질문은 법률상담 전용 심화 경로(`process_consultation`)를 건너뛴다**(판례 RAG·법령 조문 조회는 정상). "계산 질문에서 법률 근거가 덜 실린다"는 뜻이므로 T1 지표를 계산 질문 세트로도 측정할지 Design에서 판단.

### 3.2 T2 — 상담 저작권 가드 (해설서 G1~G6 계열 확장)

해설서 가드를 그대로 베끼지 말고 **성격 차이**를 반영한다: 해설서는 "단독 근거 금지"가 핵심이지만, 상담은 애초에 근거가 아니라 사례이므로 *출처 성격 표시*와 *풀어쓰기*가 핵심이다.

- 풀어쓰기 지시 — 상담 원문 축자 인용 금지. **부착 방식은 해설서 가드와 동일한 함정을 피할 것**: 답변 경로가 두 갈래(`CONSULTATION_SYSTEM_PROMPT` / `SYSTEM_PROMPT_TEMPLATE`)라 한쪽에만 넣으면 다른 경로에서 무가드로 나간다(`prompts.py:333-338` 주석의 실패 이력).
- 노출 상한 — 총량 상한 신설. 값은 T1 배분과 함께 결정.
- 공개 게시판 제외 — 상담 원문 의존 답변이 크롤 가능한 공개 페이지로 재게시되는 경로 차단(G6와 같은 논리). 판정은 `uses_textbook()`처럼 **공용 함수 하나**로.

### 3.3 T3 — 사후 대조 사례

사용자 지시: *"답변을 생성한 후 비슷한 질문이 있는지, 그 질문에 대한 답이 얼마나 다른지 대조하여 동일하다면 사례 제시하는 정도로"*

- 생성 → 유사 상담 검색 → 답변과 상담 답변의 유사도 대조 → 동일하면 "유사 사례"로 제시.
- 대조 수단 후보: (a) 임베딩 유사도(추가 LLM 호출 0, 상담 벡터는 이미 Pinecone에 있음) (b) LLM 판정(정확하지만 지연·비용). **(a) 우선 검토**.
- **답이 다를 때 = 제시하지 않고 내부 기록만 한다** (2026-08-20 사용자 확정). 근거: 노동상담에서 상충하는 정보는 사용자를 혼란시키고, 우리 답변은 판례·법조문 근거라 신뢰도가 더 높다. 기록은 버리지 않는다 — "우리 답과 실무 상담이 갈리는 주제"는 품질 모니터링·코퍼스 공백 탐지의 신호다. 저장 위치·키는 Design에서 확정하되 **공개 게시판에는 노출하지 않는다**(상담 원문 관련 메타이므로).
- 스트리밍 UX 제약: 답변 생성 후 단계이므로 SSE `sources`/신규 이벤트로 뒤이어 붙이는 형태가 자연스럽다(`replace`처럼 본문을 갈아끼우지 않는다).

### 3.4 T5 — 훈령·예규 161건 적재 (신규 발견, 가장 쌈)

조사 중 확인된 **이미 발생 중인 손해**다. 공공저작물을 늘리려는 이 사이클의 목표를 수집 비용 없이 부분 달성한다.

- **`source_type="regulation"`이 프로덕션에 0건**이다(인구조사에서 출처 분포에 아예 없음 — `interpretation` 6,828 / `precedent` 4,825 / `textbook` 6,635 / `counsel` 1,244 / `qa` 49,842).
- 그런데 `output_훈령예규고시지침/`에 **161개 `.md`가 파싱까지 끝난 채 로컬에 있다**(지침·예규·훈령·고시 4계열). 업로드된 적이 없다.
- 동시에 `rag.py:276`의 `LEGAL_PROMOTE_SOURCES`가 `regulation`을 승격 대상에 넣고 있다 — **뒷받침 문서가 0건인 죽은 멤버**다. 적재하는 순간 기존 승격 로직이 그대로 작동한다.
- 공공저작물이라 노출 가드가 불요하고, 이 Plan의 "공공 우선" 배분과 즉시 정합한다.

### 3.5 T4 — 4대보험 코퍼스 수집

**공백 원인이 확정됐다(추측 아님)**: `output_노동부 행정해석/`의 30개 카테고리가 전부 근로기준법·퇴직급여법 주제이고, 1,439개 파일 중 고용보험·산재·국민연금·건강보험·실업급여가 파일명에 든 것이 **0건**이다. 본문 회신번호에서 발신 부서를 추출하니 5,328건·26개 부서가 전부 근로기준정책과·퇴직연금복지과 계열이고 **고용보험 해석을 발령하는 고용지원실업급여과·고용보험기획과·산재보상정책과가 1건도 없다**. 크롤 범위가 아니라 nodong.kr **원본 게시판의 편집 방침**이 원인이므로, 같은 소스를 더 긁어도 나오지 않는다. 국민연금·건강보험은 **보건복지부 소관**이라 노동부 계열 소스로는 원리적으로 불가.

### 3.6 T4·T5의 함정 (조사 확인 — 전부 조용히 실패한다)

| # | 함정 | 대응 |
|---|------|------|
| a | `pinecone_upload_legal.py`를 복사하면 **검색 안 되는 네임스페이스에 쌓인다** — 그것이 쓰는 `precedent`/`interpretation`/`regulation`/`legal_cases`를 `rag.py`가 읽지 않는다(`regulation`은 Pinecone에 아예 없음) | 반드시 `laborlaw-v2`에. 참고 대상은 `pinecone_upload_court_precedents.py` / `pinecone_upload_textbook.py` |
| b | **주제 검색 결과의 `<사건번호>`가 70% 공란**(고용보험 prec 100건 중 70건) — `search_case()`는 사건번호 정확일치로 채택하므로 그대로 재사용하면 **70%가 조용히 버려진다** | `판례일련번호`로 상세를 받은 뒤 상세 응답의 사건번호로 중복 제거. ※ 기존 `_미발견.csv` 156건과는 무관함이 재검증됨(사건번호 검색 시 필드 정상, 대부분 법제처 DB 미수록) |
| c | `decc` 상세 스키마가 `prec`/`detc`와 **또 다르다** — 루트 `PrecService`, 항목 태그 `행정심판례일련번호`(검색 응답은 `행정심판재결례일련번호`) | `normalize_record()`에 세 번째 분기 |
| d | `search=2`(본문검색)는 볼륨이 폭증하나 정밀도가 무너진다(국민연금 상위가 "간이귀화불허처분취소청구") | 쓰지 않는다 |
| e | `output_자료실/`의 국민연금 요율 문서는 **2023년 값**이라 `pipeline.py::_build_insurance_facts()`가 주입하는 검증된 현재 요율과 충돌 | 적재 대상에서 제외 |
| f | **코퍼스만 채워서는 해결되지 않는다** — `consultation_topic` enum에 `고용보험`은 있으나 4대보험 전반(국민연금·건강보험) 항목이 없어 `default_laws`가 안 붙고, `_INSURANCE_SIGNALS`가 걸려 **요율표**를 주입한다(가입의무 질문에 보험료율을 답하는 셈) | T4는 코퍼스 + 토픽 매핑 + 요율표 오주입 억제를 함께 다룬다 |
