## 1. 핵심 판단

### 2.2 연결·규칙 관리 공백

- 엄격한 유형 변환에서 `난임치료휴가`, `배우자 유산·사산휴가`, `유산휴가`, `중도퇴사 급여`가 해석되지 않았다. 기존 모듈로 연결할 표현과 추가 입력을 구분해야 한다.
- `임금체불액`은 `wage_arrears`로 연결되지만 현재 모듈은 **입력된 원금의 이자**를 계산한다. 지급돼야 할 임금과 실제 지급액의 차액 산정은 별도 기능이다.
- `연말정산`은 `insurance`로 연결된다. 월 원천징수와 연간 세액 정산은 기능 범위가 다르므로 잘못된 계산 확정을 막아야 한다.
- `선택적 근로시간제`가 `working_hours`로 연결돼도 정산기간별 선택근로 정산이 구현됐다는 뜻은 아니다.
- [legal_rules.py](../../../wage_calculator/legal_rules.py)의 관리 대상은 조사 시점 11개 키다. 육아휴직 등 모든 계산기 상수가 관리자 규칙 갱신을 자동으로 따르는 구조는 아니다.
- 원격 main의 `FixedAllowance`에는 이미 `annual`·`payment_cycle`·`monthly_amount`가 있다. **지급 주기가 빠진 곳은 의도분석 도구 스키마**다. 모델을 중복 신설하지 않고 `app/templates/prompts.py`와 변환 경로를 연결한다.
- 채팅은 `annual_bonus_total`, `last_3m_wages`, `last_3m_days`, `excluded_periods`를 계산기에 전달하지 않는다. C4b에서 명시 입력의 전달과 이중 산입 방지를 검증한다.
- `public/calculator_flow/`와 계산기 폴더의 HTML 사본에도 구 상한·사후지급·연차 차감·재직 중 6% 설명이 남아 있다. 계산기 함수와 같은 릴리스에서 수정한다.

## 3. Global Constraints — 공통 구현 원칙

1. **조회 기준일과 사건 날짜를 구분한다.** `legal_rules.resolve_reference_date()`의 명시 날짜 우선 → 무지정은 오늘(KST) → 다른 연도만 지정하면 날짜 요청 규칙을 유지한다. 잘못된 명시 날짜는 무지정으로 바꾸지 않는다. 휴직 시작일·사용 구간·지급기일·퇴직일은 별도 사건 입력이다. 이를 오늘로 만들어 실제 정산액을 확정하지 않는다. 기간·자격이 충분한 현행 제도 예시는 오늘 기준이라는 조건을 붙여 계산할 수 있고, 부족한 사실에 의존하는 결과만 보류한다.
2. **규칙 근거를 남긴다.** 규칙별 법령·조문·공식 안내 URL, 시행일, 부칙, 원문 식별자·해시, 검토일을 보관한다. 구현일에 원문을 재확인한다. 기존 관리자 승인 절차가 적용되는 규칙은 그 절차를 따른다.
3. **과거 사건을 보존한다.** 현행 금액으로 과거 계산을 덮지 않는다. 개정 전후 사례를 함께 검증하고 근거가 없는 연도는 명확히 처리한다.
4. **금액을 중복 합산하지 않는다.** 체불 원금과 이자, 월급과 미지급 수당, 단축 후 사업주 지급 임금과 고용보험 급여를 구분한다. 산식 중간값은 보존하고 법정·기존 규약에 따라 반올림한다.
5. **입력에서 답변까지 연결한다.** 계산기 함수만 수정하지 않는다. `models.py`, registry, 분석 스키마·프롬프트, `_run_calculator`, 결과 설명의 필드와 의미를 맞춘다.
6. **자격 판정을 금액 계산과 구분한다.** 대지급금 수급, 부당해고 인정 등 확정할 수 없는 사실을 금액 계산기가 확정하지 않는다.
7. **기존 자료를 활용한다.** 연차 교재는 Pinecone `laborlaw-v2`의 `book_id=yeoncha`로 1,028개 벡터가 확인됐고 로컬 BM25도 1,028개다. 재임베딩을 선행 조건으로 두지 않는다. 검색 자료의 존재가 계산식의 정확성을 보장하지는 않는다.
8. **변경 범위를 분리한다.** 계산기 수정과 Q&A 갱신 효과를 따로 측정한다. 기존 작업 파일과 운영 데이터는 구현 범위 확인 없이 덮어쓰지 않는다.
9. **임금의 단일 출처를 재사용한다.** 기준 월액은 `wage_calculator/calculators/shared.py::monthly_wage_total(inp, ow, premium=True)`, 연액은 `annual_wage_total`, 평균임금 일액은 `average_wage.calc_average_wage`를 사용한다. C5·대지급금·감봉 소비처에서 산식을 복제하지 않는다. **육아휴직·단축급여의 월 통상임금은 기준 월액과 다르므로** `ow.monthly_ordinary_wage`를 사용한다.
10. **규칙 관리 방식은 내장 시행일 구간표로 확정한다.** 이번 P0는 신규 `wage_calculator/effective_rules.py`에 `[시행일 포함, 종료일 제외)` 규칙과 근거를 둔다. 현재 11개 관리자 승인 키는 늘리지 않는다. 관리 모드에서도 신규 급여·이자 규칙이 내장표임을 명시한다. 관리자 이관은 공식 `official_url` 근거 수집·업로드, 키 등록, 승인·미승인 검증을 포함하는 별도 작업이다.
11. **개정 적용은 제도별로 다르다.** 육아 급여는 지급 대상 기간을 구간 분할하고, 체불이자는 부칙상 지급사유 발생일로 적용 여부를 정한다. 공통 기간 도구가 법률별 적용 요건까지 자동 결정하지 않는다.

### 5.1 카드·답변·변이 검증

- 직접 함수 외에 `AnalysisResult → _analysis_to_extract_params → _run_calculator(params, query)`를 검증한다. 정규화 전후 지급 주기, 3개월 임금, 휴직 기간, 주 단축시간, 체불 기산일이 사라지지 않아야 한다.
- `data/eval_wage_update_queries.json`(신규)은 §2.1 다섯 유형과 개정 전후·입력 부족 반례를 담는다. 실제 답변은 저장소 밖 평가 하네스(`run_eval.py`)로 **기준선·변경 후 각 2회**, 같은 모델·법령 캐시·코퍼스 조건에서 생성한다.
- 실행 예: `python3 <평가 하네스>/run_eval.py --repo <평가할 체크아웃> --fixture <공통 fixture의 절대경로> --cases all --law-mode prod --primary openai --out <별도 결과 파일>`. 기준선에는 신규 fixture가 없으므로 두 실행 모두 같은 파일의 절대경로를 사용한다. 신규 계산 라벨은 양쪽 평가 하네스의 동일한 검증 스키마에서 허용하되 기준선 계산 코드는 바꾸지 않는다. 자리표시자는 실행 시 실제 경로로 바꾼다.
- 이 하네스의 `prod`는 **로컬에서 프로덕션 법제처 실패 조건을 재현**하는 모드이며 운영 화면 호출이 아니다. 현재 코드의 `config.supabase=None`, DRF 차단, L2 쓰기 차단을 착수 시 재확인한다. 평가 도구 버전·모델 실제 폴백 여부도 결과와 함께 기록한다.
- 1,125,000·4,500,000·600,000·14,795원 및 `2년차 차감` 금지는 **대응하는 현행 fixture의 잘못된 결론**에만 적용한다. 과거 사례의 올바른 값이나 신구 비교 설명까지 일괄 금지하지 않는다. 카드와 답변의 금액·시점·조건을 함께 대조한다.
- 변이 검사는 수정한 핵심 분기에 한정한다. 구 상한·사후지급 25%, 개정 경계 하루 이동, 퇴직 시 기산일 재설정, 연차 차감 복원, 단축 최초 10시간 누락, 미실행 카드의 월 총액 복원을 각각 임시로 넣었을 때 대응 테스트가 실패해야 한다. 변이를 제거한 정상 코드도 다시 통과해야 한다.
- 질문 날짜 무지정/현재 연도만 지정/다른 연도만 지정/잘못된 명시 날짜/급여 사건일 누락을 별도 fixture로 둔다. 일반적인 현재 기준 질문이 일괄 보류되거나 미상의 지급기일이 오늘로 바뀌면 실패다.

### 8.2 구조·범위 의견

1. **기준 월액 단일화(PR #123·#124)와의 관계를 문서에 적을 것.**
   - **같은 함수를 쓸 것.** 다음 계산은 `shared.monthly_wage_total`·`annual_wage_total`·`average_wage.calc_average_wage`를 써야 한다(CLAUDE.md '소비처에서 월 금액·평균임금을 직접 만들지 말 것').
     - C5: 체불 원금의 월 의무액
     - P2 감봉 한도: 평균임금 1일분(근로기준법 제95조 — 1회 1일분의 1/2, 1임금지급기 총액의 1/10. L7과 같음)
     - P2 대지급금: 퇴직급여의 평균임금
   - **C6 일할계산은 그 사이클이 예외로 남긴 곳이다.** `prorated`는 아직 `monthly_total_pay or monthly_wage`를 직접 읽는다. C6에서 기준 월액(수당 포함)으로 일할할지, 계약상 월급만 일할할지 정할 것.
   - **C4에 흡수할 것.** 그 사이클 후속인 아래 두 문제는 C4(분석 스키마·입력 연결)·C5(월별 항목 입력)와 같은 작업이다.
     - 의도분석이 '연 상여'를 '월 수당'으로 뽑는 문제: `fixed_allowances`에 지급 주기 필드가 없다. Live 4회 중 2회 발생했다.
     - 채팅 경로가 연 상여·`last_3m_*`·`excluded_periods`를 넘기지 않는 문제

2. **§3 원칙 1(날짜가 없으면 오늘로 대체하지 않음)은 현행 규칙과 충돌한다.**
