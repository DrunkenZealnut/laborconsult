## Executive Summary

| 관점 | 내용 |
|------|------|
| **문제** | 공개 HTML 33개가 단일 디자인 언어를 공유하지 않는다. `:root` 토큰 블록이 6개 파일에 복붙 중복돼 있고, 그중 `calculators.html`·`admin.html`은 아예 다른 색 계열(#2563eb 블루)로 이미 갈라졌다. 계산기 흐름도 25종은 파일마다 토큰 이름이 제각각(`--blue` / `--color-background-primary` / `--p`)이고 하드코딩 hex가 2,888회 출현한다. 색 하나를 바꾸려면 33개 파일을 손으로 추적해야 한다. |
| **해결** | ① `public/tokens.css`를 단일 출처로 신설 — Swiss Modernism 2.0 규격의 색·타이포·스페이싱·그리드·모션 토큰을 정의하고 33개 파일이 `<link>`로 참조. ② 무채색 베이스(#111111 / #FFFFFF / #F5F5F5) + 코퍼(#C08050) 단일 액센트로 전면 교체, Pretendard 단일 서체화. ③ 8px 배수 스페이싱과 12칼럼 그리드, 200~300ms `transform`/`opacity` 전용 모션 규칙 적용. |
| **기능/UX 효과** | 33개 페이지가 하나의 시각 언어로 수렴해 계산기·게시판·상담 간 이동 시 이질감이 사라진다. 토큰 단일화로 다크모드가 26개 파일에만 있던 비대칭이 해소되고, 이후 색·간격 변경이 1개 파일 수정으로 끝난다. |
| **핵심 가치** | **디자인 부채의 단일 출처화** — 시각적 일관성은 결과이고, 실제 이득은 "바꿀 곳이 한 곳"이 되는 것이다. |

## 1. 개요

### 1.1 목적

Swiss Modernism 2.0 디자인 시스템을 도입해 공개 웹 자산 전체의 시각 언어를 통일하고, 흩어진 CSS 토큰을 단일 출처로 수렴시킨다.

### 1.2 배경 — 현황 실측

조사 시점 2026-08-07 기준 실측치다. 추정이 아니라 파일을 세어 얻은 값이다.

**규모**

| 대상 | 파일 수 | 총 줄 수 |
|------|--------:|---------:|
| `public/*.html` (공개 페이지) | 8 | 4,642 |
| `public/calculator_flow/*.html` (계산기 흐름도) | 25 | 14,589 |
| **합계** | **33** | **19,231** |

**토큰 분기 실태**

| 토큰 계열 | 사용처 | 대표 값 |
|-----------|--------|---------|
| 네이비/코퍼 | `index` `board` `privacy` `terms` `install` `offline` (6개) | `--navy:#1B2A4A` `--copper:#C08050` `--cream:#F7F5F2` |
| 블루/슬레이트 | `calculators` `admin` (2개) | `--primary:#2563eb` `--bg:#f8fafc` |
| 시맨틱 롱네임 | 흐름도 21개 | `--color-background-primary` `--color-text-warning` 등 17종 |
| 축약형 | 흐름도 다수 | `--p` `--s` `--b` `--bg2` |
| 컬러네임 | `compensatory_leave_calc` 1개 | `--blue` `--teal` `--coral` `--purple` |

- 흐름도 25개에서 발견된 고유 토큰명: **47종**
- 하드코딩 hex 출현: 흐름도 **2,888회**(고유 123색), 공개 페이지 고유 **69색**
- → 토큰이 있어도 대부분의 색은 토큰을 거치지 않는다. 토큰화 자체가 미완이다.

**Swiss 규격 위반 현황**

| 규격 | 위반 지점 | 수량 |
|------|-----------|-----:|
| 그라디언트 금지 | `index.html` 1, `board.html` 2 | 3 |
| UI 이모지 금지 (아이콘 시스템만) | `index.html` 13, `calculators.html` 7, `finalize.js` 3, 흐름도 12개 파일 | 23+ |
| 서체 단일화 | `Noto Serif KR`(5개 파일), `Do Hyeon`(로고 전용) | 2종 제거 대상 |
| 무채색 베이스 | 네이비·크림·블루 3계열 공존 | 전면 |

**다크모드 비대칭** — 이 계획에서 가장 까다로운 지점이다.

| 다크모드 | 파일 |
|----------|------|
| 있음 (26개) | 흐름도 25개 전부 + `calculators.html` |
| 없음 (7개) | `index` `board` `admin` `privacy` `terms` `install` `offline` |

단일 `tokens.css`로 통합하는 순간 이 비대칭을 결정해야 한다. 방치하면 통합 후 26개 파일의 다크모드가 깨지거나, 나머지 7개가 의도치 않게 다크모드를 얻는다.

### 1.3 관련 문서

- 디자인 시스템 원본: https://designmd.app/library/swiss-modernism-2-0
- 프로젝트 규약: `CLAUDE.md` (Key Conventions — 공개 페이지 관련 제약)
- 선행 UI 작업: `docs/archive/2026-08/answer-at-a-glance/` (`finalize.js` 도입 경위)

| 토큰 관리 | 공유 CSS / 인라인 유지 | **공유 `public/tokens.css`** | 현재 6곳 중복이 이미 드리프트를 낳았다(`calculators`·`admin`이 다른 색 계열로 이탈). `finalize.js`·`pwa.js`와 같은 정적 파일 분리 방식과 일관 |
| 스타일 방식 | 순수 CSS / Tailwind / CSS-in-JS | **순수 CSS 커스텀 프로퍼티** | 빌드 스텝 없는 정적 HTML 구조 유지. Vercel `@vercel/static` 서빙에 그대로 얹힌다 |
| 배포 | 무변경 | **Vercel 단일** | `vercel.json` 라우트 `/(.*\..*)` → `/public/$1`로 `tokens.css`가 별도 설정 없이 서빙됨 |
| 회귀 방어 | 신규 테스트 / 기존 스위트 | **기존 3종 + 필요 시 추가** | `test_public_fetch.js`·`test_answer_renderer.js`·`test_answer_glance.js`가 이미 CI에 있다 |
