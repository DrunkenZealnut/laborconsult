# textbook-retrieval-balance Plan

## Executive Summary

| 항목 | 내용 |
|------|------|
| Feature | 해설서 코퍼스가 검색에는 잡히는데 답변 근거에는 못 드는 문제를 **출처 다양성 보장**으로 해소 |
| 시작일 | 2026-08-19 |
| 예상 기간 | 1~2일 |
| 선행 | `textbook-corpus-followup`(2026-08-17, Match 97.8%), 개별노동법실무 part4·Part5 적재(2026-08-19) |
| 발단 | part4·Part5 적재 후 검색 품질 확인에서 10질의 중 7건이 해설서 0건 |
| 결정 | 목표 = **출처 다양성 보장** / 저작권 노출 = **현행 상한(G4 3·G4-T 6) 유지** |

### Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 해설서 4,993청크를 적재했지만 답변 근거로는 거의 쓰이지 않는다. 실측 10질의 중 **7건이 해설서 0건**이고 최종 컨텍스트 46건의 구성은 qa 34 / precedent 7 / textbook 5다. 원인은 두 갈래이고 성격이 다르다 — **3건은 hybrid에 올라왔는데 Cohere rerank가 떨어뜨렸고**(랭킹), 4건은 hybrid에 애초에 도달하지 못했다(검색). 게다가 `decompose_query`가 LLM이라 같은 질의를 두 번 돌리면 결과가 달라져(휴게시간 질의 2건→0건) **개선 효과를 측정할 방법 자체가 없다.** |
| **Solution** | rerank 결과에 해설서가 0건이지만 rerank **입력(pool)에는 있었던** 경우, 최하위 1건과 교체해 해설서 1건을 승격한다. 총 건수는 불변이라 노출 상한(G4·G4-T)은 그대로다. 승격은 pool과 결과를 동시에 아는 유일한 지점에 두어 호출부가 늘어도 새지 않게 한다. 선결로 **고정 평가셋**을 만들어 분해 쿼리 비결정성을 제거한다 — 이것 없이는 어떤 개선도 검증할 수 없다. |
| **Function UX Effect** | 해설서에 해당 주제가 있는 질문에서 답변 하단 출처에 「노동법 해설서」가 최소 1건 나타난다. 답변 근거가 상담 Q&A 일변도에서 해설서·판례가 섞인 구성으로 바뀐다. 출처 총 건수와 응답 지연은 그대로다. |
| **Core Value** | 검색 단계에서 이미 확보한 근거가 랭킹 편중으로 사장되지 않게 한다. 코퍼스 투자(4,993청크)를 노출 상한을 건드리지 않고 회수한다. |

## 1. 현황 분석

### 1.1 발단

2026-08-19 개별노동법실무 part4·Part5(실무테마 36~60, 1,425청크) 적재 후 검색 품질을 확인하는 과정에서 드러났다. **적재 자체는 정상이다** — 해설서만 필터한 Dense 검색에서 주제별로 정확한 청크가 상위에 오르고(연차수당 시효 → `gaebyeol_1010_0`, 포괄임금제 무효 → `gaebyeol_1474_0`), 본문도 온전하다(빈 청크 0건). 문제는 **전체 검색에서 다른 출처에 밀려 답변 근거까지 도달하지 못하는 것**이다.

### 1.2 실측 — 단계별 해설서 비율

프로덕션 경로(`pipeline.py` ①hybrid → ②rerank → ③Self-RAG → ④가드)를 그대로 재현해 10질의를 측정했다(2026-08-19).

| 단계 | 해설서 / 전체 | 비율 |
|------|:---:|:---:|
| Dense (`search_pinecone_multi`) | 48 / 256 | 19% |
| BM25 단독 | 20 / 136 | 15% |
| Hybrid RRF (`search_hybrid`) | 22 / 136 | 16% |
| **Rerank 후 (Cohere)** | **5 / 46** | **11%** |
| 가드 후(G4·G4-T) | 5 / 46 | 11% |

코퍼스 내 해설서 비중은 4,993 / 67,732 = **7.4%**다. 즉 Dense 19%는 코퍼스 비율보다 오히려 **높다** — 검색기가 해설서를 홀대하는 것이 아니다. 비율이 꺾이는 지점은 rerank(16% → 11%)다.

### 1.3 실측 — 0건 질의의 원인은 두 갈래

해설서 0건 질의 **7/10**의 내역:

| 원인 | 건수 | 성격 | 이번 범위 |
|------|:---:|------|:---:|
| hybrid엔 있었는데 rerank가 탈락시킴 | **3** | 랭킹 편중 | **포함** |
| hybrid에 애초에 도달 못 함 | 4 | 검색 범위(SIMPLE은 `top_k=8`) | 제외 |

두 원인을 한 사이클에서 같이 다루지 않는다. 랭킹 탈락은 **이미 확보한 후보를 버리는** 문제라 추가 검색·전송 없이 고칠 수 있지만, 검색 미도달은 `top_k` 확대나 소스별 쿼터 검색이 필요해 Cohere·Self-RAG로 나가는 **외부 전송량이 함께 늘어난다**(`CLAUDE.md`가 지적한 "상한 6은 답변 컨텍스트의 천장이지 제3자 전송의 천장이 아니다"에 직결). 저작권 검토 범위가 달라지므로 분리한다.

### 1.4 실측 — 최종 컨텍스트 구성

| source_type | 건수 (46건 중) |
|---|:---:|
| qa (상담 Q&A) | 34 |
| precedent (판례) | 7 |
| textbook (해설서) | 5 |

`qa` 코퍼스는 49,842건으로 실사용 질문과 어휘가 가장 가깝다. rerank가 이를 상위로 올리는 것은 **오작동이 아니다** — 실제로 "퇴사후 1년이 흐른뒤 연차수당 받을수있나요?" 같은 결과는 질의에 정확히 대응한다. 이 사이클은 qa를 깎는 것이 목적이 아니라, **해설서가 0이 되는 것만** 막는다.

### 1.5 선결 문제 — 측정이 재현되지 않는다

같은 질의를 두 번 측정했더니 결과가 달랐다.

| 질의 | 1회차 rerank 해설서 | 2회차 |
|---|:---:|:---:|
| 휴게시간 몰아서 부여 | 2 / 5 | **0 / 5** |

`pipeline.py`가 부르는 `decompose_query()`가 LLM 호출이라 매 실행 다른 분해 쿼리를 만들고, 그것이 hybrid 후보군을 바꾼다. **이 상태로는 개선 전후를 비교할 수 없다.** 어떤 대안을 고르든 고정 평가셋이 선행되어야 한다.

### 1.6 관련 코드

| 위치 | 역할 | 이번 변경 |
|------|------|:---:|
| `app/core/rag.py::rerank_results` | Cohere 재정렬. **pool(입력)과 결과를 동시에 아는 유일한 지점** | 변경 |
| `app/core/rag.py::_cap_by_book` / `_cap_textbook_total` | G4·G4-T 상한(차감) | 불변 |
| `app/core/rag.py::format_pinecone_hits` | 가드 초크포인트. rerank 결과만 받아 pool을 모름 | 불변 |
| `app/core/pipeline.py:1622,1642` | rerank 호출 2곳(일반·wider) | 불변(함수 내부 처리) |
| `app/core/query_decomposer.py::COMPLEXITY_PARAMS` | `rerank_top_n` | 불변 |

## 2. 목표와 범위

### 2.1 목표 (확정)

**해설서가 rerank 입력에 존재하면 최소 1건은 답변 근거에 포함한다.** 총 건수를 늘리지 않고 최하위 1건과 교체(swap)하므로 저작권 노출 상한은 그대로다.

### 2.2 저작권 경계 (확정)

- G4(권당 3)·G4-T(총량 6) **수치 불변**. 검토를 통과한 실적이 있는 유일한 수치이므로 재검토를 유발하지 않는다.
- 승격은 **최대 1건**. 현재 답변당 해설서 평균 0.5건 → 약 1건으로 오르지만 상한의 1/6 수준이다.
- 승격 후에도 가드는 그대로 뒤에서 적용된다(승격이 가드를 우회하지 않는다).

### 2.3 범위 밖 (명시적 제외)

| 항목 | 제외 이유 |
|------|------|
| 검색 미도달 4건(SIMPLE `top_k` 상향, 소스별 쿼터 검색) | 외부 전송량 증가 → 저작권 검토 범위가 달라짐. 별도 사이클 |
| `rerank_top_n` 상향 | 매 답변이 상한까지 차오르게 만드는 값. 노출 재검토 필요 |
| RRF 가중치 해설서 부스트 | 튜닝 근거가 없고 조작적 |
| qa 코퍼스 축소·가중치 하향 | qa 결과가 실제로 유효함이 실측됨 |
| 기존 적재분 재업로드 | 코퍼스 변경 없음 |

## 3. 요구사항

| ID | 요구사항 | 우선순위 | 근거 |
|----|----------|:---:|------|
| **FR-1** | 고정 평가셋 구축 — 질의 20~30건 + 분해 쿼리 고정, 지표(해설서 도달률·출처 분포·상한 발동률) 산출 | **High** | §1.5. 없으면 FR-2 효과 검증 불가 |
| **FR-2** | 다양성 승격 — rerank 결과에 해설서 0건이고 pool에 있으면 최하위 1건과 교체 *(설계 확정: 후보는 전체 랭킹 `2×top_n` 이내에서만, 교체 대상은 중복-출처의 최하위 — 단일 출처는 보호. design §3 D-2·D-3)* | **High** | §1.3 랭킹 탈락 3건 |
| **FR-3** | 승격 지점을 pool·결과를 함께 아는 단일 지점에 배치 | **High** | 호출부 2곳(일반·wider)에 복제하면 새는 경로 발생 |
| **FR-4** | 회귀 테스트 — 승격이 G4·G4-T를 우회하지 않음, 비해설서를 0건으로 만들지 않음, Cohere 미설정 폴백에서도 동작 | **High** | 가드 우회는 조용한 저작권 사고 |
| **FR-5** | 계측 — 승격 발동을 로그로 남겨 운영 중 빈도 확인 | Medium | fail-open 로직은 오작동이 조용하다 |
| **NFR-1** | 추가 LLM·외부 API 호출 0회 | High | pool 내 재배치라 순수 로컬 연산 |
| **NFR-2** | 승격 실패가 검색 전체를 막지 않음(fail-open) | High | 프로젝트 전반의 graceful degradation 관례 |
| **NFR-3** | `CLAUDE.md`·설계문서에 실측치와 경계 기록 | Medium | 다음 사람이 상한을 건드릴 때 근거가 필요 |

## 4. 대안 비교

| 대안 | 랭킹 탈락 3건 | 검색 미도달 4건 | 외부 전송량 | 노출 상한 | 채택 |
|------|:---:|:---:|:---:|:---:|:---:|
| **A. 다양성 승격(swap)** | 해소 | 미해소 | 불변 | 불변 | **채택** |
| B. `rerank_top_n` 상향 | 부분 | 부분 | 증가 | **증가** | 제외(§2.3) |
| C. 소스별 쿼터 검색 | 해소 | 해소 | **증가** | 불변 | 다음 사이클 |
| D. 해설서 RRF 부스트 | 부분 | 부분 | 불변 | 불변 | 제외(근거 부족) |
| E. 현상 유지 + 문서화 | — | — | 불변 | 불변 | 제외(사용자 결정) |

**A를 고른 이유**: 랭킹 탈락은 *이미 검색해 온 근거를 버리는* 낭비라 추가 비용 없이 회수할 수 있고, 총 건수를 유지하는 교체 방식이라 저작권 검토를 새로 받을 필요가 없다.

## 5. 설계 쟁점 (Design 단계에서 결정)

| ID | 쟁점 | 선택지 |
|----|------|--------|
| D-1 | 승격을 해설서 전용으로 둘지, 일반 규칙(소수 출처 보호)으로 둘지 | 전용은 단순하지만 `interpretation`·`regulation`도 같은 문제를 겪을 수 있다. 일반화하면 qa 슬롯이 여러 건 밀려 품질 위험 |
| D-2 | 교체 대상 선정 — 최하위 1건인가, 최다 출처(qa)의 최하위인가 | 후자가 다양성 목적에 더 맞지만 rerank 순위를 더 크게 흔든다 |
| D-3 | 승격 임계 — pool 내 해설서의 rerank 점수 하한을 둘지 | 하한이 없으면 무관한 해설서가 억지로 올라온다 |
| D-4 | `rerank_results` 내부 배치 vs 별도 함수 + pipeline 2곳 호출 | 내부 배치는 새지 않지만 함수 책임이 섞인다 |
| D-5 | 평가셋을 저장소에 커밋할지(질의문에 개인정보 없음 확인 필요) | CI 실행 가능 여부가 갈린다 |
