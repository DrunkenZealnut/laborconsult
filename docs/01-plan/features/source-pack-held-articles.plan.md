# source-pack-held-articles — Plan

> 자료팩 갱신(source-pack-refresh)에서 보류한 고용보험법 시행령 3조문의 계산식을 권위 있는 원문으로 확정해 적재하고, 같은 손실을 prepare 단계에서 자동으로 표시한다.

- 작성일: 2026-11-13
- 선행 사이클: source-pack-refresh(`docs/archive/2026-11/source-pack-refresh/`, PR #167·#168, 보고서 §6 '보류 3조문'·G1)
- 기준 main: `5360ca4`

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 고용보험법 시행령 제60조의2·제104조의8·제104조의15는 근로자·예술인·노무제공자 피보험 단위기간을 합산하는 계산식인데, 법제처 eflaw 텍스트의 상자 표에서 연산 기호 1개가 `?`(0x3F)로 빠져 있어 적재하지 못했다. 세 조문 모두 검색 코퍼스에 없다(10-09 자료팩도 이미지 때문에 보류). |
| **Solution** | 법제처 화면·조문 이미지·법령 PDF·관보 원문 중 기호를 확정할 수 있는 원문을 찾아 사람이 대조하고, 확정한 기호와 출처를 원장에 기록한 뒤 새 배치로 적재한다. 함께 prepare가 상자 표 안의 `?`를 `suspect_glyph`로 표시하게 해(G1) 다음 갱신에서 사람이 놓치지 않게 한다. |
| **Function UX Effect** | 다직종(근로자+예술인+노무제공자) 실업급여 수급요건·육아휴직급여 질문에서 시행령 원문이 검색 근거로 실린다. 틀린 식이 실릴 위험은 출처 대조로 막는다. |
| **Core Value** | "원문에 없는 문자를 추측해 채우지 않는다"를 지키면서 보류를 해소한다 — 확정 근거가 없으면 이번에도 보류가 정답이다. |

## 1. 배경

- 보류 3조문 상자 표의 공통 형태(review_20261112.md):
  - 제60조의2: `1 － 근로자로서의 피보험 단위기간 ÷ 180일 ? 예술인으로서의 피보험 단위기간 ÷ 9개월 + 노무제공자로서의 … ÷ 12개월`
  - 제104조의8: `1 － 예술인 … ÷ 9개월 ? 근로자 …`
  - 제104조의15: `1 － 노무제공자 … ÷ 12개월 ? 근로자 …`
- `?` 1개가 빠졌고, 앞쪽 `－`(U+FF0D)도 원래 기호가 맞는지(부등호 `≤` 등) 텍스트만으로는 알 수 없다 — **두 기호 모두 확정 대상**이다.
- 제104조의8·제104조의15의 다른 항(① 소득감소 30% 요건 등)은 온전하지만 조문 단위로 보류했다.
- fetch 원본 XML(`data/source_pack_refresh/20261112/`, gitignore)은 로컬에 남아 있지 않다 → 재수집 필요.
- 용어 정리: 선행 보고서의 **G1은 `suspect_glyph` 표시**이고 '보류 3조문'은 별도 항목이다. 이 사이클은 둘을 함께 다룬다(G1이 같은 결함의 재발 방지다).

## 2. 범위

### 포함
1. **원문 확보 조사(P1)** — 후보 경로를 실제로 열어 세 조문의 두 기호가 보이는지 확인한다.
   - (a) eflaw XML의 `<img>`·조문 이미지 URL(이미지 자체를 사람이 판독)
   - (b) law.go.kr 법령 화면 HTML(기호가 텍스트나 이미지 alt로 있는지)
   - (c) law.go.kr 법령 본문 PDF·HWP 다운로드
   - (d) 관보 원문(시행령 개정 2023.6.27 — 제60조의2 등 신설·개정본)
   - (e) `lawService` 다른 응답 형식(`type=HTML`·`JSON`)이 같은 손실을 갖는지
2. **본문 처리 방식 결정(Design에서 확정)** — 후보:
   - A. 법제처 텍스트 그대로 + 머리 주석(“상자 표의 `?`는 원문 이미지상 ‘＋’ — 출처 …”) — 본문 불변
   - B. `?`를 확정 기호로 치환하고 원장 `corrections`에 {조문, 원래 문자, 치환 문자, 출처 URL, sha256, 검토자} 기록
   - C. 기호가 온전한 다른 권위 원문(PDF·관보 텍스트)을 본문으로 채택
   - 판단 기준: 저장 본문이 인용 원문과 문자 단위로 대응해야 한다는 기존 규칙(고시 PDF 추출본 무가공 원칙)과 충돌하지 않는 것.
3. **적재** — `source_pack_refresh.py` 흐름(fetch → prepare → review → upload → ledger)으로 새 배치(`qpack_YYYYMMDD_`) 추가, BM25 재빌드·gz 커밋.
4. **G1 `suspect_glyph`** — prepare가 상자 표 줄의 `?`(그리고 상자 표 안의 고립된 U+FFFD)를 찾아 review 표에 열을 추가하고, 표시된 조문은 판정 칸에 출처 기록이 없으면 upload를 거절한다. 오프라인 테스트 추가(CI).

### 제외
- G3(다단 상자 표 청크 경계)·G4(fetch 게이트 공유)·G5(supersede 사전 확인)·G7(audit 전체 대조) — 별도 사이클.
- 계산기 산식 변경 — 계산기는 이 조문들을 현재 인용하지 않는다(필요성은 Check에서 확인만).
- 다른 법령 조문의 기호 손실 전수 조사 — G1 검출기를 기존 배치 원문에 1회 돌려 **건수만** 보고한다.

## 5. 위험·제약

| 위험 | 대응 |
|---|---|
| 모든 원문 경로가 같은 이미지·같은 손실 텍스트를 준다 | 이미지 판독(사람)도 권위 원문으로 인정할지 Design에서 결정. 아니면 R2로 보류 유지 |
| 법제처 API는 등록 IP에서만 동작(현 회선 미등록 가능성) | 웹 화면·PDF·관보는 키가 필요 없다. eflaw 재수집이 필요하면 등록 IP 확보 후 |
| laborlaw-v2는 프로덕션 NS — 적재 즉시 검색에 섞임 | upload 전 review 판정 필수, 원장 롤백 경로 확인(`source_pack_ledger.py rollback` dry-run) |
| 앞쪽 `－`가 사실 부등호라 식 의미가 바뀜 | 두 기호를 같은 출처로 동시에 확정. 하나만 확정되면 보류 |
| 키·OC 값 노출 | 출력·문서에 URL 쿼리의 `OC=`를 남기지 않는다 |

## P1 원문 확보 조사 결과 (2026-11-13)

조사 회선 119.66.172.82(법제처 API 인증 통과). 현행판 고용보험법 시행령(시행 2026-09-18, 대통령령 제36588호, lsiSeq 288717).

| 경로 | 결과 | 두 기호 |
|---|---|---|
| (a) eflaw XML `<img>` 조문 이미지 | 세 조문 각 1개(GIF). 사람 판독 | `－` = 빼기, `?` = **`≤`** |
| (b) law.go.kr 화면(`LSW/lsInfoR.do?lsiSeq=288717&efYd=20260918`) | 같은 이미지의 `alt`에 LaTeX 원식(`@@LATEX@@1- … \leq … + …@@/LATEX@@`) | (a)와 문자 단위 일치 |
| (c) PDF·HWP 다운로드 | 미조사 — (a)·(b)로 확정돼 생략 | — |
| (d) 관보 | 미조사 — 같은 이유 | — |
| (e) `lawService type=JSON` | XML과 같은 손실(`?`) | 판정 불가 |
| (e) `lawService type=HTML` | JS 껍데기만(본문 없음) | 판정 불가 |

확정 계산식(이미지·LaTeX 공통, 단위 표기는 원문대로):

- 제60조의2①: `1 - 근로자로서의 피보험 단위기간 ÷ 180일 ≤ 예술인으로서의 피보험 단위기간 ÷ 9개월 + 노무제공자로서의 피보험 단위기간 ÷ 12개월`
- 제104조의8: `1 - 예술인 … ÷ 9개월 ≤ 근로자 … ÷ 180일 + 노무제공자 … ÷ 12개월`
- 제104조의15: `1 - 노무제공자 … ÷ 12개월 ≤ 근로자 … ÷ 180일 + 예술인 … ÷ 9개월`

증거(이미지 sha256):

| 조문 | flSeq | 크기 | sha256 |
|---|---|---|---|
| 제60조의2 | 129419233 | 560×84 | `432854070afb4fe94fc15c09cf2b534f866597c170eff2648814b3b3b41e4350` |
| 제104조의8 | 129419251 | 586×72 | `5e329b07f98dee41a2c49096275789d55ac270a307e73b1c99e8c30f8ff6124a` |
| 제104조의15 | 102803845 | 549×68 | `922bd3fdd884015bb0fafb2ae90913debae1dbf43a749785ba6308a987c5385e` |

정정 사항: Plan §1의 가정("`－`도 `≤`일 수 있다")은 틀렸다 — `－`(U+FF0D)는 빼기로 맞고, 빠진 것은 `?` 자리의 `≤` 하나다. 즉 법제처 텍스트 변환이 `≤`(U+2264)만 `?`로 잃는다. G1은 이 손실(상자 표 줄의 `?`)을 그대로 겨냥하면 된다.

Design에 넘길 것:
- 처리 방식 A/B/C 판단 재료: 확정 근거가 법제처 자신(이미지 + 화면 LaTeX)이라 B(치환 + 원장 `corrections`에 flSeq·sha256·LaTeX 출처)가 출처 대응을 유지한다. C는 (c)·(d)를 새로 조사해야 해 불필요.
- (b) LaTeX `alt`는 기계로 읽을 수 있다 — fetch 단계에서 화면 HTML을 함께 받아 `?` 위치의 기호를 자동 대조하는 방안(사람 검토는 유지).
