# production-law-api-recovery — 프로덕션 법제처 조회 복구 + 주제별 근거 조문 보강 Plan

> 입력: 외부 엄격 점검(지식iN 주제별 30문항, 2026-10-06, 프로덕션, 평균 74.5점). 여기에 Vercel 런타임 로그·대화 메타데이터·법제처 현행판 대조를 더했다.
> 선행: claim-authority-and-assessor-facts(Check 94.4%, 미커밋). 겹치는 파일(`pipeline.py`의 `_consultation_allowed`, `prompts.py`)이 있어 이 사이클 착수 전에 커밋·머지하기를 권한다.
> 작성 2026-10-06 · 단계: Plan

## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 프로덕션(Vercel)은 법제처 OPEN API에 IP가 등록돼 있지 않다. 그래서 조문·판례·중앙노동위원회 판정문의 실시간 조회가 "사용자 정보 검증에 실패"로 막힌다. 답변에는 등록 IP(로컬)에서 돌린 실행이 캐시에 채워 둔 조문만 실린다(외부 점검 시간대 26%). 이 실패는 '미매칭'으로 집계돼 아무도 알아채지 못했다. 게다가 주제 체계에 모성보호·외국인 고용·파견·성희롱이 없다. 그 결과 육아휴직 질문에 연차 조문이, 외국인 고용 질문에 해고 조문이, 성희롱 질문에 괴롭힘 조문(5인 기준)이 실렸다. |
| **Solution** | ① 조문을 공급하는 경로를 복구한다. 고정 IP를 등록하거나(Vercel Static IPs), 등록 IP 머신이 핵심 노동법령 전 조문을 캐시에 미리 채운다(다음 시행일까지 유효). ② 조회 결과를 정상·미발견·오류·차단으로 나눠 기록하고, 폴백 감시에 알림 조건을 더한다. ③ 주제 체계에 모성보호·성희롱·외국인 고용·파견을 넣고, 공식 원문으로 확인한 조문을 기본 조문으로 등록한다. |
| **Function UX Effect** | 육아휴직·배우자 출산휴가·가족돌봄·임신기 단축·외국인 사업장 변경·파견·성희롱 질문에 직접 적용되는 조문이 근거로 실린다. "참고 자료에서 확인되지 않습니다" 대신 조문에 근거한 결론이 나온다. |
| **Core Value** | 답변 품질의 하한은 모델보다 **컨텍스트에 무엇이 실리느냐**가 정한다. 이번 실측에서 프로덕션과 로컬 평가는 사실상 서로 다른 시스템이었다. 로컬 점수(3차 92.8, E1 88.8)는 프로덕션(74.5)을 대변하지 못했다. 같은 조건에서 재는 것이 개선의 출발점이다. |

**목표 지표:**
- 프로덕션 실사용 대화의 조문 요청 성공 95% 이상(존재하지 않는 조문 요청 제외)
- 인증 실패가 오류로 집계되고 알림이 동작함
- 외부 점검 30문항을 프로덕션에서 다시 돌렸을 때 "확인되지 않습니다" 유보가 16개 → 5개 이하이고, 1·2·3·6·8번 컨텍스트에 직접 조문이 실림

## 1. 실측 (2026-10-06)

### 1.1 프로덕션 법제처 조회

| 근거 | 결과 |
|---|---|
| Vercel 런타임 로그 — 외부 점검 시간대(10:45~11:30 KST) | 인증 실패("사용자 정보 검증에 실패") 45건, 서킷 열림 32건, **법령명 미매칭 0건**. 조문 요청 185건 중 성공 49건(26%) |
| Vercel 런타임 로그 — 10-04(Claude 답변·의도분석, PR #98 이전 `v3` 캐시) | 같은 인증 실패. 모델 전환·eflaw 전환과 무관하다 |
| 실사용 대화 `metadata.law_api`(10-05~06 합계) | 요청 346건 중 성공 111건(32%), **error 0건**. 인증 실패가 `miss`로 집계된다 |

- **실패가 가려지는 경로:**
  - `fetch_law_root`는 `<Response>` 루트를 예외로 올린다.
  - 그런데 `fetch_article`의 `except Exception`이 그 예외를 삼키고 None을 돌려준다.
  - `fetch_relevant_articles`는 그 None을 `miss`로 센다.
  - 서킷이 열린 30초 동안의 조회는 로그 없이 None이 된다.
  - 로그의 실패 문구에는 '조의N'이 빠진다(`제%d조`). 그래서 제19조의2 실패가 "제19조"로 찍힌다.
- **성공분은 모두 L2 캐시(Supabase `law_article_cache`) 적중이다.**
  - L2는 성공한 L3(실호출)만 채우는데, L3가 성공하는 곳은 등록 IP(로컬)뿐이다.
  - `v4` 조문 캐시는 다음 KST 자정에 만료된다(`_article_expiry`).
  - 결국 **프로덕션의 조문 컨텍스트는 그날 로컬에서 평가를 돌렸는지에 좌우된다.**
- **판례·판정문도 같은 키를 쓴다.** 판례 폴백(`search_precedent_multi`·`fetch_precedent_details`·`fetch_relevant_precedents`)과 중앙노동위원회 판정문(`fetch_relevant_nlrc`)도 같은 영향을 받을 것으로 본다. 아직 따로 실측하지 않았다.
- **로컬 평가는 이 장애를 겪지 않았다.** 3차(10-05)와 E1(10-06)은 등록 IP에서 돌았다. 2차 외부평가(10-04)는 프로덕션에서 같은 장애를 겪은 채로 채점됐다.

## 2. 범위

### P0-1 조문 공급 경로 복구 (방식 결정 필요)

| 방식 | 내용 | 장점 | 한계 |
|---|---|---|---|
| **A. 고정 IP 등록** | Vercel Static IPs(프로젝트 기본 리전)를 켜고 그 IP를 법제처 OPEN API 신청 정보에 등록한다 | 코드 변경이 없고, 실시간 현행판을 쓴다. 판례·판정문도 함께 살아난다 | 유료 옵션일 가능성(플랜·비용 확인 필요). 법제처가 해외 리전 IP 등록을 받는지 확인 필요 |
| **B. 고정 IP 프록시** | 고정 IP 서버가 법제처 호출만 중계한다 | 판례·판정문까지 복구된다 | 서버 운영·가용성·인증 부담 |
| **C. 조문 캐시 예열** | 등록 IP 머신(현재 로컬 맥)이 매일 핵심 노동법령 **전 조문**을 Supabase 캐시에 미리 채운다 | 비용 0, 결정 없이 바로 시작할 수 있다. A를 택해도 장애 완충으로 쓸 수 있다 | 판례·판정문은 예열할 수 없다(질의가 열려 있음). 예열 목록 밖 법령은 여전히 실패한다. 맥이 판본 경계에 켜져 있어야 한다 |
| **D. 조문 미러** | 법령 원문(저작권 비보호)을 판본별로 저장소에 커밋하고, 실행 시 날짜로 판본을 고른다 | 런타임 외부 의존이 0이다 | 구현량이 가장 크고, 개정마다 커밋·배포가 필요하다 |

**권고: C를 먼저 하고, A는 비용을 확인한 뒤 결정한다.** C는 이번 장애가 낸 피해(조문 부재)의 대부분을 바로 줄이고, A와 함께 써도 버릴 것이 없다. D는 A와 C가 둘 다 어려울 때 검토한다.

C의 요건(설계 단계에서 확정):
- **실행:** 등록 IP 머신에서 launchd로 매일 KST 00:10에 실행하고, 실패하면 재시도한다. 마지막 성공 시각을 기록한다.
- **대상:** `check_law_freshness.py`의 17종에, 주제 체계가 쓰는 법령(남녀고용평등법·외국인고용법·파견법·기간제법 등)을 더한다.
- **방법:** 법령마다 `fetch_law_root` 1회로 전체를 받아 조문·조의N·항 단위 키를 모두 쓴다. 텍스트는 프로덕션 `_extract_article`과 **같은 함수**로 만든다.
- **만료:** 법령별 **다음 시행 예정일 KST 자정**으로 한다(없으면 상한 N일). 맥이 꺼져 있어도 판본 경계 전까지 유지되고, 경계에서는 끊겨 옛 판본을 내지 않는다. 지금의 '자정 만료'와 같은 안전성이다.
- **캐시 키 정규화:** 같은 조문인데 약칭·가운뎃점 이형이 다른 키가 된다(로그 실측: `남녀고용평등법_19`와 정식명 키). 정식명으로 통일하고 키 세대를 `v5`로 올린다. 예열 키와 프로덕션 조회 키는 같은 함수로 만든다.

### P0-2 관측·알림

- 조문·판례·판정문 조회 결과를 **성공·미발견·오류(인증·네트워크)·차단(서킷)**으로 나눠 `stats`와 `metadata.law_api`에 남긴다. 인증 오류는 따로 표시한다.
- 실패 로그에 '조의N'과 항을 남긴다.
- 폴백 감시(`check_llm_fallback.py`, 6시간 주기)에 법령 조회 조건을 더한다. 최근 실사용 N건에서 인증 오류가 있거나 조문 성공률이 기준 미만이면 실패 메일을 보낸다.
- C를 택하면 예열 작업의 마지막 성공 시각이 36시간 이상 지났을 때도 알린다.

### P0-3 주제 체계 보강

- `ANALYZE_TOOL`의 `consultation_topic` enum, 분석 프롬프트의 주제 키워드, `TOPIC_SEARCH_CONFIG`에 다음 주제를 추가한다.
  - 모성보호: 육아휴직·출산전후휴가·배우자 출산휴가·육아기 근로시간 단축·가족돌봄·임신 중 보호
  - 직장내성희롱
  - 외국인 고용
  - 파견
- 기본 조문은 공식 원문으로 확인한 것만 넣는다(1.2 표의 '필요한 조문'). 의도분석이 '조의N'을 빠뜨려도 주제 기본 조문이 그 자리를 채운다.
- 성희롱 질문의 2-2 경로를 바꾼다. claim-authority 사이클은 "성희롱이면 2-2를 생략"하는데, 이를 "성희롱 주제로 2-2"로 바꿔 괴롭힘 조문 대신 남녀고용평등법 조문을 싣는다.
- 회귀 테스트로 고정할 것: enum과 `TOPIC_SEARCH_CONFIG` 키의 일치, 기본 조문의 원문 대조, 새 주제가 그래프·카테고리 매핑에서 빠지지 않는지.

### P0-4 평가 환경 일치

- 캐시 전용 모드(`LAW_API_LIVE=off`)를 둔다. 로컬에서 프로덕션 조건을 재현하는 용도이고, `run_eval.py`에 옵션으로 연결한다.
- 완료 검증은 프로덕션에서 한다. 외부 점검 30문항을 프로덕션에서 다시 돌린다.

## 3. 범위 밖 (다음 사이클 후보)

- 답변 모델(gpt-6-sol)의 간결·유보 성향. 컨텍스트를 복구한 뒤 다시 재고, 그래도 남으면 프롬프트 조정을 검토한다.
- 성희롱 적용 범위·모성보호 사실 블록(`rule_facts`). 조문이 실리면 우선순위가 낮아지므로 재측정 뒤 판단한다.
- "AI 답변 사절" 질문의 처리 정책과 면책 고지 중복(30번).
- 외부 점검 30문항의 보관. 원문 대신 사실관계 요약으로 fixture를 만든다.
- 점검 대화 3건이 지식iN 원문이 담긴 채 공개 게시판에 노출된 문제(정리 여부는 사용자 결정).

## 4. 위험

## 5. 완료 조건

1. 프로덕션 실사용 3일 동안 조문 요청 성공이 95% 이상이다(존재하지 않는 조문 요청 제외). 인증 오류가 나면 오류로 집계된다.
2. 강제 실패 테스트(잘못된 키, 서킷 열림)에서 오류와 차단이 따로 집계되고, 감시가 알린다.
3. 외부 점검 30문항을 프로덕션에서 다시 돌렸을 때 유보 표현이 16개 → 5개 이하이고, 1·2·3·6·8번 컨텍스트에 직접 조문이 실린다.
4. 기존 오프라인 스위트와 평가가 회귀하지 않는다.
