# 법률 기준 갱신 설계

정책 승인: 2026-09-17 사용자 선택 1 — 자동 검색은 후보 생성까지만, 적용은 관리자 승인 후.

## 범위

기존 FastAPI 관리자 인증, Supabase laborconsult 스키마, Pinecone laborlaw-v2를 재사용한다.
법률 검색은 Pinecone만 사용한다. 검색 결과 자체는 최신성/정확성의 보증이 아니다.
공식 원문 URL이 메타데이터에 있는 법령·판례·행정해석·고시만 승인 근거로 허용한다.
교재·상담 및 출처 불명 자료는 승인할 수 없다. 외부 원문 수집/업로드는 기존 별도 수집 절차를 따른다.

## 흐름

정기/수동 Pinecone 검색 → 중복 제거된 검토 후보 → 관리자가 값·시행구간·인용구절 입력 →
승인 시 Pinecone ID 재조회 및 내용 해시 확인 → 승인된 시행구간별 버전 조회 → 계산 결과에 버전 기록.
관리자는 수동 후보 등록, 대기 후보 수정, 반려, 승인 취소가 가능하다. 모든 변경은 원자적 이력 저장.

수치 파라미터(최저시급, 보험료율/기준액, 출산급여 상한)만 허용 목록을 통해 실행한다.
판례/지침에 따른 산식·자격 변경은 코드 검토 항목으로 남으며 자동 코드 생성이나 실행은 하지 않는다.
같은 파라미터에 승인된 시행기간이 겹치면 거부한다. 기존 승인을 취소한 뒤 후속 버전을 승인한다.
승인 취소도 이력에 남고 이전 버전이 자동 부활하지 않는다. 필요하면 이전 값으로 새 후보를 승인한다.

## 저장과 동시성

Supabase 단일 registry 문서에 후보/검색기록을 저장한다. 정수 revision 비교 후 RPC에서 행을 잠그고
문서 저장과 append-only 감사 이벤트를 같은 트랜잭션으로 처리한다. 충돌은 HTTP 409로 반환한다.
정기 검색은 실패/0건을 구분해 기록한다. 같은 문서 ID·내용·주제는 재등록하지 않는다.
검색 후보는 문서 변경 알림이며 법 개정 확정 판정이 아니다. 상위 검색 결과만으로 누락 없는 감시는 보장하지 않는다.

## 계산기 연결

LEGAL_RULES_ENABLED=true인 경우 승인 저장소를 읽고 reference_date에 해당하는 버전을 사용한다.
동일 연도 중간 변경을 위해 YYYY-MM-DD를 필수로 받는다. 연도만 있는 요청은 날짜 확인을 반환한다.
관리 대상 값이 없거나 저장소가 실패하면 계산 보류를 반환한다. 하드코딩 값으로 폴백하지 않는다.
ContextVar로 요청 단위 읽기 스냅샷을 전달해 병렬 요청과 기존 상수가 섞이지 않게 한다.
모드 off는 마이그레이션 전 기존 동작이며 갱신 적용 중이라고 표시하지 않는다.
이번 갱신 기능은 기존 28개 계산기의 법적 적합성을 승인하는 기능이 아니다. 기존 감사 결함은 별도 미해결 목록으로 유지한다.

## 운영

GitHub Actions 주간 검색(월요일 KST) + workflow_dispatch, 저장소 변수로 명시적으로 활성화한다.
서버 내부 무한 루프를 사용하지 않는다. 관리자 페이지는 한 주제씩 즉시 검색한다.
실제 DB DDL 적용, GitHub secrets 설정, 운영 모드 전환/배포는 운영 단계로 구분한다.
현재 공유 비밀번호 인증의 감사 주체는 admin 세션 식별자이며 개별 사용자 실명 인증을 뜻하지 않는다.

## 검증

원문 부재/변경, 비공식 출처, 승인 전/후, 시행일 경계, 기간 중복, 반려/취소, 동시 수정,
검색 재실행, 검색 장애, 날짜 미입력, 스냅샷 간 격리, 권한 없는 API 접근, UI HTML 주입을 검증한다.
외부 서비스 없이 테스트하고, 운영 DB를 자동 변경하지 않는다.
