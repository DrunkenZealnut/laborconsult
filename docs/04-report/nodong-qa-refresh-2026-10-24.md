## 3. A/B/C 실행 현황 — C 평가 미완료

기존 60문항 + 지식iN 20문항 + 개정·과거 사건·경계 20문항, 중복 없는 **100문항을 각 조건 1회** 시도했다. A/B는 각 100개, C는 91개 답변만 생성됐다. 권장된 3회 반복은 하지 않았으므로 모델 내 변동성과 작은 차이에 대한 통계적 결론을 낼 수 없다.

공통 코드 `79f9c2490a567a07be6b29fd7c8719bac0b908ce`, 계산기·프롬프트·검색 설정을 고정했다. 유효 법령 캐시 7,476행, 모델 설정 revision 12, 법률 기준 registry revision 153을 동결했다. 실제 생성 모델은 조건별 결과에 기록했고, 법령 실시간 조회·운영 DB 저장·법령 캐시 쓰기를 차단했다. 전체 실행의 차단된 DB 쓰기 시도는 0건이다. Q3 시점 필터는 모든 조건에 같으므로 Q3 단독 효과 실험은 아니다. C−B에는 신규·답변 갱신과 미답변 안내 정리·메타데이터 보강 효과가 함께 포함된다.

메모리 보완은 배포 구현에 적용하고 A/B/C는 위 공통 코드를 유지했다. 보완 전후 전체 로드 코퍼스, 문서별 단어 빈도, IDF, 문서 길이, 평균 길이의 해시가 같음을 검증해 검색값·순위 계산이 변하지 않음을 확인했다. 표본 8개 실제 검색 결과·점수도 동일했다.

**C의 실패 9건에는 OpenAI 잔액 소진(`credit_balance_exhausted`), Claude 설정 사용 한도, Gemini 선불 잔액 소진이 기록됐다.** 실제 생성 모델은 A/B 각 100개, C 91개 모두 `gpt-6-sol`이며 답변 잘림은 없었다. 실패 문항은 qna-13, qna-17, qna-14, qna-18, qna-15, qna-19, qna-08, qna-16, qna-20다. **C의 74/100은 공급자 장애를 포함한 원시 관측값이므로 갱신으로 품질이 하락했다는 뜻도, 비교 실험이 완료됐다는 뜻도 아니다.** 크레딧·한도 복구 후 공통 코드와 동결 조건을 유지해 재평가해야 한다. 실패 기록은 삭제하지 않았다. 실패 구간의 qna-12는 답변은 나왔지만 일반 지식 경로 안내가 붙었으므로, 실패 9건만 골라 교체하기보다 경계 20문항 전체를 재실행 대상으로 남겼다.

**자동 형식 통과율은 법률 정확도가 아니다.** 숫자 검사는 단위 배수를 정규화한 숫자의 존재만 확인하며 그 숫자가 올바른 항목·조건에 쓰였는지 판정하지 않는다. 지연은 이번 병렬 실행에서 관측한 값이다. 요금은 반환된 토큰 사용량에 표준 요율을 적용한 추정이며 기타 공급자·미반환 사용량·재정렬·Pinecone·캐시 쓰기 가산·계정 차이를 제외한다. [OpenAI 답변 모델 요금](https://developers.openai.com/api/docs/models/gpt-6-sol).

위 C 비교는 실패 9건을 포함한 원시 실행 기록이다. 품질 효과의 결론이나 배포 통과 근거로 사용하지 않는다.

C−B의 나머지 자동 미통과 6건을 읽었다. `wage-05`, `hours-02`, `kin-02`, `kin-12`는 법조문 문자열 검사의 미충족, `retirement-02`, `risk-06`은 분류 주제 불일치로 기록됐다. 특히 `wage-05`는 B가 최종 금액을 보류한 반면 C가 기대값 144,000원을 제시했는데도 형식 점수는 낮아졌다. 동일 법률명의 생략·띄어쓰기 등으로 인한 미검출 가능성이 있어 이를 법률 오류로 단정하지 않는다. 평가 기준을 사후 변경해 점수를 올리지 않았다.

생성된 경계 답변 11개를 작성자가 읽었으며, `qna-04`의 과거 상한·지급액 미응답과 `qna-05`, `qna-07`의 개정 경과조치 확인 유보를 사람 검토 우선 항목으로 남겼다. 이는 작성자의 분류이며 독립적인 법률 채점이 아니다.

이 목록은 사람 검토의 우선순위이며 법률 오류의 확정 목록이 아니다. 예를 들어 qna-04의 갱신 전 답변은 과거 육아휴직 상한·지급액을 제시하지 않고 계산을 보류했는데도 형식 검사에는 통과했다. 현재·과거 법률의 적용, 금액 의미, 유보의 적절성은 별도 확인해야 한다.

조건명을 문항마다 가린 `blinded-review.html`, 정답 기준과 공식 근거, 답변 유무를 표시한 300개 빈 평가 행의 `human-review-template.json`을 비공개 산출물로 만들었다. **사람의 법률·계산·유용성 평가는 아직 하지 않았고 실제 사용자 만족도 자료도 없다. 정확도나 만족도가 향상됐다고 발표할 근거는 아직 없다.**

## 4. 구현과 코드 검증

- 수집 재개·내용 해시·문서별 롤백, Dense/BM25 provenance, 시점 필터와 질문-only 표시, 내부 검색 기여 추적 구현.
- 세션·대화·버전에 묶인 서명 토큰, 노출 후 투표, 중복 멱등 처리, 변경 간격, 선택형 부정 사유, 관리자 분모·버전별 집계 구현.
- 피드백 테이블/RPC는 `laborconsult` 스키마의 서비스 역할 전용. 공개 쓰기 권한을 늘리지 않았다. `QA_QUALITY_ENABLED` 기본값은 꺼짐.
- 신선한 맥락의 코드 리뷰 1회에서 채팅 스크립트 구문, 관리자 라우트 순서, 후속 갱신의 명시적 버전 보존, 미배포 변경분 누락 및 감사 CLI의 무동작 문제를 발견했다. 각 문제를 실패 테스트로 재현한 뒤 수정했다.
- 관련 48개 테스트 통과. 실제 CI 워크플로의 30개 검증 단계 전부 통과했으며 실제 폐기용 PostgreSQL17의 권한·트랜잭션 검증, HTML 파싱 후 전체 inline JS 컴파일을 포함한다. 기존 환경 의존 skip은 로그에 남겼다.
- 리뷰 수정 전후의 이번 후보 manifest, BM25 전체 비압축 내용, legacy 버전 맵이 같음을 검증했다. 수정은 이번 평가의 생성 파이프라인과 질문·코퍼스 내용을 바꾸지 않았다.

API 사용 가능 상태 복구와 경계 20문항 재실행이 우선 필요하다. 계획 Q5의 **새 중대한 법률·금액 오류 0건, 필수 경계 정답, 회귀 원인 해결**은 사람 검토 후 판정한다. 자동 점수만으로 `gate.json.passed=true`를 만들지 않았다. 운영 반영 시 검증된 후보 버전, 코드/BM25/legacy 버전 맵/release 메타데이터를 함께 검토하고 실행·복구 절차를 따른다.
