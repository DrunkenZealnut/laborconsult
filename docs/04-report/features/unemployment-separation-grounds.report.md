## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | 실업급여는 실사용 질문 1위(139건 중 32건)이고, 그중 이직사유 질문이 21건이다. 판단 기준인 시행규칙 별표 2는 공공 자료 0건이고 예열 대상도 아니어서, 이직사유 답변 21건 중 10건(48%)이 근거 부재로 유보됐다. |
| **Solution** | 별표 2·별표 1의2와 시행규칙 제101조를 법제처 원문 그대로 받아 앵커로 고정했다. 이직 단서가 있는 실업급여 질문에만 13개 사유 요건을 담은 동반 규칙 블록(약 2,020자, 원문 앵커 45개)을 붙이고, 고용보험법 제58조를 키워드 규칙으로 싣는다. |
| **Function/UX Effect** | 측정(합성 fixture 19건, 실사용 30+15건, 280답변)에서 블록 발동은 양성 100%, 비이직 0건이었다. 제58조는 강단서 질문 100%에서 실렸고, 기대 사유 적중은 92%(24/26), 금지 문구는 0건이었다. 이직사유 요건 관련 유보는 5·3건에서 0·0건으로 줄었다. 다만 전체 근거 부재 유보는 평균 0.235에서 0.14로 줄어 목표(0.117 이하)에 미달했다. |
| **Core Value** | 근거가 없으면 단정하지 않는다는 원칙을 유지하면서, 수요 1위 주제의 판단 기준을 컨텍스트에 결정적으로 공급했다. 별표 개정은 앵커 대조와 현행판 점검이 잡는다. 지금까지 맞던 수치가 학습 지식 덕분이었던 위험을 제거했다. |

## 6. Lessons Learned & Retrospective

### 6.1 What Went Well (Keep)

- 설계 단계에서 design-validator를 거쳐 결정과 측정 정의를 고쳤다. 구현 뒤 Check가 설계와 축자 일치를 확인하는 데 걸린 시간이 짧았다.
- 저장본 현행 대조(D8)가 첫 실행에서 실제 낡은 저장본(제109조)을 잡았다.
- 판정을 `separation_signals` 한 모듈로 뗐다. 2-1 규칙과 블록이 같은 함수를 쓰고, U12가 import 경계를 고정한다.
- 측정 관문을 실패 항목까지 그대로 보고했다. 관문 정의를 결과 뒤에 바꾸지 않았다.

### 6.2 What Needs Improvement (Problem)

- 실행 항목 여섯 개가 전부 법제처 등록 IP 하나에 걸려 있었다. 등록 회선 IP가 유동이라 재할당마다 같은 장애가 날 수 있다. 등록 화면에서만 실체가 드러났다.
- 유보 관문 정규식이 쟁점을 가리지 않아 범위 밖 유보까지 셌다. 목표 미달의 상당 부분이 블록의 범위 밖 쟁점에서 나왔다.
- 설계 수치(강단서 10건, 별표 단위 4개, K 2회)가 fixture와 실데이터 확정 전에 적혀, 구현 뒤 여러 차례 정정했다.
- 메타 대조를 브랜치 SHA로 할 수 없었다. 미커밋 상태에서 측정을 돌려 트리 지문으로 대체했다.

### 6.3 What to Try Next (Try)

- 다음 설계의 유보 관문은 "해당 쟁점 문장만"으로 처음부터 정의한다.
- 설계 수치는 fixture와 실데이터가 확정된 뒤 실측값으로 다시 적는다.
- 외부 전제(법제처 등록 회선)가 필요한 실행은 사이클 시작 때 목록으로 만들고, 고정 IP 호스트로 예열하는 방안을 먼저 정한다.
