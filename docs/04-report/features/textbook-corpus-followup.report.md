## Executive Summary

### 1.1 4관점 가치 전달

| 관점 | 내용 |
|------|------|
| **Problem** | 해설서가 2권 → 3권이 되면서 답변 1건당 저작물 노출 상한이 **6청크 → 9청크로 서적 등록만으로 조용히 상승**했다. 권당 상한(`_cap_by_book`)만 있고 총량 예산이 없어, 서적을 추가할 때마다 저작권 검토 없이 노출 총량이 선형 증가하는 구조였다. 동시에 「개별 노동법실무」의 `title`이 전체 85개 실무테마 중 41%(1~35)만 적재됐음을 밝히지 않아, 미수록 주제 질문에도 그 서명이 인용될 수 있었다. 코퍼스에는 표 구분선·OCR 반복 같은 무의미 청크가 검색 대상으로 남아 있었고, 업로드 스크립트는 `--all` 중간 실패와 전역 `--allow-large-prune`으로 복구 불가능한 대량 삭제를 허용했다 |
| **Solution** | ① 해설서 **총량 상한(G4-T, 6)**을 `_cap_by_book`과 같은 초크포인트(`format_pinecone_hits`)에 권당 상한 다음 순서로 추가. ② `title`에 수록 범위(`1권 — 실무테마 1~35`)를 명시해 G3(서명 표기)가 실제 범위를 말하게 함. ③ 단일 의미비율 임계값 대신 **구조 판정**(표 구분선·토큰 반복 축약 후 재판정)으로 청크 신호 게이트를 도입 — 판례 표(의미비 0.309)를 잡음(0.266)과 분리. ④ 3권 전량 청킹을 업로드 루프보다 앞으로 옮기고, `--allow-large-prune`을 서적 단일 실행에서만 허용하도록 좁힘 |
| **Function UX Effect** | 사용자가 보는 답변에서 해설서 근거 총량이 6청크로 고정되고, 출처가 실제 수록 범위를 드러낸다. 표 구분선·OCR 잔해가 출처 카드에 뜨는 일이 사라졌다(gaebyeol 47건 축소 확인). 프리뷰 실측: G4가 실제 요청에서 발동(`gaebyeol 4→3`)했고, 실코퍼스 재현으로 G4-T 발동(`12→9→6`, 2권 생존)도 확인됨 |
| **Core Value** | 서적이 늘어도 저작물 노출이 늘지 않는 **구조적 상한**을 세우고, 인용이 코퍼스의 실제 수록 범위를 벗어나지 않게 했다. 이 사이클 자체가 `CLAUDE.md`가 경고하는 "Match Rate 90% 초과도 배포 신호가 아니다"를 다시 증명했다 — 97.8% 뒤에서 설계 대조로는 원리적으로 못 잡는 결함 9건(가드 우회·죽은 회귀·거짓 근거·섹션 소실 등)이 후속 코드리뷰로 발견·수정됐다 |

| **판정↔집계 분리** | 판정은 `chunk_section()`, 집계·게이트는 `build_chunks()` | Gap 분석에서 설계 문구(§4.5)가 반대로 적혀 있음을 발견 — **구현이 옳아** 설계를 수정(G-1) |

### 2.3 v0.2 정정 — §11 프리뷰 검증 반영 (2026-08-18, 이번 세션)

설계 문서 §2.1의 천장표(`min(rerank_top_n, 3×서적수)`)가 **rerank 직후 기준**이라는 점을 명시하지 않고 있었다. 실제로 `format_pinecone_hits`는 그 뒤 Self-RAG 필터를 한 번 더 통과한 결과를 받는다. 프리뷰 실측(§5)에서 COMPLEX 일반 경로 입력이 `7→6`·`7→5`로 줄어드는 것을 확인해, 3권 체제 COMPLEX 자연 질의에서는 G4-T가 사실상 발동하지 않는다는 사실을 §2.1 각주·§10 리스크·§11 신설 섹션에 반영했다. **상한 자체가 무용하다는 뜻은 아니다** — 서적 추가나 `rerank_top_n` 상향 시 이 여유는 사라진다.

### 5.3 G4-T — 자연 질의 미도달, 실코퍼스 재현으로 실동작 확인

해설서 편중어(`근기법` 96배 등)로 유도한 COMPLEX 질의 4회 전부 총량 6에 미도달(원인: Self-RAG가 rerank 뒤에서 재차 축소, 실측 `7→6`·`7→5`). 실코퍼스 벡터로 재현:

```
입력: 3권 × 4건 = 12건
G4  적용 → 9건 ({'juhae3':1,'win':1,'gaebyeol':1} 차감)
G4-T 적용 → 6건 ({'gaebyeol':3} 차감)
결과: juhae3 3건 + win 3건 (2권 생존) — 정순 적용 효과 실측 확인
LLM 컨텍스트 블록 6건 = meta 6건 (인용 화이트리스트 동기화 확인)
```

역순이었다면 상위 1권이 6슬롯을 독점해 3건/1권만 남았을 구성이다.

### 5.4 미해결 관측 (이번 범위 밖, §6.4 후속 과제로 이관)

- `/api/board/recent`가 `total: 0` — 프리뷰 대화 미노출은 확인했으나 게시판이 비어 있어 **G-B 합성 판정의 양성 검증은 되지 않음**(fail-open이라 꺼져 있어도 같은 결과)
- 프리뷰 로그에 `ADMIN_JWT_SECRET 미설정 → ADMIN_PASSWORD 재사용` 경고(환경변수, 이 사이클 무관)

## 11. 최종 결론

### 11.1 성과

1. **구조적 저작권 상한 확립** — 서적 수 증가와 무관한 총량 6청크 고정, 프리뷰 실배포에서 실동작 확인(§5)
2. **수록 범위 정직화** — title이 실제 코퍼스 범위를 반영, 미수록 주제에 무관한 서명 인용 경로 차단
3. **코퍼스 품질 개선** — 구조 기반 신호 게이트로 47건 정리, 판례 표 등 유용 콘텐츠 오탐 0건
4. **업로드 운영 안전성** — 전량 청킹 선행 + prune 서적 단일 한정으로 복구 불가능한 대량 삭제 경로 차단
5. **Match Rate의 한계를 다시 증명** — 97.8% 뒤에서 가드 우회·죽은 회귀·거짓 근거·섹션 소실 등 9건을 설계 무관 리뷰로 추가 발견·수정
6. **배포 전 실배포 검증** — Check 단계가 보지 못하는 콜드 스타트·Self-RAG 상호작용을 Vercel Preview 실측으로 확인, 문서 오류(천장 공식) 사후 발견·정정

### 11.2 수치

- **Match Rate**: 97.8% (44/45)
- **구현 규모**: 8개 파일, 1,189줄 추가 / 14줄 삭제(커밋분) + 5개 파일, 75줄 추가 / 7줄 삭제(문서 정정, 미커밋)
- **테스트 커버**: 216개 검증(T22 34개 포함), 전체 통과
- **후속 코드리뷰**: 15건 발견 → 9건 실결함 수정, 6건 기록/범위 밖
- **프리뷰 검증**: BM25 66,307건 확인, G4·G4-T 실동작 확인(자연 질의 + 실코퍼스 재현)

### 11.3 위험도

**낮음**
- 핵심 변경(G4-T)은 기존 G4 위에 순수 차감으로 덧씌워짐 — 비해설서 경로 무영향
- 3자 일치(Pinecone·원장·BM25)로 데이터 정합 확인
- 실배포 프리뷰에서 두 가드 모두 발동 확인(자연 발생 + 강제 재현)
- 미커밋 항목(§6)은 코드 동작 변경이 없는 문서·주석 정정
