## 구현 중 판단한 사항과 비용

아래는 작업 기록의 모든 `Ruling:` 항목을 결정 순서대로 정리한 것이다.

1. 직접 구현하고 릴리스마다 독립 리뷰를 받았다. 자동 실행 권한과 실행 스킬에 따른 방식이다. 비용: 작업별 중간 리뷰 횟수는 줄며 회귀와 릴리스 리뷰로 보완한다.
2. 승인된 C0/C4a 식별자를 유지하고 실행 지침을 직접 생성했다. 스킬 도구가 숫자 Task 제목만 해석하기 때문이다. 비용: 자동 도구의 형식 일치를 대신 점검해야 한다.
3. 관리형 독립 작업 디렉터리를 유지하고 커밋 전에 기능 브랜치를 만들었다. 비용: 별도 브랜치와 작업 디렉터리가 남지만 원본 변경 사항과 분리된다.
4. 실패 회귀는 해당 모듈 착수 때 추가하고 최초 오답 재현은 별도 보존했다. 비용: 미래 모듈의 실패 테스트는 그 릴리스 전까지 CI에 들어가지 않는다.
5. 다른 작업에서 작성한 미공개 계획을 구현 PR에 넣지 않았다. 확정 계획은 원본 저장소에 남겼다. 비용: 원본 계획과 공개 구현 보고서의 저장 위치가 다르다.
6. 지급 주기 미확인과 평균임금 불명확성은 의존 계산만 보류했다. 직접 호출의 생략 주기는 기존 월 단위 계약을 유지하고, 분석기는 미확인을 보존한다. 상여 중복은 출처 ID·명시 포함액으로 판단한다. 비용: 추가 사실 확인이 필요한 사례가 있다.
7. 명시 출산휴가는 사용 기간·회사·보험 자격이 확인된 전체 사용만 계산한다. 부분·분할·연도 경계는 보류하고 기존 유형 생략 비교는 유지한다. 비용: 일부 휴가 사례에 추가 입력 또는 별도 설계가 필요하다.
8. P0 종료는 릴리스별 전후 각 2회 평가, 최종 공통 회귀, 변이 7개로 판단했다. 문서 커밋만 바뀌었다고 모든 과거 답변을 재생성하지 않았다. 비용: 최종 P0 HEAD에서 전체 26문항을 다시 실행한 통합 배치는 없다. 공유 Pinecone/L2는 독점 고정하지 않았다.
9. 파생 원금은 확인된 단일 정산월의 기초를 사용한다. 다른 조건의 과거 월은 확정 의무액 또는 별도 산정이 필요하다. 명시 209시간을 보존하고 추정 월액은 이자 채권에서 제외한다. 비용: 복잡한 월별 이력은 사전 정리가 필요하다.
10. 근로자성·권리·충당·상계·세후→세전·상여 지급기일·휴일 시간 구간·과거 조건을 추측하지 않는다. 비용: 다툼 또는 누락 사실은 사용자 확인을 요구한다.
11. 신규 원금 HTML, P2/P3, 판결/DC/약정 이자, 별도 효력일이 있는 과거 정정은 범위 밖이다. 변경 없는 C1/C3/C7 산식과 일반 기존 임금 누락 처리는 공통 회귀 이상 재감사하지 않았다. 비용: 이들 경로는 별도 작업이 필요하다.
12. 실제 답변·원격 SQL 관문은 실행자가 확인하고, main 병합·배포·운영 데이터 갱신은 포함하지 않았다. 비용: 검토 가능한 PR 이후 통합·배포 결정이 남는다.
13. 별도 C2 요청은 명시 false와 독립 채권으로 구분하고, 귀속 불명 이자 제외는 보류한다. 정산 출력은 최대 32,768로 제한하고 잘린 결과를 거절한다. 비용: 모호하거나 매우 큰 명세는 확인·분할 입력이 필요하다.
