## Executive Summary

### 1.3 Value Delivered

| 관점 | 내용 |
|------|------|
| **Problem** | 프로덕션 BM25는 **Mecab을 한 번도 쓴 적이 없다** — `konlpy`가 `requirements.txt`에 없어 Vercel에서는 항상 정규식 폴백이 돈다. 그런데 코드 주석과 `CLAUDE.md`는 일관되게 "Mecab 우선"이라 적혀 있어 **아무도 그 폴백의 품질을 검증할 이유를 갖지 못했다.** 그 폴백은 어절 끝 한 글자가 조사 후보면 무조건 떼어내, 같은 단어를 뒤따르는 글자에 따라 3가지로 토큰화했다(`연차휴가 `→`연차휴`, `연차휴가를`→`연차휴가`, `연차휴가(`→`연차휴가`). 분열률 실측은 연차휴가 43%·연차유급휴가 46%·출산전후휴가 51%·회계년도 68%. 더 심한 것은 어간 최소 길이 가드가 없어 **2음절 단어 16종 중 13종이 색인에서 통째로 사라진 것**이다 — 거기에 `근로`와 `휴가`가 있었다. |
| **Solution** | 형태소 분석기 런타임 탑재는 실측으로 배제(kiwipiepy 41.6MB + 모델 109MB = 150.6MB > Vercel 250MB 여유). 정규식 토크나이저를 7단계 파이프라인으로 재작성했다 — 어절 분할 → 캐시 → 불용어 → **어미** → **조사** → 불용어 → 길이. `MIN_STEM=2`로 소멸을 막고, 조사 절단을 반복 + 매 회차 보호어 검사로 바꾸고, 사전 2종(보호어 40 / 불용어 59)을 코퍼스 실측에서 도출했다. 어절 캐시(로드 스코프)와 끝글자 버킷 인덱싱으로 성능을 흡수하고, `eval_tokenizer.py`(API 키 불요)를 신설해 CI에 편입했다. |
| **Function & UX Effect** | "연차휴가"·"출산전후휴가"·"근로" 같은 **가장 흔한 질문 어휘가 처음으로 코퍼스 전체와 매칭**된다. 검색 실효(top-20 핵심어 포함률) 74.5% → **90.0%**, 전체 파이프라인 해설서 도달률 61.1% → **80.0%**. 부수적으로 답변 근거 구성이 개선돼 **공공저작물(행정해석·판례·훈령)이 15 → 23건(+53%)**, 상담글이 73 → 67건이 됐다 — `legal-corpus-coverage`가 쿼터로 밀어붙이던 방향이 토크나이저 교정만으로 따라왔다. |
| **Core Value** | 하이브리드 검색의 절반이 **예외도 로그도 없이** 반쪽으로 동작하던 상태를 걷어냈다. 다만 이 사이클의 진짜 산출물은 수치가 아니라 **그것을 지키는 장치**다 — 결함이 오래 살아남은 원인이 측정 수단의 부재였으므로, `eval_tokenizer.py`(M1~M7, CI 게이팅)와 회귀 T-a~T-j를 함께 남겼다. 프로덕션(Linux) 비용은 메모리 370→367MB, 로드 7.0→6.9초로 **사실상 0**이다. |

## 교훈

### 1. 회귀 지표를 "고치기 전의 증상"으로 정의하면, 고친 뒤의 실패 모드를 못 잡는다

M1을 처음에 *분열률*로 정의했다. 독립 리뷰가 **그 지표가 자신이 막으려던 회귀에서 값이 거꾸로 내려간다**는 것을 찾아냈고, 20,000문서로 직접 재현했다:

| | M1 | 판정 |
|---|---:|:---:|
| 보호 ON (정상) | 3.75% | PASS |
| **보호 OFF (회귀 재현)** | **0.00%** | **PASS** ← 회귀인데 더 좋은 점수 |

분열률 탐지식은 원형과 절단형이 **둘 다 어휘에 있을 때만** 후보로 삼는다. 새 `_strip_josa`는 문맥 독립적으로 일관 절단하므로 보호가 없으면 원형이 통째로 사라져 후보에서 탈락한다. 구 구현의 실패 지문(분열)으로 지표를 만들었는데, **그 지문을 없앤 것이 바로 이 변경이었다.**

→ 지표는 **증상**이 아니라 **불변식**으로 세운다. 현재 M1은 "보호어 전종이 어휘에 존재한다"는 존재 단언이고 전체 제거(40종)·부분 제거(3종)를 모두 잡는다.

### 2. "측정 수단이 없어 결함이 살았다"로 시작해, 만든 측정 수단이 같은 사각을 가졌다

교훈 1이 그 구체적 형태다. 덧붙여 `TOPIC_TERMS`(M2 검사 대상)가 **항상 `PROTECTED_TERMS`의 부분집합**이라 이미 보호된 것만 검사하고 미보호 도메인어는 아무도 안 봤다 — 그 사각에서 `근로시간제도`→`근로시간제`(569회)·`전문가`→`전문`(398회, 판례 `全文`)이 **다른 실단어와 병합** 중이었다.

### 3. 경고를 써 놓는 것과 지키는 것은 다르다 — 구조로 막아야 한다

모듈 상단에 *"로컬에서 Mecab으로 잰 수치를 프로덕션 근거로 쓰지 말 것"* 이라 직접 적어 놓고, 바로 아래 테스트에서 `_tokenize_ko`를 불러 Mecab 경로를 검증할 수 있게 뒀다. CI에 konlpy가 없어 **우연히** 통과하고 있었다. 정규식 경로를 `_tokenize_regex`로 분리해 테스트가 그것을 지목하게 했다 — 주석 추가가 아니라 구조 변경이다.

### 4. 병렬 호출부 둘 중 하나만 고치는 패턴이 **세 번** 반복됐다

| 회차 | 고친 곳 | 빠뜨린 곳 |
|---|---|---|
| 1 | 테스트를 정규식 경로로 고정 | 평가 하니스는 `_tokenize_ko` 그대로 |
| 2 | `_ingest`에 null text 가드 | 평가 하니스 로더 2곳 그대로 |
| 3 | (2를 고치며) 한 곳 | 같은 파일의 나머지 한 곳 |

전부 CodeRabbit이 잡았다. **같은 결함이 두 곳에 있으면 grep으로 전수 확인할 것.** 이 저장소가 이미 아는 교훈이다(`extract_post_id` NFC 수정이 `pinecone_upload_contextual.py`에 3.5개월 전파되지 않은 사고).

### 5. 성능·메모리 판단에 macOS 수치를 쓰면 매번 과대평가한다

플랫폼 격차가 이 모듈에서 두 번째로 확인됐다. `CLAUDE.md`가 이미 "판단은 Linux 값으로"라고 지시하고 있었는데 **그 Linux 값이 변경 전 것이라 지시가 무효인 상태**였다 — 지시만 남기고 값을 갱신하지 않으면 지시가 죽는다.
