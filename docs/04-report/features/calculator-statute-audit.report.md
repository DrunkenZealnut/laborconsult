### 1.3 Value Delivered

| 관점 | 내용 |
|---|---|
| **Problem** | 계산기가 인용한 조문 134건은 현행 법령에 있었지만, 산식과 문구 3곳이 법령과 달랐다. 조기재취업수당은 '절반×50% = 최대'로 안내했고(법령은 미지급일수의 1/2, 절반 남긴 경우가 하한), 일용직 기준기간 '1년'은 법에 없으며, 산재 휴업급여는 3일 이내 불지급 단서가 빠져 있었다. 재결례에서 반복 다투어지는 산재 법정 규칙 5개도 계산기에 없었다. |
| **Solution** | 법 영역별 PR 2개로 나눴다. 각 근거 문구에는 원문 앵커(`CALC_BASIS_ANCHORS`)와 공식 원문 등록을 함께 넣어 테스트와 현행성 점검이 순회하게 했다. 고시 금액은 효력 기간 표로 두어 시행일을 넘으면 조용히 계속 적용되지 않게 했다. |
| **Function UX Effect** | 조기재취업수당 카드가 '최대'가 아니라 '절반 남긴 시점 기준 하한'을 보이고 요건·제외 사유를 함께 안내한다. 3일 이내 요양은 산재 휴업급여 0원과 사업주 보상(근로기준법 제78·79조)을 안내한다. 61세 이상 감액, 일용근로자 통상근로계수, 최고·최저 보상기준이 법정 기준대로 계산된다. CLI 116사례의 금액은 바뀌지 않았다(회귀 없음). |
| **Core Value** | 새로 적재한 공공 원문을 검색 코퍼스로만 쓰지 않고 계산 산식 검증에 썼다. 확정 오류 3건과 누락 규칙 5건을 금액 회귀 없이 고쳤다. 자료팩 자체의 공백(산식 이미지로 보류된 조문 7건, 스냅숏 이후 신설 19건)도 드러나 후속 과제로 남겼다. |

## 5. 교훈

### 5.1 What Went Well
- 조문 존재 대조를 자료팩 색인과 현행판으로 2단 확인해, 확정 오류와 데이터 공백을 구분할 수 있었다.
- 앵커 구절과 등록을 같은 PR에 묶어, 원문 대조 테스트와 현행성 점검이 새 근거를 자동으로 순회하게 했다.
- 재대조(gap-detector 2차)가 설계 문서 자체의 불일치(N1~N3)를 찾았다.
- 금액 회귀를 CLI 116사례로 전후 비교해, 바뀐 입력을 목록으로 특정했다.

### 5.2 Areas for Improvement
- 자료팩 준비 스크립트가 산식 이미지가 있는 조문을 통째로 보류해, 실제로 법에 있는 조문이 "없음"으로 보였다(오판 1건).
- 법제처 XML은 `<조문단위 속성>`과 CDATA라서 `<조문단위>`로 찾으면 0건이 된다.
- 최저 보상기준이 최저임금액과 같은 해(2026)에는 별표 1 제3호·제1호 단서 경로가 닿지 않아, 회귀는 표 치환으로만 고정할 수 있었다.
- 설계 문서의 개수 표기(앵커 10·11·14개, 11건·13건)가 본문과 어긋났다.
- 산재 계산기는 채팅 입력에 `age`가 없어 61세 감액이 채팅 경로에서 재현되지 않는다.

### 5.3 To Apply Next Time
- 자료팩에 없는 조문은 "법에 없음"이 아니라 "보류 또는 신설"로 먼저 분류한다(현행판 확인이 기본).
- 계산 카드의 산식 문구는 LLM 근거이므로, 등식에는 감액 전 값과 적용 금액을 함께 적는다(N1).
- 두 PR이 같은 새 테스트 파일을 만들면 스택으로 쌓고 재타깃 순서를 미리 정한다.
- 별표 앵커는 fixture·U3·U5·등록 검사 네 곳이 함께 움직이므로, 하나를 바꾸면 나머지 셋을 같이 확인한다.
- 회선 IP가 법제처 등록 밖이면 현행성 점검이 막힌다. 고정 IP 호스트 예열을 후속으로 둔다.
