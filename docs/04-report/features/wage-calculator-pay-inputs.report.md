# 지급 주기·평균임금·휴가 입력 연결 결과

> 2026-10-24 · C4b / P0-E · 완료
> 계산 코드 `62667da` · [PR #130](https://github.com/DrunkenZealnut/laborconsult/pull/130) · 선행 PR #129 위에 분리

## 변경 내용

- 연·분기·반기 수당을 지급 주기에 맞게 월 환산한다. 연간 총액 표시가 있으면 지급 회차와 구분한다. 주기가 불명확한 금액은 월 수당으로 단정하지 않는다.
- 실제 3개월 임금·달력일수·법정 제외 기간과 해당 임금을 분석부터 계산기까지 보존한다. 평균임금 사유 발생일은 퇴직일과 별도로 입력할 수 있다.
- 고정수당과 연 상여의 출처 ID, 실제 3개월 임금·월 총액에 이미 포함된 상여 금액으로 중복을 조정한다. 같은 금액이라는 이유만으로 같은 항목으로 판단하지 않는다.
- 평균임금 보류를 퇴직금·DB 퇴직연금 등 의존 계산에도 전달한다. 독립적으로 계산 가능한 체불이자 등은 유지한다.
- 난임·배우자 유산사산·배우자 출산휴가를 요청한 하위 유형으로 연결하고 사용 구간·실사용일·기사용일·지원 자격을 검증한다. 본인 출산전후휴가의 부분 사용을 90일로 대체하지 않는다.
- 연 상여의 월 환산액은 실제 매월 지급액과 구분해 표시한다. 지급 주기·상여 이름을 산식에 명시하고, 입력에 없는 식대 지급을 사실로 서술하던 참고 안내를 조건 확인 문구로 수정했다.

입력 계약과 공식 근거는 [설계 문서](../../02-design/features/wage-calculator-pay-inputs.design.md), 106행·43라벨 및 기타 62행 검토는 [라벨 감사](../../02-design/features/wage-calculator-input-label-audit.md)에 기록했다.

CLI #11·21·23은 분기 지급 회차액을 매월 수당으로 다루던 과대 산입을 수정했다. #11은 월 통상임금 420만→320만 원, 월 연장수당 105만→80만 원이다. #21은 통상임금 490만→290만 원, #23은 220만→180만 원이다. #28은 출산휴가 급여에 붙던 평소 월급 총액을 제거했다. #22·57·59는 근거·주기·비과세 안내 문구 변경이다.

초기 전체 검사에서 새 보조 모듈의 통상임금 의존 분류와 출산휴가의 필수 입력을 갖추지 않은 기존 fixture가 실패했다. 각각 실제 소유 계산기에 연결해 분류하고 자격·사용 구간을 명시한 fixture로 보완했다. 실패 검사를 삭제하지 않았다. 중간 실행의 토크나이저 시간 배수 초과는 최종 로컬·원격 검사에서 통과했으며 토크나이저 구현은 바꾸지 않았다.

## 실제 상담 비교

동일한 질문 6개를 변경 전후 각각 2회 생성했다. 변경 전 `b3507ea`, 최종 변경 후 `62667da`를 사용한다.

| ww26-22 실제 임금·사용자 귀책 휴업 | 1,000만 원에서 100만 원 제외, 92일에서 10일 제외. 900만/82일=109,756원, 통상임금 하한 적용 115,068원 |

중간 평가에서는 금액이 맞아도 답변이 연 상여 월 환산액을 별도 수당으로 오해하거나, 현재 조문으로 시행 예정일 이후 계산을 뒤집는 문제가 발견됐다. 항목별 산식과 적용일 근거를 보강했다. 평균임금 산정일 누락도 명시 필드로 수정했다. `b998c40`의 12개 핵심 계산·답변은 맞았으나 비과세 참고 안내에서 미제공 식대 지급을 주장해 최종 문구 수정 후 재평가했다. 최종 답변 12건 전문과 계산 카드 12건을 모두 읽었으며, 요청 계산의 부정확·미연결 사례는 변경 전 12/12에서 변경 후 0/12가 됐다. 오류 0건·제공자 폴백 0건, 네 실행 모두 깨끗한 코드 상태였고 실제 모델은 gpt-6-sol이었다.

원자료는 저장소 밖 평가 원자료(로컬 보관, 실행 묶음 c4b)의 `before-{1,2}.json`, `after-verified-{1,2}.json` 및 메타데이터에 보관한다. 모두 같은 모델 설정 revision 12, OpenAI 기본 제공자, 로컬 운영 법제처 실패 재현 모드다. 대화 저장·운영 L2 쓰기·모델 설정·검색 코퍼스는 변경하지 않는다. 지정 사례의 검증이며 사용자 만족도나 전체 상담 정확도 향상률 측정이 아니다.

## 독립 리뷰와 추가 발견

독립 리뷰의 Important 4건을 모두 실패 테스트로 재현하고 수정했다.

1. 지급 주기 미확인 수당이 대안 계산에서 예외를 내 독립 체불이자까지 소실 → 예외 경계를 수정.
2. DB 연금 단독 호출에서 평균임금 보류 우회, 보류 퇴직금을 미발생 0원으로 취급 → 의존 계산 결과 전파.
3. 휴가 급여만 요청해도 임금 구성 보정 뒤 월급 총액 재등장 → 최종 카드의 월급 표시 억제.
4. 본인 출산휴가의 실제 사용일·피보험기간 무시 → 명시 입력 검증, 부분·분할·미확인 계산 보류.

실제 답변에서 추가 발견한 산정일·상여 표시·식대 사실 단정도 실패 테스트를 먼저 추가해 수정했다. 전체 회귀검사로 검증했으며 동일 코드를 반복 리뷰하는 대신 재현 검사와 실제 답변으로 확인했다.

## 한계와 후속 연결

- 제외 기간과 연 상여가 함께 있는 복잡한 귀속, 1년 미만 상여 배분, 제외 기간 전체에 해당하는 특례는 추가 자료를 요구한다. 임의 추정으로 확정하지 않는다.
- 본인 출산전후휴가의 명시 호출은 확인된 전체 90/100/120일 구간을 지원한다. 부분·분할·연도 경계는 보류한다. 기존 직접 비교 호출의 호환 경로는 유지했다.
- 자동 유형 감지가 새 평균임금·가족휴가 필드만으로 독립 유형을 추론하지 않는 Minor는 후속으로 남긴다. 명시 유형을 전달하는 상담 경로는 연결했다.
- 실제 월별 지급 의무와 연 상여 지급기일별 채권은 C6·C5에서 계약 조건으로 계산한다. 통상임금 월 환산액을 자동 채권으로 만들지 않는다.
