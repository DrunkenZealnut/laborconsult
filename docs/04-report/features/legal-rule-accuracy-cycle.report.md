## 2. PR #77 — 법률 기준 관리 화면 + 4대보험 드리프트

### 2.1 발단

사용자 질문: *"최신정보주입의 ui가 너무 복잡합니다. 이 ui로 구성되어 있는 이유를 제시해주세요"*. 관리자 "법률 기준 관리" 화면의 설계 의도를 설명하는 과정에서 4가지 UX 결함을 확인하고 개선에 착수했다. 그런데 화면을 고치려면 실제 계산값과 대조해야 했고, 그 대조에서 **화면 문제가 아니라 계산 자체의 오류**가 먼저 드러났다.

### 2.2 2027년 최저임금 누락 (`1e32ae2`)

고시된 지 이미 몇 주 지난 2027년 최저임금(10,700원, 2026-08-05 고시)이 내장표에 없어, 상담이 "아직 고시되지 않았다"고 **사실과 다르게** 답하고 있었다. 시스템이 알 수 있는 것은 "등록되지 않음"뿐이고 "미고시"는 별개의 사실인데, 코드가 전자를 후자로 단정하고 있었다. 표 누락과 단정 문구, 두 원인을 함께 고쳤다. 골든 테스트가 8월 5일 이후 다음 연도 누락을 자동으로 실패시키도록 게이트를 추가했다.

### 2.3 4대보험 기준값 드리프트 (`2b21218`)

| 항목 | 전 | 후 | 근거 |
|---|---:|---:|------|
| 국민연금 기준소득 상한 | 6,370,000 | **6,590,000** | 보건복지부 고시 (2026.7~2027.6) |
| 국민연금 기준소득 하한 | 400,000 | **410,000** | 〃 |
| 건강보험료 월 상한(근로자) | 4,240,710 | **4,591,740** | 고시 9,183,480 ÷ 2 |
| 건강보험료 월 하한(근로자) | 9,890 | **10,080** | 고시 20,160 ÷ 2 |

근본 원인은 "낡은 값"이 아니라 **구조적 한계**였다 — 국민연금 기준소득월액 적용기간은 7월~다음 해 6월인데(국민연금법 시행령 제5조④) `INSURANCE_RATES`는 연 단위라 1월 1일 값만 표현할 수 있었다. `PENSION_INCOME_PERIODS` 시행일 구간표를 단일 출처로 두고 조회를 기준일 기반으로 재구성했다.

**실측 영향**: 월 800만원 소득자의 국민연금이 2026년 7월 이후 월 10,450원 적게 계산되고 있었다(302,575원 → 313,025원). 같은 원인으로 상담 사실 블록도 연 단위 표를 직접 읽고 있어, 고치지 않았다면 한 답변 안에서 사실 블록과 계산 결과가 갈릴 뻔했다.

### 2.4 법률 기준 관리 화면 개선 (`0e929cb`)

"쓰기 어렵다"의 구조적 원인 4가지와 대응:

| # | 원인 | 대응 |
|---|------|------|
| 1 | 승인 게이트가 출처(해시·호스트·구간·kind)만 검증, **값의 타당성은 검증하지 않음** — 건강보험 전체요율(근로자분의 2배)·국민연금 최종연도값(2033년)이 정식 인용까지 붙어 승인 통과 | 입력란 옆에 현재 적용값 표시 + 통상 개정폭(30%) 이탈 경고 |
| 2 | Pinecone 벡터 ID를 화면 어디에도 없는 값으로 손 입력해야 함 | 공식 원문 17건 목록 제공(`GET /documents`) |
| 3 | 웹에서 복사한 정확한 인용이 반드시 거절됨 — 저장 원문이 PDF 추출물이라 낱말 사이 공백 없음 | 공백 무시 대조 + 원문 표기로 자동 교정(`alignQuote`) |
| 4 | 자동 검색 후보가 `kind="legal_review"`로 고정 생성돼 그대로는 영원히 승인 불가인데 화면에 안내 없음 | 배너 + `to-parameter` 전환 버튼 |

### 2.5 검토 이력 — `/code-review`(code-analyzer) 11건

전건 재현 후 반영. 실제 결함으로 확인된 주요 항목:

1건(버튼 mousedown이 선택 지움)은 Chrome 실조작으로 반증해 반영하지 않았다.

## 3. PR #78 — 출산전후휴가 상한 정정 + 배우자 출산휴가 20일

### 3.1 발단

PR #77 검토 중 "출산휴가 상한이 고시와 구조가 다르다"를 따라가다 **상한표 전체가 고시값이 아니라는 것**이 드러났다.

### 3.2 상한표에 법적 근거 없음

`MATERNITY_LEAVE_UPPER`가 `최저임금 × 209h`로 만들어져 있었다. 그러나 고용보험법 시행령 제101조제1호는 상한액을 **고용노동부 고시**에 위임하며, 최저임금은 고시가 고려하는 여러 요소(평균 통상임금·물가상승률·최저임금·기타) 중 하나일 뿐이다.

| 연도 | 기존(최저임금×209h) | 고시 월 상한 | 차이 |
|---|---:|---:|---:|
| 2023 | 2,009,080 | **2,100,000** | −90,920 |
| 2024 | 2,060,740 | **2,100,000** | −39,260 |
| 2025 | 2,096,270 | **2,100,000** | −3,730 |
| 2026 | 2,156,880 | **2,200,000** | −43,120 |

### 3.3 기간 총액 산식도 틀렸음

고시 원문(제2025-124호) 대조로 `총액 = 월 상한 ÷ 30 × 일수`가 정확히 성립함을 확인:

```
90일  2,200,000 × 3    = 6,600,000  ✓ 고시 660만원
120일 2,200,000 × 4    = 8,800,000  ✓ 고시 880만원 (다태아)
100일 2,200,000 × 10/3 = 7,333,333  ✓ 고시 7,333,330 (미숙아)
```

기존 코드는 `× 12 ÷ 365`(연 365일 환산)를 써서 90일 총액이 6,382,001원 — 고시 대비 **217,999원 부족**이었다. 이 검증 덕분에 기간별 총액 표를 새로 만들 필요 없이 월 상한 + `÷30` 환산만으로 고시와 정확히 일치시켰다.

### 3.4 배우자 출산휴가 옛 법 기준

남녀고용평등법 제18조의2 개정(2025-02-23 시행)으로 10일→**20일**, 고용보험 지원 5일분→**전 기간**으로 확대됐는데 코드는 10일·5일분이었다. 시행일 구간표(`SPOUSE_LEAVE_PERIODS`)로 날짜 기준 분기 처리.

### 3.5 사용자 영향 (2026, 우선지원대상기업)

| 월 통상임금 | 개선 전 90일 | 개선 후 | 차이 |
|---|---:|---:|---:|
| 200만원 | 5,917,808 | 6,470,640 | **+552,832** |
| 300만원 이상 | 6,382,001 | 6,600,000 | **+217,999** |
| 다태아 120일 | 8,509,335 | 8,800,000 | **+290,665** |
| 배우자 출산휴가 | 10일·무상한 | 20일·상한 적용 | 일수 2배 |

### 3.6 CodeRabbit 반영 (`53ed41f`)

배우자 출산휴가의 유급액(사업주 의무)과 고용보험 급여(상한 적용)를 분리 — 상한을 유급액에 그대로 걸면 대규모기업 근로자의 법정 유급액이 줄어든 것처럼 보이는 결함을 이 시점에 확립했다(이 원칙이 §6.4의 PR #81 결함과 직결된다).

### 3.7 범위 밖으로 명시적으로 남긴 것

미숙아·난임치료휴가(별건 필요), 흐름도 산식 불일치(월급÷30 vs 시급×8h, §4에서 해소), 2023~2025 배우자 상한 고시(HWP 미확보).

## 4. PR #79 — 흐름도 통상임금 기준 통일

### 4.1 발단

PR #78이 범위 밖으로 남긴 "흐름도와 계산기의 통상임금 기준 불일치".

### 4.2 문제 — 흐름도가 자기 자신과도 어긋남

흐름도는 1일 통상임금을 `월급 ÷ 30`(평균임금식 일할계산)으로 계산했다. 통상임금은 `통상시급 × 1일 소정근로시간`(근로기준법 시행령 제6조)이어야 한다. 더 심각한 것은 **같은 화면의 산식 라벨·예시는 이미 올바른 식**이었다는 점이다 — 산식 라벨(`통상시급×8h×20`)과 예시(`15,000×8=120,000`)는 맞고, 실제 계산(`ww/30`)만 달랐다.

### 4.3 함정 — 209h가 아니라 208.6h

처음 209h로 맞췄더니 0.19% 차이가 남았다. 백엔드 월 소정근로시간은 `(40+8)×365/7/12 = 208.6h`(`ordinary_wage._get_base_hours`)이고, 209h는 같은 화면의 하한 표시(`최저시급×209h`)가 쓰는 **별개의** 최저임금 월환산용 수치였다. 두 값이 한 화면에 공존하므로 혼동 방지 주석을 남겼다.

### 4.4 검증 — 실브라우저, 슬라이더 전 구간 0원 차이

| 월 통상임금 | 유급액 차이 | 고용보험 지원 차이 |
|---|:--:|:--:|
| 100만·150만·250만·400만·500만원 | **0원** | **0원** |

```
개선 전: 1일 83,333원 (월 250만원)
개선 후: 1일 95,694원  ← 계산기와 동일, 약 15% 상향
```

CodeRabbit(`5cb58c2`)이 반올림 순서(통상시급 소수 2자리 반올림 후 곱셈)까지 맞춰 1원 단위 어긋남도 제거했다.

CodeRabbit이 §3.6에서 이미 확립했던 원칙(유급액≠보험급여)이 **이 새 경로에 적용되지 않은 것**을 잡아냈다. 고시 1일 상한을 유급액에 그대로 걸어, 대규모기업 근로자의 법정 유급액이 줄어든 것처럼 보이는 결함이 재발했다:

| 일 통상임금 120,000원 · 유산·사산 3일 | 수정 전 | 수정 후 |
|---|---:|---:|
| 유급액(사업주 의무) | 252,630 ❌ | **360,000** |
| 고용보험 급여(우선지원) | — | 252,630 |
| 고용보험 급여(대규모기업) | — | 0 |

같은 리뷰에서 발령번호 기록 경로의 **판본 대조 누락**도 지적됐다 — `board_find()`는 같은 제목의 최신 글을 돌려주므로, 저장본이 옛 판본이면 새 번호가 옛 본문에 찍혀 `check_updates()`가 "최신"으로 오판할 수 있었다(확인 불가보다 나쁜 상태). 게시글 발령일이 저장본 시행일보다 나중이면 기록하지 않는 게이트를 추가했다. `--dry-run`·`--only`가 새 기록 함수에 전달되지 않던 것도 함께 고쳤다.

2025년 난임치료휴가 상한(고시 제2025-14호)은 게시글 본문에 금액이 없고 첨부가 hwp(OLE 바이너리) 단건뿐이라 — 실측으로 직접 확인 — 등록하지 못했다. 배우자 출산휴가 5일분과 같은 사정으로, 추정값 대신 경고 문구로 대체했다(이 경고 부재 자체가 실제 결함이었다).

## 12. 후속 처리 — 항목 6 해소 (2026-09-24, 보고서 작성 직후)

사용자 요청 *"후속 과제 6번 공용 헬퍼로 추출해줘"*에 따라 즉시 처리했다. 아직 커밋되지 않음(프로젝트 규칙: 커밋은 요청 시에만).

### 12.1 구현

`wage_calculator/calculators/maternity_leave.py`에 함수 2개 신설:

- **`_employer_and_insurance(daily_wage, paid_days, insurance_days, is_priority, upper_total)`** — 핵심 수치 분리. 유급액(`daily_wage × paid_days`)은 상한을 절대 보지 않고, 고용보험 급여만 `is_priority`로 게이팅되고 `upper_total`로 상한이 걸린다. `paid_days`≠`insurance_days`(배우자 출산휴가 2025년 개정 전 10일/5일)도 인자로 분리해 수용한다.
- **`_benefit_warning(label, days, pay, benefit, is_priority)`** — 세 휴가(배우자 출산·난임치료·배우자 유산사산)가 공유하던 "차액은 사업주가 부담" 경고 문구를 통합.

세 호출부(배우자 출산휴가, `_daily_leave` 클로저 내부 2건)를 전부 이 함수로 교체했다. 1일 상한(난임·유산사산)과 기간 총액 상한(배우자 출산)은 `upper_total = daily_upper × paid_days`로 호출 전에 환산해 같은 인터페이스로 넘긴다 — `min(a,b)×n == min(a×n,b×n)`(n>0)이 성립해 두 상한 방식이 수학적으로 동치이기 때문이다.

### 12.2 검증

전체 회귀 재실행, 전건 통과(값 변화 없음 — 순수 리팩터링):

```
golden · wiring · offline-units · abuse-guard · precedent-ingest · llm-fallback · legal-rules 56 · CLI 116
```

배우자 출산휴가의 유급/보험 일수가 갈리는 옛 규정 경로(2019-10-01, 10일/5일)도 회귀 그대로 통과 — 공용 함수가 이 비대칭 케이스를 인자로 정확히 수용함을 확인.

### 12.3 부수 변경 — 경고 문구 통일

배우자 출산휴가의 경고 문구가 난임·유산사산휴가와 같은 형태("유급 N일분 P원 중 B원이 고용보험 지원 대상...")로 통일됐다(기존: "N일분(B원)이... 유급액 P원과의 차액..."). 두 표현 모두 같은 사실을 말하며, 어떤 테스트·프론트엔드도 이 문자열의 정확한 형태에 의존하지 않음을 확인 후 진행했다(전체 저장소 grep으로 검증).

### 12.4 규모
